# Retrieval Near-Duplicate Suppression

> Date: 2026-11-01  
> Status: implemented, opt-in  
> Scope: HybridSearch candidate list before rerank / final ranking

## What Was Implemented

`services/search/dedup.py`:

```text
normalize_text()
shingles()          word 3-gram shingles
jaccard()
suppress_near_duplicates()
threshold_from_env()
```

Rules:

```text
exact duplicate sentence_id / para_id      removed
exact normalized text                      removed
near-duplicate (same paper only)           removed at 0.90 default
highest-scoring copy                       kept
different papers                           never near-collapsed
```

`HybridSearch._apply_near_dup_suppression()` applies this after RRF and before
rerank. It is **opt-in**:

```text
SCIPAL_NEAR_DUP_THRESHOLD unset  -> behavior unchanged
SCIPAL_NEAR_DUP_THRESHOLD=0.90   -> enable same-paper suppression
SCIPAL_NEAR_DUP_THRESHOLD=0      -> exact dedupe only
```

## Why Opt-In

The audit showed that aggressive diversity can destroy evidence:

```text
max_per_paper=2
unique_papers@10:    3.85 -> 7.50
gold_sentence_top10: 9/20 -> 0/20
```

Near-duplicate suppression is safer than a hard cap, but it still needs a
20-query quality check before being enabled in production.
