# 阶段四-A：消除「手动起 Flask」这个人工前置

> 决策时间：2026-10-24 ｜ 决策人：用户采纳 WorkBuddy 建议 ｜ 落盘人：WorkBuddy
> 本文是**架构决策**，CodeBuddy 看不到我们的对话，开工前必读。

---

## 1. 要解决的问题

MCP 工具全部依赖 SciPal 的 Flask API（`127.0.0.1:5000`）先跑起来。它一停，
6 个工具全部返回「SciPal API 未启动」。

**2026-10-24 当天这件事已经咬了我们两次**，每次都要停下来重新拉服务才能继续验证。
在它解决之前，后续任何工具扩展、任何验收都会被同一道坎反复打断。

---

## 2. 实测得到的事实（写方案前先量，不拍脑袋）

| 项 | 实测值 |
|---|---|
| 冷启动耗时 | 约 **30–45 秒**（模型预热：加载 3 组权重 + 摘要库 + LLM 客户端） |
| 本地混合检索 | **7–12 秒**（`use_online=false`） |
| MCP 工具超时上限 | **60 秒**（`toolCallTimeoutMs`） |
| 现有启动方式 | 根目录 `start.bat`；仓库内**无 `logs/` 目录** |

**由「冷启动 30–45 秒」直接推出一条硬约束：**

> ❌ **不允许在 MCP 工具调用里同步等待服务启动完成。**
> 30–45 秒 + 首次检索 7–12 秒，随时可能顶到 60 秒上限。
> 服务启动必须是**工具调用之外**发生的事。

这条约束否掉了「MCP server 检测未启动就自己拉起并等待」这个看起来最省事的方案。

---

## 3. 方案（三层，成本递增，收益也递增）

### L1 · 开机自启（必做）

Windows 计划任务，触发条件「用户登录」，延迟 30 秒执行。
目标：`scripts/sciPal_watchdog.py`。

选计划任务而不是启动文件夹快捷方式的原因：计划任务可以设延迟（避开开机时的
资源争抢）、可以设为后台静默、卸载也干净。

### L2 · 崩溃自愈（必做，成本极低）

`scripts/sciPal_watchdog.py` 是个常驻循环：

```
每 10 秒:
    if 端口 5000 的 /api/health 不通:
        以 detached 方式拉起 api_server.py，stdout/stderr 落 logs/sciPal_api.log
    文件锁保证只有一个 watchdog 实例，避免重复拉起抢端口
```

CPU 开销可忽略（10 秒一次 HTTP 探测）。
它同时解决「开机自启」和「运行中崩掉」两件事，**一套代码覆盖两个场景**。

### L3 · 工具侧提示可操作（必做，一行文案）

MCP server 的服务未启动错误，从

```
SciPal API 未启动：连接 http://127.0.0.1:5000 失败，请先运行 python api_server.py
```

改为指向守护脚本，例如

```
SciPal API 未启动（127.0.0.1:5000）。
若已安装自启：稍等 30–45 秒后重试（服务正在预热）。
否则执行：python scripts/sciPal_watchdog.py --once
```

**为什么不做「MCP server 自动拉起 Flask」**：见第 2 节的超时约束 + 并发拉起抢端口的风险。
自愈交给 L2 的独立进程，职责更清楚。

---

## 4. 边界与红线

- **不改 `api_server.py` 的任何业务逻辑** —— 本次零业务代码改动。
- 新增文件只落在 `scripts/` 与 `logs/`，不碰 `services/`、`config/`、`data/`、`mcp_server/` 外的既有文件。
- **安装计划任务必须由用户显式执行**（改动系统状态）。本轮不自动安装，只交付安装脚本。
- watchdog **不得**在检测到服务存活时反复重启它；只在「确实不通」时才拉起。

---

## 5. 验收标准

1. `python scripts/sciPal_watchdog.py --once` 在 Flask 未运行时能拉起它，并**打印实际耗时**
2. 服务活着时再跑 `--once`，**不得重复拉起**（幂等）
3. 手工 kill 掉 Flask 后，watchdog 在 **≤15 秒**内重新拉起
4. `mcp_server/selftest.py` 仍 PASS
5. `python self_check.py` 通过数不低于 **110**（基线 110/1/121）
6. `git diff --stat` 只显示 `scripts/` 下新文件 + `mcp_server/scipal_server.py`（仅文案改动）
