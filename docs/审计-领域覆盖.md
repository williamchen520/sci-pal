# Domain Coverage Audit

> Date: 2026-11-01  
> Data: `data/research.db`  
> Status: **partial audit — domain labels are missing**  
> Script: `scripts/domain_coverage_audit.py`

## 1. Headline

```text
domain_labels: missing
```

The current SQLite database has no reliable L1/L2 domain labels for papers.
Only one domain pack exists (`biomed-oncoimmuno`), and the corpus itself spans
many journals outside that pack.

Therefore this audit **does not claim** a domain-level coverage ceiling.
It reports what can be measured now:

```text
corpus long tail (by journal)
query lexical support (weak proxy)
result hubness (from the HybridSearch audit)
```

## 2. Corpus distribution

```text
papers                    3,310
distinct journals           940
singleton journals          485
top journal share         8.1%
journal Gini              0.588
```

Interpretation:

```text
the corpus is already long-tailed by journal
about half of the journals appear only once
the largest single journal is still only ~8%
```

This is consistent with a broad, uneven corpus, but **journal is not domain**.
Journal statistics cannot substitute for L1/L2 labels.

## 3. Query support proxy

For each query, the script counts papers whose title/abstract/keywords contain
any query term:

```text
mean available_support     1,930 / 3,310
mean title_support           496 / 3,310
mean coverage_ceiling@10   1.00
```

This is an **upper bound**, not a relevance count. Common biomedical terms make
the proxy saturate. It cannot answer:

```text
how many papers in this subdomain are actually relevant?
```

That number requires labelled qrels or a domain taxonomy.

## 4. Result hubness

From the HybridSearch 20-query audit:

```text
unique papers across top10         59
hub_paper_rate                     0.237
mean distinct papers@10            4.45
mean new_paper_rate                0.576
```

Meaning:

```text
23.7% of papers that appear in any top10
appear in at least two queries
```

This is direct evidence of hubness:

```text
the same papers keep coming back
```

It does not prove domain-level concentration, because the 20 queries are not
domain-stratified.

## 5. What the audit can and cannot conclude

### Can conclude

```text
- the corpus is long-tailed by journal
- HybridSearch top10 has only 4.45 distinct papers on average
- 23.7% of returned papers recur across queries
- near-dup does not reduce HybridSearch hubness
```

### Cannot conclude

```text
- which domain has low coverage
- whether a sparse subdomain has 3 or 30 relevant papers
- whether a domain boost would help or hurt
- whether hubness is caused by corpus imbalance or ranking
```

## 6. Required next step: labels

Create a label file:

```text
eval/domain_labels.csv

paper_id,domain_l1,domain_l2
paper_...,oncology,hepatocellular carcinoma
paper_...,neuroscience,alzheimer
...
```

Then rerun:

```bash
python scripts/domain_coverage_audit.py \
  --labels eval/domain_labels.csv \
  --out eval/results/domain_coverage_audit.json
```

The script already supports:

```text
papers_per_domain
domain_counts
query domain (if gold paper labelled)
```

## 7. Decision

```text
Do not implement domain routing yet.
Do not claim coverage ceiling is the cause.
First label the corpus, then stratify the 20 queries by domain density.
```

Current evidence supports one conclusion only:

```text
HybridSearch has measurable hubness;
the corpus is long-tailed;
domain-level attribution is blocked by missing labels.
```
