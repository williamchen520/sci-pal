# 工作计划：句子种子 + 章节类型路由

> 目标：在不牺牲拒答的前提下，提升 strict sentence Recall@10。  
> 前置结论：ContextExpander v2 与旧版持平，说明“上下文扩展”不是 strict Recall 的杠杆；下一步改**候选生成**与**章节/句子选择**。

## 1. 背景

当前链路：

```
paragraph hybrid → rerank → anchor → context
```

问题：

- 最小单元是句子，但召回从段落开始；
- 章节类型（Intro/Methods/Results/Discussion）没有参与排序；
- References/Acknowledgements 等噪声章节未系统排除；
- 句子选择仍以词重合为主。

已有数据：

- `sentences_fts`（862k 句）；
- `sections.path/depth`、`section_level1/2/3`；
- `sentence_links.intent`；
- 100 题评测与 contract 指标。

## 2. 假设

1. gold 句子常常能在 `sentences_fts` 里被召回，但被段落级候选截断；
2. 问题类型与章节类型有稳定对应关系（结果类问题 → Results，方法类 → Methods）；
3. 排除 References/Acknowledgements 能减少无效候选与拒答噪声。

## 3. 工作流 A：句子种子融合

### 3.1 召回

```
sentences_fts top-N (N=50)
→ 按 para_id 聚合
→ 得到 sentence_seed_para_scores
```

### 3.2 融合

对每个段落：

```
score = paragraph_rrf_score
      + α * sentence_seed_score
      + β * section_type_prior
```

- `sentence_seed_score`：该段落内命中句子的最高 FTS 分；
- 只用于“候选排序”，不直接把句子塞进 top10；
- 仍保留“每个 anchor 1 句”的规则。

### 3.3 参数

```
SCIPAL_SENTENCE_SEEDS=1
SCIPAL_SENTENCE_SEED_ALPHA=0.3
SCIPAL_SENTENCE_SEED_TOPK=50
```

### 3.4 验收

- strict Recall +≥3pp；
- paragraph Recall 不下降；
- refusal 下降 ≤2pp；
- 延迟增加 ≤20%。

## 4. 工作流 B：章节类型路由

### 4.1 分类

用 `section_level1/path` 规则分类：

```
Introduction
Methods
Results
Discussion
Conclusion
References
Other
```

规则示例：

- Methods：method, material, patient, inclusion, statistical, protocol；
- Results：result, outcome, efficacy, survival, response；
- Discussion：discussion, limitation, implication；
- References：reference, bibliography, acknowledgement。

### 4.2 查询意图

规则分类：

```
factual/result  → Results, Methods
method          → Methods
limitation      → Discussion
background      → Introduction
```

### 4.3 先验

- 匹配类型：`+γ`；
- References/Acknowledgements：`-∞`（直接排除）；
- 不匹配但不禁止：不惩罚。

参数：

```
SCIPAL_SECTION_ROUTING=1
SCIPAL_SECTION_PRIOR=0.15
```

## 7. 风险

- `sentences_fts` 命中含参考文献/页眉；
- 章节分类规则覆盖不足；
- α/γ 过拟合 100 题；
- 句子种子把噪声段落带进候选；
- 延迟上升。

回滚：所有功能 flag 默认关闭，失败不影响默认链路。

## 8.1 第一轮结果

100 题：

| 配置 | sentence strict@10 | paragraph@10 | coverage | refusal |
|---|---|---|---|---|
| baseline | 0.5885 | 0.6823 | 0.7604 | 0.75 |
| +sentence seeds | **0.6094** | **0.6979** | 0.7604 | **0.75** |
| +seeds +routing（30 题） | 0.5192 | 0.7308 | 0.7692 | 0.75 |

30 题：

| 配置 | sentence strict@10 | paragraph@10 | refusal |
|---|---|---|---|
| baseline | 0.5192 | 0.7692 | 0.75 |
| +sentence seeds | **0.5962** | **0.8462** | 0.75 |

延迟（12 复杂问题）：

| 配置 | median |
|---|---|
| baseline | 1064 ms |
| +sentence seeds top10 | 3866 ms |

结论：

- 句子种子把 100 题 strict Recall 从 0.5885 提到 **0.6094（+3.6%）**；
- paragraph 也从 0.6823 提到 0.6979；
- refusal 保持 0.75；
- 但延迟约 **3.6×**，暂不默认启用；
- section routing 在 30 题上反而下降，保持关闭。

当前开关：

```powershell
$env:SCIPAL_SENTENCE_SEEDS = "1"
$env:SCIPAL_SENTENCE_SEED_TOPK = "10"   # 默认
$env:SCIPAL_SECTION_ROUTING = "0"       # 默认关闭
```

## 8.2 延迟优化与 adaptive 试验

- sentence seed 改为批量查询段落，避免逐条 DB；
- `SCIPAL_SENTENCE_SEED_TOPK` 默认 5，`MAX_ADD` 默认 5；
- 尝试“简单问题关闭、复杂问题开启”（adaptive）。

100 题结果：

| 配置 | sentence strict@10 | paragraph@10 | refusal |
|---|---|---|---|
| baseline | 0.5885 | 0.6823 | 0.75 |
| seeds（全部问题） | **0.6094** | 0.6979 | 0.75 |
| seeds adaptive（仅复杂） | 0.5885 | 0.6823 | 0.75 |

结论：

- 收益主要来自 simple 问题，complex-only 不产生增益；
- 若全量启用，延迟从 1.06s 升到约 3.8s；
- 当前默认关闭；需要时显式开启：

```powershell
$env:SCIPAL_SENTENCE_SEEDS = "1"       # 全部问题
$env:SCIPAL_SENTENCE_SEEDS = "adaptive" # 仅复杂问题（无增益）
```

## 8.4 TreeRouter 第一轮（beam best-first）

实现：

- `services/search/tree_router.py`
- `SCIPAL_TREE_ROUTER=1`
- 候选论文来自 flat 检索；
- 节点分 = 0.5 parent + 0.4 summary cosine + 0.1 type prior；
- beam=4、depth=3。

30 题：

| 指标 | baseline | tree router |
|---|---|---|
| sentence strict@10 | 0.5192 | 0.5192 |
| paragraph@10 | 0.7692 | 0.7500 |
| sentence-in-paragraphs | 0.8462 | 0.8077 |
| refusal | 0.75 | 0.75 |

结论：

- summary embedding + beam 没有带来 strict Recall 增益；
- paragraph/coverage 反而略降；
- root/depth 和 parent_id 覆盖不足仍是问题；
- TreeRouter 默认关闭，保留实验开关。

## 8.5 Section 树校验 + 段落级节点分

### 树校验

`python -m build_db.validate_section_tree`：

```
total=69,128
roots=29,198
missing_parent=0
wrong_depth=0
orphan=0
self_parent=0
```

depth 1 的 parent 为空是正常根节点；depth>1 的树完整，不需要重建。

### 段落级节点分

TreeRouter 节点分改为：

```
root:  0.5 paragraph + 0.3 summary + 0.2 type_prior
child: 0.5 parent + 0.2 paragraph + 0.2 summary + 0.1 type_prior
```

30 题：

| 指标 | baseline | TreeRouter（段落分） |
|---|---|---|
| sentence strict@10 | 0.5192 | 0.5192 |
| paragraph@10 | 0.7692 | **0.7885** |
| sentence-in-paragraphs | 0.8462 | 0.8462 |
| refusal | 0.75 | 0.75 |

结论：

- paragraph 略升，但 strict Recall 没有提升；
- TreeRouter 仍不默认启用；
- section 补充段落会与现有 anchor 竞争，收益有限。

## 8.6 TreeRouter 改为“只重排、不补候选”

按“补充段落会与 anchor 竞争”的结论，TreeRouter 改为只在 rerank 后给已有段落加分：

```
section 命中 → 对已有 anchor 的 section 加分
不新增任何段落
```

30 题：

| 指标 | baseline | TreeRouter（只重排） |
|---|---|---|
| sentence strict@10 | 0.5192 | 0.5192 |
| paragraph@10 | 0.7692 | 0.7885 |
| sentence-in-paragraphs | 0.8462 | 0.8462 |
| refusal | 0.75 | 0.75 |

结论：

- 不再有候选竞争，但 strict Recall 仍无提升；
- section prior 只改变少量顺序，不足以改变 top10 句子；
- TreeRouter 默认关闭。
