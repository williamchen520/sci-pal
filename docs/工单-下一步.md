## 一、工单 A：补 `import sqlite3`（真 bug，已实证）

### 现象
服务启动日志实拍：
```
⚠️  数据库迁移跳过（不影响运行）: name 'sqlite3' is not defined
```
`run_db_migrations()` 从来没成功执行过。

### 位置与原因
`api_server.py:1958` `def run_db_migrations():` —— 函数体内**直接**用
`conn = sqlite3.connect(...)`（第 1963 行），但该函数内**没有** `import sqlite3`。
异常被 `try/except` 吞掉，表现为「跳过」。

### 修法（务必跟项目风格）
本项目习惯**函数内局部导入**，不是顶部全局导入。参考现有写法：
`api_server.py` 第 352、367、464、944、1414、1503、1528、1585、1647、1841 行都是函数内 `import sqlite3`。

→ 在 `run_db_migrations()` 的 `try:`（第 1962 行）**之前**加一行 `import sqlite3`。
**不要在文件顶部加全局 import。**

### ⚠️ 风险提示（第一次真跑迁移）
这个函数此前**从未成功执行**。修好后首次启动会真正跑迁移：
```python
for col in ["volume", "issue", "pages"]:
    if col not in existing_cols:
        cursor.execute(f"ALTER TABLE papers ADD COLUMN {col} TEXT")
```
虽然是幂等的 `ALTER TABLE ADD COLUMN`（只补缺失列，低风险），但
**`data/research.db` 会第一次被写** → 修之前请先备份 `data/research.db`，
并在实施说明里写明备份位置。

### 验收
- 重启服务，启动日志中**不再出现** `数据库迁移跳过`。
- 确认迁移已跑：查 `papers` 表应含 `volume` / `issue` / `pages` 三列
  （`PRAGMA table_info(papers)`）。
- `python self_check.py` 不引入新失败（基线：通过 110 / 失败 1 / 总计 121）。
