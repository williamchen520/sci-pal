🎼 解析器调度器 核心
build_db/parsers/parser_orchestrator.py
V3 架构：Docling 主力 + GROBID 增强（可选）
统一调度多个解析引擎，合并结果为标准化格式。GROBID 服务未运行时静默回退到只用 Docling，不影响主流程。
分工策略：
• Docling：段落、图表、表格、章节层级（正文结构主力）
• GROBID：元数据（标题/作者/期刊/DOI/年份）+ 结构化参考文献（补充增强）
• GROBID 可选：服务没运行时自动降级，只靠 Docling
标题合理性校验算法（防止GROBID返回错误标题）：
① 全大写检测：字母大写比例 >85% → 判定为页眉/期刊标签
② 联盟后缀检测：以 "consortium"/"study group"/"collaboration" 等结尾 → 判定为作者团队名
③ 截断检测：以 "("/"-"/"—" 结尾且无闭合 → 判定为截断页眉
④ 标题过短/过长检测：<10字符 或 >300字符 → 可疑
→ 可疑时用 Docling 标题或 PDF 元数据标题替代

🏆 第2层：主力解析器 — Docling（正文结构）
IBM Docling · 布局检测 · 表格AI · 标题层级 · 分层分块
🏆 Docling 主力解析器 主力引擎
build_db/parsers/docling_parser.py
Sci-Pal 的主力 PDF 解析引擎。基于 IBM Docling，专门处理学术 PDF 的正文结构。负责段落、图表、表格、章节层级的提取，是整个解析系统的核心。
管线配置（PdfPipelineOptions）：
• OCR：❌ OFF（数字PDF不需要OCR，提速）
• 表格结构：✅ ON（TableFormerMode，表格AI识别）
• 布局检测：✅ ON（版面分析，段落/标题/图表定位）
• 标题层级：✅ ON（优先用 PDF 书签，其次用布局检测推断）
提取的内容类型（docling_core types）：
• TextItem：正文段落
• SectionHeaderItem：章节标题（含层级 level）
• TableItem：表格（含结构化表格数据）
• FigureItem / PictureItem：图表（版本兼容处理）
分块算法：HierarchicalChunker（分层分块）
不是简单按字数切分，而是按文档的章节层级结构分块：
• 保留章节上下文（section_l1, section_l2）
• 每个 chunk 知道自己属于哪个章节
• 后续检索时可做 small-to-big 上下文扩展
模型下载配置：
• HF_ENDPOINT = https://hf-mirror.com（中国镜像，加速下载）
• HF_HUB_DISABLE_XET = 1（禁用 Xet 协议，避免国内连接问题）
Docling 布局检测 表格AI 分层分块 中国镜像

📋 第3层：元数据/参考文献解析器 — GROBID（可选增强）
GROBID · TEI XML · 元数据提取 · 结构化参考文献 · DOI正则
📋 GROBID 元数据解析器 可选增强
build_db/parsers/grobid_parser.py
GROBID (GeneRation Of BIbliographic Data) 是专门的学术文献元数据提取工具。补充 Docling 在元数据和参考文献方面的不足。需要本地运行 GROBID 服务（默认 http://localhost:8070），未运行时自动跳过。
服务配置：
• GROBID_URL = http://localhost:8070（可通过环境变量覆盖）
• 调用 /api/processFulltextDocument 接口
• 返回 TEI (Text Encoding Initiative) XML 格式
提取内容（V2.0 完整TEI XML解析）：
• 元数据：标题、作者、DOI、期刊、年份、卷期、页码
• 结构化参考文献：每篇参考文献的作者/标题/期刊/年份/DOI（解析为结构化字段，不是纯文本）
• 章节层级：TEI 中的 div 层级结构
DOI 正则提取算法（find_doi_in_text）：
正则：10\.\d{4,9}/[^\s;,\]\)"<>]+（不区分大小写）
处理场景：
① 标准格式：dx.doi.org/10.xxxx/...、doi:10.xxxx/...、裸 10.xxxx/...
② 空格分隔的 DOI（OCR错误）：先去掉所有空格再匹配
③ 尾部清理：去掉末尾的 .,;: 等标点，转小写
为什么需要 GROBID？
Docling 的参考文献提取是纯文本，GROBID 能把参考文献解析为结构化字段（作者/标题/期刊/年份/DOI），用于：
• 构建论文引用图谱（CITES 关系）
• 参考文献去重（按 DOI/标题匹配）
• 引用溯源（文内引用 → 参考文献条目）
GROBID TEI XML 元数据 结构化参考文献 DOI正则

🔄 第4层：备选解析器 — MinerU（学术PDF最佳整体）
MinerU (magic-pdf) · 懒加载 · 学术优化 · 标准化输出
🔄 MinerU 备选解析器 备选引擎
build_db/parsers/mineru_parser.py
MinerU (magic-pdf) 是上海人工智能实验室开源的学术PDF解析工具，号称"学术PDF最佳整体解析器"。作为 Docling 的备选方案，在 Docling 解析效果不佳时使用。
懒加载设计（Lazy Load）：
• 启动时不加载 MinerU（避免启动延迟）
• 首次调用 parse() 时才 from magic_pdf.cli.common import common_parse
• 未安装时打印提示：pip install mineru[all]，返回空结果不崩溃
标准化输出格式：
{ "paragraphs": [...], "figures": [...], "metadata": {...} }
与 Docling/GROBID 输出格式一致，调度器可直接合并。
MinerU 核心技术：
• 版面分析（检测标题/正文/图表/公式/表格区域）
• 公式识别（LaTeX 输出）
• 表格识别（结构化输出）
• 阅读顺序推断（多栏排版的正确阅读顺序）
• 中英文混合优化
MinerU magic-pdf 懒加载 学术优化
📊 第5层：专用解析器 — pdfplumber（复杂表格提取）
pdfplumber · 表格提取 · 逐页扫描 · 空表过滤
📊 pdfplumber 表格专用解析器 专用引擎
build_db/parsers/pdfplumber_parser.py
专门用于复杂表格提取。当 Docling 的表格识别效果不佳时（如复杂跨页表格、合并单元格、无框线表格），用 pdfplumber 做补充提取。不处理正文段落，只专注表格。
核心方法：
• pdfplumber.open(pdf) 打开PDF
• 逐页 page.extract_tables() 提取表格
• 返回二维列表（行×列）
表格过滤算法：
• 跳过空表/小表：len(table_data) < 2（少于2行的跳过）
• 自动编号：table_id = "{paper_id}_tab{index:03d}"
• 记录页码：page_number（用于PDF定位）
输出结构：
{ "tables": [ { "table_id", "paper_id", "page_number", "caption", "table_data": [[...]] } ] }
pdfplumber 表格提取 逐页扫描 空表过滤

⚡ 第6层：期刊感知优化器 — Nature/Science/Cell 专项优化
DOI前缀识别 · 期刊家族检测 · 标题识别优化 · 双栏布局 · 章节归一化
⚡ 期刊感知优化器 V25.16新增
build_db/parsers/journal_optimizer.py
针对 Nature / Science / Cell 及其子刊的专项优化。检测论文所属期刊家族，应用针对性的解析优化策略，提高顶刊论文的解析准确率。
期刊家族检测算法（DOI前缀映射）：
通过 DOI 前缀识别期刊家族，例如：
• 10.1038/s41586 → Nature
• 10.1038/s41591 → Nature Medicine
• 10.1038/s41587 → Nature Biotechnology
• 10.1038/s41467 → Nature Communications
• 10.1126/science → Science
• 10.1016/j.cell → Cell
• 10.1016/j.ccell → Cancer Cell
• ...（共覆盖 50+ 子刊）
支持的期刊家族：
• 🌿 Nature 家族：Nature, Nature Medicine, Nature Biotechnology, Nature Communications, Nature Immunology, Nature Neuroscience, Nature Genetics, Nature Methods, Nature Physics, Nature Chemistry...
• 🔬 Science 家族：Science, Science Advances, Science Robotics, Science Immunology...
• 🧬 Cell 家族：Cell, Molecular Cell, Cancer Cell, Cell Stem Cell, Cell Reports, Cell Metabolism, Immunity, Neuron...
• 📄 Other：通用优化策略
优化内容（按期刊家族应用）：
① 期刊特定章节标题识别：不同期刊的章节命名习惯不同（如 Nature 用 "Results"，Cell 可能用 "Results and Discussion"）
② 卷期页码提取：不同期刊的卷期页码格式不同
③ 章节类型归一化：把不同表述统一为标准类型（intro/methods/results/discussion/conclusion）
④ 双栏布局提示：顶刊多为双栏排版，提供布局检测的先验知识
期刊感知 DOI识别 Nature Science Cell 双栏优化
