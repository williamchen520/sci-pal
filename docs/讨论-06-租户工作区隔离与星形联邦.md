# 讨论记录：租户工作区隔离与星形联邦

> 日期：2026-11-14  
> 编号：讨论 06  
> 状态：已形成结论  
> 关联：租户权限、主库、联邦索引、类 Unix 工作区

---

## 1. 问题

租户和主库是否可以拥有相同的建库/功能系统，但权限不同？

租户是否可以有独立工作区，并选择与主库建立联邦索引，而租户之间严禁联邦？

---

## 2. 结论

```text
同构系统
异构权限
功能复制
权限不复制
```

```text
主库是唯一联邦中心
租户只能挂主库
租户之间没有联邦边
隔离靠拓扑和凭据，不靠 UI
```

---

## 3. 类 Unix 模型

```text
platform        = kernel / root
tenant          = namespace + workspace
tenant library  = mount point
federation      = mount main，只读
```

每个租户：

```text
自己的 workspace
自己的 library
自己的用户
自己的索引
自己的 codeRAG
自己的配额
```

彼此不可见。

---

## 4. 星形联邦拓扑

```text
             main
           /  |  \
      tenantA tenantB tenantC
```

允许：

```text
tenantA -> main
tenantB -> main
tenantC -> main
```

严禁：

```text
tenantA -> tenantB
tenantB -> tenantC
```

租户之间没有联邦边。

---

## 5. 允许的查询 scope

```text
scope=own
scope=main
scope=both
```

默认：

```text
main 只读
own 可写
```

租户不能：

```text
写主库
改主库索引
看主库未授权 library
把主库数据复制进自己的库
```

除非显式授权/导出。

---

## 6. 租户之间禁止联邦

必须结构性禁止：

```text
federation catalog 不登记 tenant->tenant
gateway 不接受 target_tenant_id
tenant connector 没有其他租户的 DSN/URL
凭据不共享
查询 scope 只允许 own/main/both
```

不能只靠：

```text
前端不显示
角色没勾选
```

那只是 UI 约束，不是隔离。

---

## 7. 租户之间需要协作怎么办

不能直接联邦，只能：

```text
1. 主库中转的共享项目
2. 显式导出/导入
3. 平台审批的跨租户数据集
4. 双方授权的研究协作空间
```

而且要有：

```text
审批
范围
时限
审计
```

不是默认能力。

---

## 8. 权限模型

```text
tenant admin
  可以管理自己的 workspace
  不能建立 tenant->tenant federation

platform owner
  可以开/停租户
  可以配置 main 联邦
  不能默认读租户正文

tenant user
  只能 own
  可选 main
```

使用：

```text
principal
  + membership
  + role
  + capability
  + resource scope
```

而不是：

```text
admin / user
```

---

## 9. 平台拥有者的边界

可以有：

```text
租户开通/停用
配额
平台插件版本
全局模型配置
跨租户目录
审计
```

不应默认有：

```text
读取租户正文
修改租户数据
代替租户批准发布
```

支持访问必须：

```text
support grant
工单授权
审计留痕
限时访问
```

---

## 10. 租户管理员边界

可以有：

```text
创建 library
批量导入
配置本租户 parser
邀请成员
审批本租户发布
删除本租户数据
```

不能有：

```text
访问其他租户
修改平台插件注册表
修改主库
绕过平台配额
把租户数据写进主库
```

---

## 11. 当前系统差距

```text
已有 workspace_id
已有 tenant governance 文档
但还没有 federation catalog
没有 tenant connector
没有 scope=own/main/both 的强制路由
没有 tenant->tenant 的结构性拒绝
```

需要补：

```text
federation_catalog
  tenant_id
  library_id
  allowed_scopes = own,main
  main_subscription
  no peer_tenant_edges

gateway
  resolve_scope(tenant, requested)
  reject tenant:<other>
```

---

## 12. 实现决策点

后续讨论需要决定：

```text
1. 一租户一 DB，还是一 library 一 DB
2. federation catalog 存哪里
3. tenant connector 如何拿 main 凭据
4. main 联邦是只读还是允许订阅复制
5. 平台支持访问是否需要双人审批
6. 租户互访是否只允许主库中转
7. 跨租户共享项目的数据边界
8. 配额/队列/模型是否物理隔离
9. 删除租户时联邦索引如何撤销
10. 审计事件保留多久
```
