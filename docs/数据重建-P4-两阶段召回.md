# Two-Stage Sentence Recall + Cross-Encoder

> Date: 2026-11-01  
> Trigger: 9.2s sentence-FTS stage in the 20-query RRF loop.

## 1. EXPLAIN result

The GIN index is present and used:

```text
Bitmap Index Scan on idx_sentences_search
Parallel Bitmap Heap Scan on sentences
Sort by ts_rank(...)
Limit 1000
```

No sequential scan was observed. The cost is the bitmap heap scan plus sorting
all matching sentences by `ts_rank`.

## 2. Cheap recall without ranking

```text
SentenceFTS.recall(query, top_k=200)
```

Latency:

```text
~0.256s
```

But paper quality was unusable:

```text
Recall@10 = 0.00
```

Reason:

```text
LIMIT without ORDER BY returns an arbitrary physical subset
the gold paper is not guaranteed to appear in that subset
```

## 3. Ranked recall, 5 terms

```text
SentenceFTS.search(query, top_k=200, term_limit=5)
→ cross-encoder over the 200 sentences/paragraphs
```

20 queries:

| System | Recall@10 | MRR | nDCG@10 |
|---|---:|---:|---:|
| paragraph_fts | 1.0000 | 0.8806 | 0.9097 |
| ranked recall 5 / 200 + rerank | 0.8500 | 0.7681 | 0.7866 |

Latency of the FTS stage:

```text
5 terms / 200: 1.65s cold, then 0.36–0.5s warm
```

## 4. Interpretation

```text
The cheap unranked recall is fast but loses the gold paper.
Ranked recall with fewer terms is fast enough, but loses ~15% recall.
Cross-encoder cannot recover a paper that is absent from the candidate set.
```

## 5. Decision

```text
Keep paragraph FTS for production paper ranking.
Keep the two-stage candidate generation experimental.
Do not trade recall for latency without a better first stage.
```

## 6. Next options

```text
1. Increase candidate depth but keep 5–8 terms.
2. Add a cheap lexical pre-score instead of ORDER BY ts_rank.
3. Use ts_rank_cd for the first stage and compare recall.
4. Partition sentences by year/domain and search only the relevant partition.
5. Evaluate Elasticsearch/Milvus only after the data volume justifies it.
```
