## V33.17（2026-10-14）

**修改**：
- `services/review/review_generator.py` — 综述证据检索支持摘要回退：
  - 新增 `_get_fulltext_doi_map()`：从 `research.db` 加载 DOI → paper_id 映射（模块级缓存，476 篇）
  - `search_and_assign_papers()`（按大纲分配流程）每章节全文检索后追加摘要库检索，摘要命中按 DOI 判定：
    - 全文库无同 DOI → 摘要当一条证据（`paper.source="abstract"`、`source_type="abstract"`、`section_l1="Abstract"`）
    - 全文库有同 DOI → 摘要证据合并到全文 paper_id 名下（一篇论文一个身份，不产生 pmid 重复条目）

  - `_retrieve()`（topic 流程）摘要循环补齐 DOI 去重与 `source_type` 字段

- `frontend/src/paper_list.js` — 证据数区分显示：`3 条证据（全文2+摘要1）` / `1 条证据（摘要）`
- `frontend/src/review.js` — 证据详情面板给摘要证据加 `📄 摘要` 徽章

**背景**：按大纲分配的论文若只有摘要（无 PDF/XML 全文），检索证据返回 0 条 → 该章节空白。

## V33.14（2026-10-14）

**修改**：
- `services/ai/rag_validator.py` — 修正则表达式：
  - 原 `r'\[([TPFC]\d{2})\]'` 仅匹配 `[T01]/[P02]/[F03]/[C04]`，与 qa_service 的实际引用格式不匹配
  - 新 `r'\[([TPFRCG]\d+)\]'` 支持 P/F/T/R/C/G 类型、数字位数不限，与 `qa_service.CITATION_PATTERN` 对齐
- `services/qa/qa_service.py` — QAService.ask() 接入 RAGValidator 防幻觉校验：
  - 顶部新增 `from services.ai.rag_validator import RAGValidator`
  - `__init__` 实例化 `self.validator = RAGValidator(coverage_threshold=0.8)`（QA 场景阈值 0.8）
  - Step 3 之后新增 Step 3.5：从 envelope 文本提取引用 ID → validate → 失败则用 build_retry_prompt 重试一次
  - result 新增 `validation` 字段（coverage / passed / missing / retried / message），不删改任何原有字段

**设计决策**：
- 防幻觉不是 NLI 模型，是引用 ID 覆盖率校验（项目约定）
- 阈值 0.8 而非 0.9：QA 不要求每个证据都被引用
- 重试上限 1 次，避免长链路超时
- 前端 `/api/qa/ask` 接口格式不变，只新增可选字段

**验证**：
- `python -m py_compile` 两个文件语法 OK
- self_check.py 1-6 项通过（6.5 为 pre-existing 编码问题）

**文档（V33.14 续）**：
- `ARCHITECTURE.md` 第八章"NLI/LoRA/微调"暂缓记录下方追加：
  - NLI 接回触发条件（每周矛盾案例 ≥3 例 / 检索准确率 ≥90% 但生成质量仍卡 / 出现 ≤500MB 轻量 NLI 模型）
  - NLI 接入方案预告（模型选型 / 接入位置 / 逐句 entailment 策略 / 非阻塞后处理）
- `docs/任务.md`"当前进行中"表格新增 P1 技术债：`QAService 接入 RAGValidator`，说明重构时漏接正则引用覆盖率校验、防幻觉仅靠 prompt，需在 `llm.chat()` 后插入 `validate()`、阈值 0.8、不通过重试一次
