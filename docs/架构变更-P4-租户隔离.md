# 架构变更授权：P4 租户隔离

> 日期：2026-11-08  
> 状态：**待人类批准修改**  
> 规则：`.dsh_rules` 规则 0A  
> 前置：P0-P3 完成

---

## 1. 问题

现在所有连接都是同一个超级用户：

```text
role       scipal
rolsuper   true
schema     public / catalog / library_main / library_bench
users      2
workspaces 1（ws_default）
```

后果：

```text
应用进程可以写主库任何表
workspace 只是行级 workspace_id
没有数据库级只读边界
一个 bug 可能写坏主库
```

---

## 2. 变更

改哪一层：

```text
权限 + schema
```

P4a 新增角色：

```text
scipal_main_reader    只读主库
scipal_tenant_writer  只写租户 schema
```

权限：

```text
scipal_main_reader
  CONNECT scipal_bench
  USAGE catalog / library_main / library_bench / public
  SELECT 所有主库表
  无 INSERT / UPDATE / DELETE / DDL

scipal_tenant_writer
  CONNECT scipal_bench
  USAGE 自己的 lib_ws_* schema
  CREATE / USAGE 自己的 schema
  无 public / catalog / library_main 写权限
```

P4a 新增：

```text
lib_ws_<hash>
  每 workspace 一个 schema
  初始为空
```

P4a 不改：

```text
应用 DSN
现有 scipal 连接
public 数据
API
```

P4b 才切换应用连接。

---

## 3. 理由

```text
只靠 workspace_id 过滤，不是隔离
数据库角色是最后一道防线
先建角色和 schema，再切连接，风险最低
```

如果直接切 DSN：

```text
现有所有写路径可能失败
租户 schema 还没建
回滚成本高
```

---

## 4. 影响

当前规模：

```text
users       2
workspaces  1
```

P4a 不改数据，只加：

```text
2 个角色
1 个 lib_ws_default schema
```

风险：

```text
角色权限配置错误 -> 后续 P4b 连接失败
schema 命名冲突 -> 先检查
```

---

## 5. 迁移

步骤：

```text
1. 创建 scipal_main_reader / scipal_tenant_writer
2. 授予主库只读
3. 创建 lib_ws_default
4. 授予 tenant_writer 该 schema
5. 用 SET ROLE 验证
6. 应用继续用 scipal
```

回滚：

```sql
DROP SCHEMA IF EXISTS lib_ws_default CASCADE;
DROP ROLE IF EXISTS scipal_tenant_writer;
DROP ROLE IF EXISTS scipal_main_reader;
```

P4a 不改数据，回滚安全。

---

## 6. 验证

```text
SET ROLE scipal_main_reader;
  SELECT count(*) FROM public.papers;       成功
  INSERT INTO public.papers ...;            拒绝

SET ROLE scipal_tenant_writer;
  CREATE TABLE lib_ws_default.t (...);      成功
  SELECT count(*) FROM public.papers;       成功（只读）
  INSERT INTO public.papers ...;            拒绝
```

应用：

```text
/api/health 200
A 组 smoke 无 5xx
```
