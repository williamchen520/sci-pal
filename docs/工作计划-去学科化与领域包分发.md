# 工作计划：去学科化、领域包与分发

> 状态：待评审  
> 定位：面向有计算机基础的二次开发者、计算机中心与开源分发。  
> 原则：核心学科无关，领域知识以领域包挂载；声明式优先，Python 钩子兜底。

## 1. 背景

SciPal 目前仍有 HCC/生物医学硬编码：

- 领域 taxonomy；
- section 类型；
- QA/综述/简报 prompt；
- 词表；
- 评测集；
- UI 术语。

目标不是做“给非技术用户的后台配置”，而是：

```
开发者不改核心
→ 写领域包
→ 签名
→ 分发
→ 部署到新单位/新学科
```

## 2. 目标用户

1. 有 Python 基础的领域研究者；
2. 学校/研究所计算机中心；
3. 二次开发团队；
4. 需要离线部署的实验室/超算中心。

## 3. 非目标

- 非技术 PI 的无代码配置；
- 任意用户安装插件；
- 承诺稳定 API；
- 公共插件市场；
- 第一版做可视化包编辑器。

## 4. 核心架构

```
scipal-core          学科无关
├─ VFS / 权限
├─ 检索 / 证据 / 引用
├─ 任务 / 审计
└─ SDK 扩展点

scipal-sdk           开发者接口
├─ DomainPack
├─ TaxonomyProvider
├─ SectionClassifier
├─ EvidenceSchema
├─ PromptProvider
├─ SourceConnector
└─ Evaluator

packs/               领域包
├─ biomed-hcc
├─ chemistry
└─ ...
```

核心只依赖 SDK，不 import 具体领域包。

## 5. 领域包粒度

支持三级：

```
学科        chem
子领域      chem.organic
课题组      chem.organic.lab-x
```

规则：

- 包 ID 用点分层；
- `extends` 继承父包；
- `compose` 组合多个包；
- workspace 选择主包；
- 论文可属于多个包；
- 课题组包可以覆盖 prompt/词表，但不能改核心权限。

示例：

```yaml
id: chem.organic.lab-x
version: 0.1.0
extends: chem.organic
```

## 7. pack.yaml

```yaml
id: chemistry
version: 0.1.0
discipline: chemistry
language: zh
license: AGPL-3.0-only
extends: null
requires:
  scipal_sdk: ">=0.1"
hooks:
  section_classifier: hooks.hooks:ChemistrySectionClassifier
  evidence_schema: hooks.hooks:ChemistryEvidenceSchema
```

说明：

- `scipal_sdk` 只是提示，不承诺兼容；
- 安装时记录 core commit；
- 破坏性变更在 release notes 标注。

## 8. 声明式 + Python 钩子

### 声明式
- taxonomy；
- section types；
- evidence fields；
- prompt；
- sources；
- UI labels；
- eval gold。

### Python 钩子
- 复杂 section 分类；
- 自定义证据抽取；
- 自定义评测；
- 特殊数据源。

约束：

- 钩子只能通过 SDK context 访问数据；
- 不直接连数据库；
- 不读 `/etc`、其他 workspace；
- 运行在受控进程；
- 包必须签名。

## 9. SDK 扩展点

建议先定义最小集合：

```python
class TaxonomyProvider(Protocol):
    def classify(self, text: str) -> list[TaxonomyLabel]: ...

class SectionClassifier(Protocol):
    def classify(self, title: str, path: list[str]) -> str: ...

class EvidenceSchema(Protocol):
    def validate(self, evidence: dict) -> list[str]: ...

class PromptProvider(Protocol):
    def get(self, name: str, language: str) -> str: ...

class SourceConnector(Protocol):
    def search(self, query: str, **kwargs) -> list[SourceItem]: ...

class Evaluator(Protocol):
    def evaluate(self, gold: list[dict], answers: list[dict]) -> dict: ...
```

不承诺 API 稳定，但：

- SDK 版本号；
- 变更日志；
- 迁移指南；
- 示例包跟随更新。

## 10. 核心去硬编码

第一批迁移：

| brief prompt | `prompts/brief.md` |

验收：

```bash
grep -R "HCC\|hepatocellular\|ORR" scipal/ --include=*.py
```

核心代码不应出现领域词。

## 11. Git 分发

### 仓库

```text
scipal-packs/
├─ packs/
│  ├─ biomed-hcc/
│  ├─ chemistry/
│  └─ general/
├─ keys/
│  └─ allowed_signers
└─ README.md
```

### 版本

- 推荐 semver；
- tag：`chemistry-v0.1.0`；
- 安装锁定 commit/tag；
- 不使用浮动分支。

### 签名

要求签名：

- minisign / Ed25519；
- 每个包生成 `pack.tar.gz.minisig`；
- 安装时校验；
- 公钥放 `keys/allowed_signers`；
- 未签名包默认拒绝。

### 安装

```bash
scipal pack install git+https://.../scipal-packs.git#chemistry-v0.1.0
```

或：

```bash
scipal pack install chemistry-0.1.0.tar.gz
```

## 14. 非医学试点

建议第一个非医学包：**化学**。

原因：

- 结构差异明显；
- 开源数据多；
- 与生物医学共享部分术语，但 section/证据不同；
- 便于验证核心抽象。

验收：

```
安装 chemistry 包
→ 不改核心代码
→ 20 题 smoke
→ 检索/证据/引用可用
```

- 许可证随包。

## 16. DSH 深度嵌合后的离线包

后续目标：

```
SciPal + DSH + 领域包 + 本地模型
→ 一个离线安装包
```

要求：

- 无外网依赖；
- 内网模型端点可替换；
- 领域包可插拔；
- 安装脚本幂等；
- 升级/回滚；
- 许可证清单。

## 17. 许可证

核心：AGPL-3.0-only。

领域包：AGPL-3.0-only。

要求：

- `LICENSE` 随包；
- `pack.yaml` 写 license；
- 文档说明 AGPL 义务；
- 二次开发者分发修改版时的源码义务；
- 闭源集成边界写清楚。

## 18. 安全

- 只允许管理员安装包；
- 签名校验；
- 包不能直连 DB；
- 包不能跨 workspace；
- 包不能读系统配置；
- hooks 在受控进程；
- prompt 注入测试；
- 安装/升级审计。

## 19. 版本与兼容

不承诺稳定 API，但提供：

- `scipal_sdk` 版本；
- core commit 记录；
- pack lock；
- release notes；
- 迁移指南；
- conformance 测试。

安装时：

```
warn if pack requires newer sdk
fail if pack uses removed API
```

不保证旧包永远可用。

## 21. 验收

- 核心代码 grep 无 HCC/ORR 等硬编码；
- 新包不需要改核心；
- 未签名包拒绝安装；
- 签名包可离线安装；
- `scipal pack test` 可跑；
- 化学 20 题 smoke；
- 文档 quickstart 可复现；
- AGPL 文件齐全。

## 22. 风险

- 不承诺 API 稳定导致包碎片；
- hooks 安全边界；
- 签名密钥管理；
- 包与核心版本漂移；
- 离线包过大；
- 模型许可证；
- 领域包质量参差；
- 核心仍残留隐式学科假设。

## 23. 需要确认

1. 签名工具：minisign 还是 cosign？
2. 包仓库是否独立 git repo？
3. 化学试点数据源选什么？
4. 离线包是否包含模型权重？
5. 是否要求包作者提供 20 题 smoke？
6. 包安装权限只给 admin？
7. 是否保留 `general` 包作为 fallback？
