## 1. 问题

现在哪里不成立，证据是什么：

```text
scipal_bench 主库没有 work / library / document 三层
papers.paper_id 同时兼任 work 和 document
scipal_v2 有 documents/source_nodes 雏形，但未接入主库
v2 documents 2,903 / main papers 10,102，覆盖率 28.7%
v2 source_type 只允许 pdf/xml，MD 未支持
```

证据：

```text
scipal_v2.documents          2,903
scipal_v2.documents.pdf         83
scipal_v2.documents.xml      2,820
scipal_v2.papers             3,301
scipal_bench.papers         10,102
```

后果：

```text
同一篇论文 PDF + XML 会被 paper_id 覆盖
无法表达 main / tenant / benchmark library
无法做 work 级去重
无法做联邦检索
```

## 2. 变更

改哪一层：

```text
schema
```

新增：

```text
catalog schema
  libraries
  works

library_main schema
  documents
  source_nodes
```

不修改：

```text
public.papers
public.paragraphs
public.sentences
现有 API
现有检索
```

---

## 3. 理由

为什么必须改：

```text
work 是跨格式聚合的最小单位
library 是主库/租户库/评测库的边界
document 是格式版本的边界
```

不改的代价：

```text
300 题金标无法稳定绑定 work/document
GraphRAG 会被重复版本污染
客户端入库追踪无法挂到正确库
联邦检索没有候选集边界
MCP 工具无法表达 scope
```
