# 工作计划：多用户与数据隔离

> 状态：待评审  
> 范围：第 4 项（多用户、权限、数据隔离、PI 只读/复制、LLM 数据边界）  
> 原则：Linux “一切皆文件” + 应用层 VFS + 数据分级 + 本地优先。

## 1. 背景与约束

实验室场景：

- 常开 Linux 服务器；
- GPU 在服务器/工作站；
- 一个课题组 20–30 人；
- 账号规模 1000，并发约 100；
- 私有数据不出实验室/研究所网络；
- 已发表文献允许走远端模型；
- 有的实验室有账号系统，有的没有；
- 存储为服务器本地盘或外挂硬盘；
- 不需要跨实验室共享。

## 2. 目标

1. 多用户、多 workspace 隔离；
2. PI 只读课题组共享数据；
3. private 资源 PI 不可读、不可复制；
4. sealed 资源 PI 完全不可见；
5. 本地/超算/公网模型按数据等级路由；
6. 单节点起步，支持 1000 账号 / 100 并发；
7. 兼容 SciPal 独立账号与实验室账号。

## 3. 非目标

- 跨实验室共享；
- 组织架构/多级部门；
- 公网 SaaS 多租户；
- 第一版做完整 LDAP/AD 同步；
- 第一版做 Kubernetes。

## 4. 总体架构

```
Caddy / Nginx（TLS、限流）
        │
Flask API（多 worker）
        │
PostgreSQL（元数据、权限、审计）
Redis（session、队列、限流）
RQ/Celery worker（索引、简报、导出）
Chroma/Qdrant（向量，workspace 过滤）
MinIO / 本地内容寻址目录（文件）
vLLM（本地模型）
LLM Gateway（本地 / 超算 / 公网路由）
```

单节点 Docker Compose 起步，组件按 100 并发设计。

## 5. 身份与认证

### 5.1 模式

```yaml
auth:
  mode: local | oidc | ldap | saml | hybrid
  allow_local_fallback: true
  group_mapping:
    lab_group: workspace_id
```

- `local`：SciPal 独立账号；
- `oidc/saml`：实验室统一身份；
- `ldap`：AD/OpenLDAP；
- `hybrid`：外部身份 + 本地管理员/服务账号。

### 5.2 本地账号

- Argon2id 密码；
- 邮箱/用户名唯一；
- 首个管理员由部署初始化；
- 不把用户映射为 Linux 系统用户。

### 5.3 会话与 token

- Redis session；
- 短期 access token；
- MCP/DSH 使用 scoped API token；
- token 绑定 user + workspace；
- 支持撤销。

### 5.4 账号规模

- 1000 账号；
- 100 并发；
- SSO 优先；
- 本地账号只做 fallback。

## 6. 多租户模型

```
Organization（可选）
└─ Workspace（课题组）
   ├─ Membership(role)
   ├─ Project
   ├─ Experiment
   ├─ Brief
   └─ Resource
```

- `workspace` 是隔离单位；
- 一个用户可以属于多个 workspace；
- 不跨 workspace 共享；
- 全局只共享 `public` 论文库。

### 角色

| 角色 | 权限 |
|---|---|
| owner | 管理 workspace、成员、配置、删除 |
| PI | 读 internal/public；复制 internal/public；不能写他人 |
| member | 读写自己的资源；读共享项目 |
| viewer | 只读共享内容 |
| admin | 系统配置/备份/审计；默认不读业务数据 |

## 7. 数据分级

每个资源：

```text
data_class = public | internal | private | sealed
source     = published | unpublished | experiment | note | brief
license    = ...
```

| 级别 | 示例 | PI 读 | PI 复制 | 公网模型 |
|---|---|---|---|---|
| public | 已发表论文 | ✅ | ✅ | ✅ |
| internal | 课题组共享 | ✅ | ✅ | ❌ |
| private | 实验原始数据 | ❌ | ❌ | ❌ |
| sealed | 笔记、简报草稿 | ❌ | ❌ | ❌ |

### private

PI 可见：

- 资源存在；
- 类型；
- 大小；
- 修改时间；
- hash/版本变化。

PI 不可见：

- 内容；
- 文件名以外的敏感字段；
- 不可复制。

### sealed

PI 连存在/修改都不可见。  
只有 owner 可见。

### 成员主动共享

private/sealed 只能由 owner：

```
share / transfer
→ 生成副本或授权
→ PI 才能读/复制
```

不允许 PI 主动盲复制。

## 8. 逻辑 VFS

```text
/scipal
├─ library/                  # public，只读
├─ workspaces/<ws>/
│  ├─ shared/                # internal
│  ├─ members/<user>/        # private
│  ├─ projects/
│  ├─ experiments/
│  ├─ briefs/
│  └─ pi/
├─ users/<user>/private/     # sealed/private
├─ etc/                      # 系统配置，业务不可见
├─ var/                      # 索引/缓存/任务/审计，业务不可见
└─ proc/                     # 运行态，业务不可见
```

### 业务可见范围

只暴露白名单资源：

- paper
- project
- experiment
- brief
- note
- attachment

`/etc`、`/var`、`/proc` 对业务用户完全不可见。

### 不提供任意路径操作

- 不提供 `cp /any/path`；
- 复制只接受资源 ID；
- 服务端解析资源路径；
- 拒绝 `..`、绝对路径、跨 workspace；
- 符号链接不用于权限边界。

### xattr

```text
owner
workspace
data_class
source
license
hash
copied_from
```

## 9. 复制与解锁

### 允许复制

仅：

- public；
- internal；
- 已被 owner share/transfer 的 private。

### 复制语义

```
POST /api/resources/<id>/copy
target = 个人目录或指定项目
→ 服务端深拷贝元数据 + 内容
→ 记录 source_resource_id
→ 新资源 owner = 操作者
→ 保留 data_class 与 license
→ 写审计
```

### PI 复制

- PI 可复制 internal/public；
- 复制后归 PI，可编辑；
- 原资源不变；
- 不能复制 private/sealed。

## 10. LLM 网关与数据边界

### 10.1 端点注册

```yaml
providers:
  - id: local-vllm
    trust_zone: onprem
  - id: hpc-llm
    trust_zone: hpc
  - id: deepseek
    trust_zone: public_cloud
```

### 10.2 路由矩阵

| data_class | local | hpc | public_cloud |
|---|---|---|---|
| public | ✅ | ✅ | ✅ |
| internal | ✅ | ✅ | ❌ |
| private | ✅ | ✅ | ❌ |
| sealed | ✅ | ✅ | ❌ |

### 10.3 规则

- evidence 含 private/sealed/internal → 只能 onprem/hpc；
- 没有可用本地/超算模型 → 只返回证据，不生成结论；
- 不允许静默回退到公网；
- 每次调用记录 policy 决策；
- 复制/派生继承最高 data_class。

### 10.4 公网 API

- 只处理 public 论文；
- 不发送项目名、实验记录、笔记、简报草稿；
- 发送前做资源级检查，不是只检查 query。

## 11. 存储

### 元数据

PostgreSQL：

- users
- workspaces
- memberships
- resources
- resource_acl
- resource_copies
- audit_log

### 文件

```
/data/scipal/
  blobs/<sha256>
  workspaces/<ws>/
  backups/
```

- 内容寻址；
- 本地盘或外挂硬盘；
- 不依赖 NAS；
- 服务账号读写，业务用户不直接访问。

### 备份

- restic / pg_dump；
- 每日增量；
- 本地 + 外挂盘；
- 加密；
- 定期恢复演练。

## 12. 数据模型（核心表）

```sql
users(user_id, username, email, password_hash, status, created_at)

workspaces(workspace_id, name, owner_user_id, created_at)

memberships(workspace_id, user_id, role, status)

)

  resource_id, metadata, created_at
)
```

## 13. 隔离实现

### 数据库

- 所有查询强制 `workspace_id`；
- repository 层统一注入；
- PostgreSQL RLS（第二阶段）；
- 禁止路由直接拼 SQL。

### 向量库

- 单 collection + `workspace_id` metadata；
- 所有 query 强制 filter；
- 负向测试：不能跨 workspace 命中；
- 企业版可选独立 collection。

### 缓存

- key 带 user/workspace；
- 禁止跨 workspace 复用。

### 文件

- 路径由服务端生成；
- 业务 API 不接收原始路径；
- 下载走鉴权接口。

## 14. 审计

记录：

- 登录/失败；
- PI 读取 internal/public；
- 成员 share/transfer；
- 复制；
- 导出；
- 删除；
- 权限变更；
- LLM policy 决策。

private：

- 记录 PI 查看了元数据；
- 不记录内容；
- 不记录 PI 读取内容（因为不可读）。

sealed：

- 不对 PI 产生可见审计。

审计对成员可见的范围：

```
成员可看到“自己的资源被 PI 查看元数据/被共享/被复制”
```

## 15. 迁移

现有单用户数据：

1. 创建默认 workspace；
2. 现有数据归 owner；
3. 回填 `workspace_id`；
4. 旧 API 默认映射到默认 workspace；
5. 迁移脚本可回滚；
6. 迁移前备份。

现有云端配置：

- 默认只对 public 生效；
- private 必须走本地/超算；
- 启动时检查 provider 配置，不合规拒绝启动或禁用云端。

## 17. 验收

### 隔离

- A 用户不能读 B 用户 private；
- 成员不能读他人 private；
- PI 不能读/复制 private；
- PI 看不到 sealed；
- 跨 workspace 查询返回空；
- 向量检索不跨 workspace。

### 权限

- PI 可读 internal/public；
- PI 不能写他人资源；
- PI 复制 internal/public 后解锁；
- 成员 share 后 PI 可读。

### 数据边界

- private 请求不会调用 public_cloud；
- 无本地/超算模型时只返回证据；
- policy 决策有审计。

### 规模

- 1000 账号；
- 100 并发 smoke；
- API P95 可接受；
- 索引队列不阻塞查询。

## 18. 风险

- private 元数据仍可能泄露信息；
- Chroma filter 遗漏导致越权；
- 多 worker 下 SQLite 不可用，必须 PostgreSQL；
- 外挂盘故障；
- 本地模型能力不足；
- 超算端点信任边界；
- PI 共享流程被滥用；
- 备份未加密。
