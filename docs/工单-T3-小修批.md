## T3-1（P2）排队期间取消 → **不许再跑一次 docling**

### 现状

`_parse_and_store()` 里 `on_acquired` 是「只写进度」的回调，之后**无条件** `ParserOrchestrator()` + `parse_paper()`。
于是「排队时点了取消」的任务：等到锁 → 还是解析约 15 s（+3.5 GB）→ 到 `before_store` 才放弃。
数据是对的（不落库），但**白烧一次解析**。

### 要做的

1. `on_acquired` 的约定改成**有返回值**：
   - 返回 `False` → 立刻 `raise ParseCancelled("排队期间已取消，未解析")`，**在 `ParserOrchestrator()` 构造之前**；
   - 返回其他/不返回（`None`）→ 照常解析（**向后兼容，同步路由不传它**）。
2. 异步路由把 `on_acquired` 换成带返回值的函数：

   ```python
   def _on_acquired() -> bool:
       if task_manager.is_cancelled(task_id):
           return False                       # 排队期间被取消 → 这次解析直接放弃
       task_manager.update_progress(task_id, "解析中（docling）…")
       return True
   ```

3. `run_task()` 里已有的 `except ParseCancelled` 分支保持原样（幂等 `cancel_task` + 打日志），
   **日志文案要区分两种原因**：`排队期间取消`（新）与 `解析后取消`（原 `before_store` 那条）。
   建议统一成 `[INFO] 解析已取消（<阶段>），未写库：<filename>（<task_id>）`，`flush=True` 保留。

### 判据

| # | 断言 |
|---|---|
| T3-1-a | 单实例下 A 先解析、B 排队 → 在 B 仍显示「排队中」时取消 B → **`logs/sciPal_api.log` 里不出现 `Starting parse pipeline for: <B>`**（这是「真的没解析」的硬证据） |
| T3-1-b | B 终态 `cancelled`；`papers` 无 B 行；`paragraphs` 无 B 段 |
| T3-1-c | 日志出现一条 `[INFO] 解析已取消（排队期间），未写库：<B>` |
| T3-1-d | 对照：A 正常 `completed` 且入库段数 > 0（证明改动没把正常路径弄坏） |
| T3-1-e | **解析期间**取消（A 正在 docling 时取消 A）仍走 `before_store` 分支、仍不落库（老路径不能退化） |

## T3-2（P3）守卫文件不再删除 —— 消掉「放开锁再动文件」的窗口

### 现状

`sciPal_watchdog.py` 的 `launch_guard()` 在 `finally` 里是 `UNLCK → close → unlink()`。
**锁放开之后才删文件**：close 与 unlink 之间若有人抢到锁并通过 `same_file` 校验，
W1 一删路径、W3 造新 inode 再抢一把 → W2/W3 同时 launch。当初删文件只是为了满足「不留残留」这条外观要求。

### 要做的

1. **删掉 `finally` 里的 `unlink()`**（连带 `FileNotFoundError`/`OSError` 那两段）。守卫文件**允许常驻**。
2. 文件内容仍写 `{pid,start,at}`（供 `--status` 排障），但**任何判定都不得读它**。
3. `--status` 输出改为三行可判读：`launch guard: 存在=True/False`、`held=True/False`（`LK_NBLCK` 试抢即放）、
   `content=<...>`。**不要**再把「内容里的 pid 还活着」当成持有判据。
4. 文档里作废旧判据：原「A5 正常退出后守卫文件不存在」**作废**，替换为下面的 T3-2-b。

### 判据

| # | 断言 |
|---|---|
| T3-2-a | `--once` 正常退出后，守卫文件**可以存在**；`--status` 报 `held=False` |
| T3-2-b | **残留不影响**：手工留一个守卫文件（内容随便写个死 pid）→ 再跑一次 `--once`：能正常取得锁并拉起，**监听峰值 1** |
| T3-2-c | **A7 回归三轮**：残留守卫 + 同刻两个 `--once` → 每轮峰值 **1**、已拉起 **1** 条、「守卫被占」**1** 条 |
| T3-2-d | **A8 回归**：W1 持锁期间启动 W2 → W2 `exit 0`、不拉起、守卫文件内容**逐字节不变** |
| T3-2-e | 全程不得出现第二个监听 PID（每轮采样间隔 ≤2 s） |

## T3-3（P2）解析并发上限 —— 超限显式拒绝，不许静默排队

### 现状

`POST /api/papers/parse_async` 每个请求 `threading.Thread(...).start()`，**无上限**。
N 个请求就有 N 个线程全卡在 `_parse_lock` 上，只有 1 个在真解析。前端连点或 MCP 反复提交都会积累。

### 要做的

1. 模块级常量 `PARSE_MAX_CONCURRENT = 3`（带注释说明为何是 3：单实例 + docling 一次只跑一个 + 预留前端一键与 MCP 各一）。
2. **准入检查放在 `create_task()` 之前**，且「检查 + 建任务」包在同一把短锁里（新建 `_parse_admit_lock = threading.Lock()`，
   与 `_parse_lock` 分开，避免和解析互相牵连）：

   ```python
   with _parse_admit_lock:
       running = <SELECT COUNT(*) FROM tasks WHERE type='parse_paper' AND status='running'>
       if running >= PARSE_MAX_CONCURRENT:
           return jsonify({
               "error": f"解析任务已达上限（{PARSE_MAX_CONCURRENT}），请等前面的完成或取消",
               "running": running, "limit": PARSE_MAX_CONCURRENT,
           }), 429
       task_id = task_manager.create_task("parse_paper", params={"filename": filename})
   ```

3. 计数口径写清楚：`type='parse_paper' AND status='running'`（**不含** completed/failed/cancelled）。
4. **同步路由 `POST /api/papers/parse` 不做准入控制**（前端按钮，人点的；加了会让页面莫名报错）。
   在代码注释里写明这是**有意为之**，别让后来人以为是漏了。
5. MCP 侧不动：`_forward._call` 会把 429 原样包成 `ok:false` + `status:429`，工具描述不用改。

### 判据

| # | 断言 |
|---|---|
| T3-3-a | 单实例下连续提交 3 个（不同文件，每个都真会解析）→ 第 4 个立刻返回 **429**，body 含 `running=3`、`limit=3` |
| T3-3-b | 第 4 个**没有建任务行**（`tasks` 里 `parse_paper` 行数只 +3） |
| T3-3-c | 前 3 个里取消 1 个并等它终态后再提交 → 这次能拿到 `task_id`（不能变成永久堵死） |
| T3-3-d | 前 3 个结束后 `SELECT COUNT(*) ... status='running'` == 0；`running_task` 为 `false` |
| T3-3-e | 探针 PDF 与论文行全部清干净，六项计数回基线（565 / 52629 / 373 / 4843 / 239 / fts 50950），`documents` 回到 77 |

> 探针建议用 `documents/` 里**最小的三个** PDF 复制三份（省时间），测完删。别用大文件，一次 3 个并发很吃内存。

## T3-4（P3）`tasks.params` 落库 —— 任务行要能查到是哪个文件

### 现状

`create_task(task_type)` 不接收参数，`params` 列**永远 NULL**。于是「这条解析任务是哪个 PDF」在库里查不到，
清理测试数据只能按 `task_id` 猜。

### 要做的

1. `create_task(self, task_type: str, params: Optional[dict] = None) -> str`：有 `params` 就
   `json.dumps(params, ensure_ascii=False)` 写进 `params` 列；没有就保持 `NULL`（**兼容既有 5 个调用点**）。
2. `parse_async` 调用处传 `params={"filename": filename}`。
3. **其余调用点（qa_ask / agentic_search / generate_outline / generate_review）本单不传**，
   `params` 保持 `NULL` —— 不许顺手扩，避免把工单撑成重构。
4. `get_task()` 的 7 键契约**不变**（`params` 不进返回体，前端/MCP 都别受影响）。

### 判据

| # | 断言 |
|---|---|
| T3-4-a | 提交一个解析任务后：`SELECT params FROM tasks WHERE task_id=?` 是 `{"filename": "<文件>"}` 的合法 JSON |
| T3-4-b | `GET /api/review/task/<id>` 返回**仍是 7 个键**（`task_id/task_type/status/progress/result/error/cancelled`），没多出 `params` |
| T3-4-c | 一个 `generate_review` 任务的 `params` 仍是 `NULL`（没被顺手改） |

## T3-5（P3）状态迁移要能判断「改没改成」

### 现状

- `cancel_task()` 已经返回 `bool`（路由靠它给 404）；
- **`complete_task()` 与 `fail_task()` 返回 `None`**，调用方无法区分「真的迁移了」和「任务早已 cancelled，这次 UPDATE 被 `WHERE status='running'` 挡掉」。

### 要做的

`complete_task()` / `fail_task()` 都 `return cursor.rowcount > 0`，docstring 补一句语义
（`False` = 任务已不在 `running`，本次未生效）。**`cancel_task` 保持不变。**

### 判据

| # | 断言 |
|---|---|
| T3-5-a | 脚本里直接调：running 任务 `complete_task` → 返回 **True**，且 `get_task().status == 'completed'` |
| T3-5-b | 先 `cancel_task` 再 `complete_task` → 返回 **False**，且 `status` 仍是 **cancelled**、`result` 仍为 `None` |
| T3-5-c | 先 `cancel_task` 再 `fail_task` → 返回 **False**，`status` 仍是 cancelled、`error` 仍为 `None` |
| T3-5-d | 现有路由行为不变：解析成功仍 `completed`、失败仍 `failed`（回归 T-4 的 B 组不重跑，但这一条要从接口层看一次） |

## T3-6（P3）解析入口的入参校验

### 现状

两个解析路由只判了 `".."`/`/`/`\` 和 `pdf_path.exists()`：

- 传目录名 → `exists()` 为真 → 一路到 docling 才炸，报错信息是解析器的，不是「你给错文件了」；
- 传 `foo.txt` → 同样先进解析。

### 要做的（两个路由都要，判据顺序固定）

1. 路径穿越检查（保留）
2. **后缀**：`pdf_path.suffix.lower() != ".pdf"` → `400 {"error": "只支持 .pdf 文件"}` + `filename`
3. **是文件**：`not pdf_path.is_file()` → `404 {"error": "文件不存在或不是普通文件: <name>"}`

### 判据

| # | 断言 |
|---|---|
| T3-6-a | `POST /api/papers/parse` 传 `{"filename": "docs"}`（目录名）→ **404**，error 含「不是普通文件」 |
| T3-6-b | 传 `{"filename": "x.txt"}` → **400**，error 含「只支持 .pdf」 |
| T3-6-c | 传不存在的 `nope.pdf` → **404**（文案不变，前端按 error 展示） |
| T3-6-d | 异步路由 `parse_async` 三条同样成立，且**都不建任务行**（`tasks` 计数不变） |
