## 2. 模块详情

### 2.1 Core / System

```text
routes/core.py
routes/system.py
services/retrieval/
services/graph/
```

职责：

```text
/api/health          健康检查
/api/retrieve        检索调试入口
/api/graph           引用/语义图
/api/communities     社区检测结果
```

改这里通常会影响全局，先看 `services/retrieval`。

```text
  hybrid.py
  ingest.py

  dedup.py
```


## 4. 新增模块的落点

```text
1. routes/<name>.py
   只做 HTTP 解析、权限、错误映射

2. services/<domain>/
   业务逻辑、SQL、外部 API

3. 如果有异步任务
   services/<domain>/task_manager.py
   或复用 services/review/task_manager.py

4. 如果有表
   build_db/<domain>_schema.py
   迁移必须幂等
```

路由注册在 `api_server.py`，不要在新模块里全局改 app。

## 5. 测试落点

```text
tests/test_<module>_routes.py      路由契约
tests/test_<module>_service.py     业务逻辑
tests/test_<module>_pg_writes.py   PG 写路径
```

每个 PR 至少覆盖：

```text
成功路径
一个失败路径
一个权限/隔离路径（如果涉及用户数据）
```

## 6. 数据层速查

```text
PostgreSQL
  papers / paragraphs / sentences / sections
  projects / experiments / runs
  claims / reviews
  watch
  tenancy

SQLite
  FTS5 mirror
  legacy build mirror
  local compatibility

Chroma
  paragraphs
  paragraphs_contextual
  papers
  section_summaries
  figures
  tables
```

写路径原则：

```text
运行时优先 PG
SQLite 只做 FTS / legacy mirror
新增写路径先看 services/papers/pg_writes.py
```

## 7. 最小上手路径

```text
1. 跑 health
2. 跑一个 /api/evidence/search
3. 看 routes/evidence.py -> services/search
4. 再看 tests/test_evidence_routes.py
5. 改一个不涉及写路径的返回字段
6. 跑对应测试
```

不要从 `docs/` 里的 100+ 份实验记录开始读。
