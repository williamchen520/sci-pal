# 段-句双权重重排：实验设计（暂缓实施）

> 日期：2026-11-02  
> 状态：**设计完成，代码未写，暂缓到 PG 纯净化完成后。**  
> 本文只定义实验，不改变生产排序。

## 1. 研究问题

在 paragraph FTS 已经给出强基线的前提下，加入一个**小权重句子信号**，能否提升句子级证据命中，同时不损失论文级排序和 3s SLO？

核心假设：

```text
H1：段落分为主，句子分为辅，可以改善 gold sentence 排名
H2：句子权重足够小，不会显著破坏 paper Recall/MRR/nDCG
H3：只在 paragraph 候选内取句子，延迟可以控制在 3s 内
```

## 2. 不做什么

```text
不做 sentence FTS 独立召回
不做两路全量检索融合
不调 sentence ranking 本身
不改变生产 paragraph FTS
不在 20-query 上反复调 λ
```

## 3. 实验系统

### Baseline

```text
paragraph FTS
production ranking
top_k = 10
candidate depth = 300
```

### 实验组 A：段内 RRF

```text
1. paragraph FTS 取 top K
2. 对每个候选段落，取段内 top1 句子
3. 句子排名只在候选段落内计算
4. 融合：
   score(p) = 3/(60+rank_para) + 1/(60+rank_sent)
```

### 实验组 B：段内线性加权

```text
score(p) = norm(para_score) + λ * norm(sent_score)
λ ∈ {0.1, 0.2, 0.3}
```

归一化必须在**每次查询内**做，不能用跨查询固定尺度。

### 对照组

```text
C1: sentence-only（已有负结果，仅引用，不重跑）
C2: HybridSearch + rerank（已有结果，仅引用）
```

## 4. 变量

| 变量 | 取值 | 说明 |
|---|---|---|
| candidate depth K | 50 / 100 / 300 | 段落候选深度 |
| 融合方式 | RRF / 线性 | 主实验 |
| 句子聚合 | top1 / top2 mean | 段内句子分 |
| λ | 0.1 / 0.2 / 0.3 | 仅线性组 |
| RRF 权重 | 3:1 / 5:1 | 仅 RRF 组 |

不要一次全网格；先固定：

```text
K=100
聚合=top1
RRF=3:1
```

再单独做 λ 和 K 的敏感性。

## 6. 评估指标

### 主指标

```text
paper Recall@10
paper MRR
paper nDCG@10
gold sentence top10
p95 latency
```

### 护栏

```text
paper Recall@10 不得低于 baseline
MRR 不得低于 baseline
nDCG 不得低于 baseline
p95 <= 3s
```

### 记录

```text
per-query 明细
失败 query 列表
候选深度与命中位置
```

## 7. 通过门槛

只有全部满足才进入 canary 讨论：

```text
Recall@10      >= 1.0000
MRR            >= 0.8806
nDCG@10        >= 0.9097
gold sentence  >= 13/20（优于 baseline 12/20）
p95            <= 3s
holdout 不出现方向性反转
```

否则：

```text
停止该方向
不调参救结果
不切生产
```

## 8. 延迟测量

```text
warm run: 3 次，取第 2/3 次
cold run: 单独记录，不混入 p95
p50/p95 按 query 统计
句子查询只允许发生在候选段内
```

如果句子查询需要全量索引：

```text
直接判定不可行
```

## 9. 失败条件

```text
paper 指标下降
gold sentence 没提升
p95 > 3s
只有 dev 提升、holdout 不提升
提升来自 query 泄漏或 gold 泄漏
```

任一成立：

```text
记录负结果，停止
```
