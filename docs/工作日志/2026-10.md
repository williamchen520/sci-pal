### 任务：QAService 接入 RAGValidator 防幻觉校验（V33.14）

**背景**：
- `docs/接口明细.md` 写"QA 用 NLI 防幻觉校验"，但 `services/qa/qa_service.py` 实际**没有调用任何校验**

   - 注释更新：支持 `[T1]/[P02]/[F3]/[C04]/[R7]/[G6]`

2. `services/qa/qa_service.py`
   - 顶部新增 import：`from services.ai.rag_validator import RAGValidator`
   - `__init__` 末尾新增：`self.validator = RAGValidator(coverage_threshold=0.8)`
   - Step 3 之后新增 Step 3.5：从 envelope 文本正则提取 `required_item_ids` → validate → 失败重试一次（仅追加 user_prompt，system_prompt 不变）
   - result 新增字段 `"validation": validation_info`

**测试结果**：
- ✅ `python -m py_compile services/ai/rag_validator.py` OK
- ✅ `python -m py_compile services/qa/qa_service.py` OK
- ✅ self_check.py 检查 1-6 通过（6.5 失败为 pre-existing 编码问题，与本次无关）
- ⏳ 端到端验证待用户在 Windows 上 git pull 后跑实际问答测试

**遗留问题**：
- 防幻觉不是真 NLI，是引用 ID 覆盖率校验 → 阈值可按需调（当前 0.8）
- 如果想引入真 NLI 模型（如 DeBERTa-NLI），需独立写 NLIValidator，不复用 RAGValidator

### 任务：修复 /api/retrieve 接口 500 错误

**问题**：前端搜索报错 `'UnifiedRetriever' object has no attribute 'search_papers'`，后端日志显示 `/api/retrieve` 返回 500。

**原因**：V31.61 时把 `/api/retrieve` 接口里的调用从 `retriever.retrieve()` 改成了 `retriever.search_papers()`，但 `get_retriever()` 返回的是 `UnifiedRetriever` 对象，它只有 `retrieve()` 方法。`search_papers()` 是 `HybridRetriever` 的方法，用于 `/api/search/hybrid` 接口。

**改动文件**：
- `api_server.py` — 第210-215行，改回 `retriever.retrieve(query=q, paper_id=..., top_paragraphs=..., top_figures=..., filters=...)`

**测试结果**：语法检查通过，已推送 Gitee（提交 `26580af`）。

**遗留问题**：用户需在 Windows 上 `git pull` 并重启服务验证。
