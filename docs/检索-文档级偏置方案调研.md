# 文档级偏置与冗余：社区方案调研

> Date: 2026-11-01  
> Trigger: 20-query audit 显示 paper Recall@10 = 1.0，但 gold sentence top10 只有 9/20；HybridSearch top10 平均只有 4.45 篇不同论文。

## 1. 结论先行

```text
论文/项目不会把“同一文档多段命中”当成优点。
工业界通常做三件事：
1. 先按文档去重/限流，再算指标
2. 文档级与句子/证据级分别评估
3. 用 MMR / per-document cap / 分层检索控制冗余
```

我们的问题不是独有 bug，而是**passage-level retrieval 的已知评估偏差**。

## 2. 评估层：先把“文档”和“证据”分开

### 2.1 文档级指标

```text
Recall@10 (paper)
MRR (paper)
nDCG@10 (paper)
unique_papers@10
max_hits_per_paper
```

### 2.2 证据级指标

```text
gold_sentence_recall@10
gold_quote_match
answer_contained@10
```

参考 ReQA 的 answer retrieval 评估思路：最终目标是“答案句/答案片段被召回”，不是“文档出现”。

- [ReQA: An Evaluation for End-to-End Answer Retrieval Models](https://scholar.google.ca/citations?view_op=view_citation&hl=th&user=PbgcS6AAAAAJ&citation_for_view=PbgcS6AAAAAJ:_kcjbZDykSQC)

### 2.3 评估工具

- `ir_measures`：标准 IR 指标，支持 TREC 风格 qrels
- `pytrec_eval`：TREC eval 的 Python 绑定
- `ranx`：ranking / fusion / reranking + 指标

参考：

- [ir_measures guide](https://raw.githubusercontent.com/ai-engineering-curriculum/rag-engineer-learning/refs/heads/main/lessons/mod-109-retrieval-quality-evaluation/03-core-retrieval-metrics-with-ir-measures.md)
- [ir_measures GitHub](https://github.com/terrierteam/ir_measures)
- [pytrec_eval GitHub](https://github.com/cvangysel/pytrec_eval)
- [ranx GitHub](https://github.com/AmenRa/ranx)

## 3. 检索层：控制单文档占位

### 3.1 Per-document cap

在 RRF / rerank 之前或之后限制：

```text
max_per_doc = 1 或 2
```

优点：

```text
简单
可直接对比 raw vs capped
能显著提高 unique_papers@10
```

风险：

```text
可能丢掉同一论文中真正互补的证据
```

### 3.2 MMR / 多样性重排

MMR 在相关性与多样性之间折中：

```text
score = λ * relevance - (1-λ) * max_similarity_to_selected
```

适合：

```text
同一论文多段高度相似
同一主题多个近似段落
```

### 3.3 分层检索

```text
paper-level recall
→ section-level
→ paragraph/sentence-level
```

先保证文档覆盖，再在文档内选证据。  
这比“句子级 RRF 后强行去重”更符合证据检索。

### 3.4 RRF 的文档归一化

当前 RRF 是 paragraph/sentence 级投票：

```text
一篇论文有 118 个候选段
另一篇只有 1 个
→ 前者天然占优
```

可在融合前做：

```text
每篇论文最多保留 N 个候选
或对每篇论文的 RRF 票数做归一化
```

## 4. 论文与开源实践

### 4.1 RAG 中的 chunk redundancy

“Reducing Redundancy in Retrieval-Augmented Generation through Chunk Filtering” 直接讨论 chunk 冗余对 RAG 的影响，并给出过滤思路。

- [Chunk filtering paper](https://ar5iv.labs.arxiv.org/html/2604.24334)

### 4.2 句子级证据整合

SAKI-RAG 使用 sentence-level attention 处理长文档上下文碎片化。

- [SAKI-RAG](https://aclanthology.org/2025.emnlp-main.63.pdf)

### 4.3 相关性与多样性

“Finding the Right Balance: Relevance and Diversity in LLM Retrieval” 讨论 relevance 与 diversity 的权衡。

- [Relevance and Diversity](https://export.arxiv.org/pdf/2610.09412)

### 4.4 多阶段检索评估

MST-R 讨论多阶段检索系统与指标评估，强调不能只看单阶段分数。

- [MST-R](https://arxiv-org.ezproxy.obspm.fr/html/2412.10313v1#3)

### 4.5 通用检索评测

BEIR / MTEB 是文档级检索评测；它们同样需要 qrels 去重和文档级聚合。

- [BEIR](https://github.com/beir-cellar/beir)
- [MTEB](https://github.com/embeddings-benchmark/mteb)

## 5. 对 SciPal 的直接建议

### 第一步：评测改造

```text
1. 保留 paper-level 指标
2. 新增 gold_sentence_recall@10
3. 新增 unique_papers@10
4. 新增 max_hits_per_paper
5. 所有指标先按 paper/sentence 去重
```

### 第二步：检索改造

```text
1. 加 max_per_doc = 2
2. 对比 raw vs capped
3. 如果 cap 伤害证据覆盖，改用 MMR
4. 再考虑 paper → section → sentence 分层
```

### 第三步：工具选择

```text
短期：现有 SQLite FTS + 自定义指标 + ir_measures 校验
中期：ranx 做 RRF/capped 对比
长期：Elasticsearch/OpenSearch 或 Vespa 做 BM25 + 多阶段排序
```
