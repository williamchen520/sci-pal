## 2. AGPL 的关键义务

### 2.1 分发（§4–§6）

- 分发源码或二进制时，必须附带许可证与版权声明；
- 分发修改版时，必须标明修改内容与日期；
- 分发二进制时，必须提供对应的完整源码（Corresponding Source）。

### 2.2 网络服务（§13）

如果**修改后的 SciPal** 通过计算机网络供用户交互（SaaS、内网服务、API 平台），
必须向这些用户提供获取对应源码的方式，例如：

- 页脚/关于页放 “Source” 链接；
- API 响应或文档中给出源码地址；
- 提供可下载的源码归档。

> 未修改地运行官方代码不触发额外源码提供义务，但仍受 AGPL 其他条款约束。

### 2.3 不得附加限制

- 不得对 AGPL 授予的权利再收费或附加限制；
- 衍生作品整体继续使用 AGPL。

## 4. Gitee 上怎么设置

1. 推送根目录 `LICENSE` 后，Gitee 通常会自动识别为 `AGPL-3.0`；
2. 若未显示：仓库 → **设置 → 基本信息 → 开源许可证**，选择 `AGPL-3.0`；
3. 仓库需为**公开**，许可证徽章才会展示；
4. README 已加许可证说明，Gitee 仓库页会显示 “AGPL-3.0”。

## 6. 常见问题

**Q：内部使用也要开源吗？**
A：AGPL 的源码提供义务主要针对“向他人分发”和“网络交互”。纯内部、不对外提供网络服务，通常不触发 §13；对外提供服务则需提供源码。

**Q：能闭源商用吗？**
A：AGPL 不允许闭源分发；闭源商用需替换 AGPL 依赖（如 PyMuPDF 商业许可）并取得各依赖的商用授权，或与版权方另行协商。

**Q：可以用 AGPL-3.0-or-later 吗？**
A：可以。本仓库当前选择 `AGPL-3.0-only`；若希望允许未来版本，把 README/包元数据改为 `AGPL-3.0-or-later` 即可，LICENSE 文本不变。
