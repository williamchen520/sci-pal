# 系统综述工作流

> 代码：`build_db/review_schema.py`、`services/review/systematic.py`、`routes/systematic_review.py`
> 测试：`tests/test_systematic_review.py`

## 1. 表

```sql
review_projects(project_id, owner, name, field_text, pico_json, created_at)
review_project_papers(project_id, paper_id, added_at)
screening_decisions(id, project_id, paper_id, stage, decision, reason, reviewer, created_at)
evidence_rows(id, project_id, paper_id, design, sample_size,
              intervention, comparator, outcomes, effect, source_sentence, created_at)
```

## 2. API

```

GET  /api/review-projects/<id>/prisma     PRISMA 计数
POST /api/review-projects/<id>/pico       自动抽取 PICO
GET  /api/review-projects/<id>/kappa      双人筛选一致性
GET  /api/review-projects/<id>/conflicts  筛选冲突
POST /api/review-projects/<id>/adjudicate 冲突裁决
GET/POST /api/review-projects/<id>/members 成员
GET  /api/review-projects/<id>/events   审计事件
GET/POST /api/review-projects/<id>/webhooks  Webhook
GET  /api/review-projects/<id>/export.json  JSON 备份
POST /api/review-projects/import         JSON 恢复
POST /api/review-projects/<id>/evidence   自动抽取证据表
GET  /api/review-projects/<id>/evidence.csv
GET  /api/review-projects/<id>/brief        一页纸 Markdown 简报
GET  /api/review-projects/<id>/report.html  独立 HTML 报告（含图）
GET  /api/review-projects/<id>/report.pdf   PDF 报告
GET  /api/review-projects/<id>/report.docx  Word 报告
GET  /api/review-projects/<id>/prisma.svg    PRISMA 流程图（SVG）
GET/POST /api/review-projects/<id>/risk-of-bias  风险偏倚

POST /api/review-projects/<id>/import-records 按 DOI/标题导入记录

```

### 示例

```json

  "name": "HCC ICI rechallenge",

  }

```

## 3.1 PICO 自动抽取

```powershell
POST /api/review-projects/<id>/pico
```

规则：

- population：HCC / carcinoma / cancer / patients with…；
- intervention：ICI / anti-PD-1 / 药名（*mab）/ rechallenge；
- comparator：placebo / standard / initial ICI / versus；
- outcome：OS / PFS / ORR / DCR / mortality / toxicity。

只填空字段，不覆盖人工填写。

## 3.2 双人筛选一致性

```powershell
GET /api/review-projects/<id>/kappa
```

- 至少 2 位 reviewer；
- 返回 pairs、agreement、Cohen's kappa；
- 不足 2 人时 kappa=null 并提示。

## 3.3 PRISMA 流程图

```powershell
GET /api/review-projects/<id>/prisma.svg
```

- 识别 → 筛选 → 纳入 → 待定；
- 排除数量单独显示；
- 深色 SVG，可直接嵌入报告。

## 3.4 风险偏倚（RoB 2 简化）

```powershell
POST /api/review-projects/<id>/risk-of-bias   # 自动评估
GET  /api/review-projects/<id>/risk-of-bias   # 查看结果
```

五个域：

- randomization：随机化 / 非随机；
- deviations：盲法 / open-label；
- missing_data：失访、缺失；
- measurement：客观终点 / 主观终点；
- reporting：注册/方案。

judgement：`low` / `some concerns` / `high`；整体取最差。

## 3.5 从 Watch 导入

```powershell
POST /api/review-projects/<id>/from-watch  {"run_id": 12}
```

- 把该次 Watch 入选的论文直接加入综述项目候选池；
- 后续可继续筛选、抽证据、评估偏倚。

## 3.6 一页纸简报

```powershell
GET /api/review-projects/<id>/brief
```

输出 Markdown：

- 项目与 PICO；
- PRISMA 计数；
- 证据表；
- 风险偏倚 overall；
- 可直接贴进周报/开题材料。

## 3.7 HTML 报告

```powershell
GET /api/review-projects/<id>/report.html
```

- 独立 HTML（内嵌 CSS），可直接打印/另存 PDF；
- 含 PICO、PRISMA、证据表；
- PRISMA 流程图 + RoB 分域堆叠图（SVG）。

## 3.8 PDF 报告

```powershell
GET /api/review-projects/<id>/report.pdf
```

- ReportLab 生成，内置 `STSong-Light` 中文字体；
- 含 PICO、PRISMA 表、证据表、RoB；
- 无需 LibreOffice。

## 3.9 筛选冲突

```powershell
GET /api/review-projects/<id>/conflicts
```

- 按“论文 + reviewer”取最新一次决定；
- 同一论文出现不同决定即列为冲突；
- PRISMA 也只统计每篇论文的最新决定，重复筛选不会重复计数。

## 3.10 冲突裁决

```powershell
POST /api/review-projects/<id>/adjudicate
{"paper_id": "p1", "decision": "include", "reason": "third reviewer"}
```

- 裁决结果优先于 screening；
- PRISMA 使用裁决后的最终决定；
- conflicts 返回 `resolved` 与 `adjudicated` 字段。

## 3.11 成员权限

```powershell
POST /api/review-projects/<id>/members
{"member": "bob", "role": "reviewer"}
```

- owner 可添加成员；
- 成员可查看/筛选/抽证据/导出，但不能添加成员；
- `list_projects` 返回 owner + 共享项目；
- 角色目前只区分 owner / member，后续细化 reviewer/viewer。

## 3.12 审计事件

```powershell
GET /api/review-projects/<id>/events
```

记录：

- project_created / project_imported；
- papers_added / watch_imported；
- screened / adjudicated；
- evidence_extracted / risk_of_bias / pico_extracted；
- member_added。

用于多人协作追溯。

## 3.13 备份与恢复

```powershell
GET  /api/review-projects/<id>/export.json
POST /api/review-projects/import   # body = 上面导出的 JSON
```

- 导出项目、PICO、论文、筛选、裁决、证据、RoB、成员、事件；
- 恢复时生成新项目 ID，不覆盖原项目；
- 可用于迁移/归档/换机。

## 3.14 外部记录导入

```powershell
POST /api/review-projects/<id>/import-records
{"records": [{"doi": "10.1/a"}, {"title": "Trial B"}]}
```

- 先按 DOI 精确匹配，再按标题（小写精确）匹配；
- 返回 matched / unmatched / paper_ids；
- unmatched 可人工处理，不会报错。

## 3.15 文件导入

```powershell
curl -F "file=@records.bib" http://127.0.0.1:5000/api/review-projects/<id>/import-file
```

- 支持 BibTeX（`.bib` / `.bibtex`）与 CSV/TSV（列名 `title` / `doi`）；
- 最大 5MB；
- 解析后复用 DOI/标题匹配逻辑；
- 返回 parsed / matched / unmatched。

## 3.16 Webhook 通知

```powershell
POST /api/review-projects/<id>/webhooks
{"url": "https://example.test/hook", "events": "screened,adjudicated"}
```

- `events` 支持 `*` 或逗号分隔；
- 审计事件写入后异步 POST JSON：
  `{"project_id","event","data":{"actor","target","detail"}}`；
- 可选 `secret`，放在 `X-SciPal-Secret` 头；
- 失败静默，不影响主流程。

## 3.8.1 Word 报告

`powershell
GET /api/review-projects/<id>/report.docx
`

- python-docx 生成；
- 含 PICO、PRISMA 表、证据表、RoB；
- 可直接编辑/投稿模板。

## 4. 证据抽取规则

- design：randomized / cohort / case-control / single-arm / review；
- sample_size：`(\d+) patients|participants|subjects`；
- intervention / comparator：来自项目 PICO；
- outcomes：摘要中含 outcome/endpoint/response/survival 的句子；
- effect：`HR/OR/RR` 或百分比。

## 5. 实测

```
project rev_98f53a7629
add 1 paper → screen include
prisma: identified=1, included=1, pending=0
evidence: 1 行
csv: paper_id,design,sample_size,intervention,comparator,outcomes,effect
```

## 6. 限制

- PICO 需人工填写（未自动从主题抽取）；
- 摘要缺失时证据表质量差；
- 证据句可能是作者列表/页眉（PDF 摘要解析噪声）；
- 未实现双人筛选一致性、风险偏倚、GRADE。
