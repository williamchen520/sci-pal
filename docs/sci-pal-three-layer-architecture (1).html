🏗️ Sci-Pal 三层链路架构图

🔧 支撑链路（可调试、可进化、可维护）
决定长期能否越用越准
1 检索可观测性 缺失
记录每次检索的：query、扩展词、各路召回结果（向量/BM25/实体）、重排前后排名变化、最终入选证据来源。方便定位是"召回不到"还是"重排排错"。
（待实现：retrieval_observability.py）
2 评审与迭代 已实现
review_section 5维评分（相关性30%+证据支撑30%+逻辑20%+写作10%+无臆测10%），低于60分触发feedback重生成（最多1次）。
review_generator.py (_review_section)
3 用户反馈闭环 缺失
用户修改生成结果时记录 original vs edited，用于后续微调 reranker、prompt，甚至做 DPO/RLHF。让系统越用越准。
（待实现：user_feedback.py + user_feedback 表）
4 错误处理与重试 部分
API 失败、解析失败、模型超时的 retry / fallback / dead_letter_queue。在线搜索已有3次重试，下载已有失败重试，其他模块需补充。
online_search.py (3次重试) / online_downloader.py (失败重试)
5 日志与监控 部分
每个模块的输入输出、耗时、成功率记录。目前有 print 日志，缺少结构化日志和监控面板。
（print 日志已有，结构化日志待实现）

🦴 核心链路（决定可信不可信）
少一块，科研级就不成立
①数据源→ ②数据存储→ ③检索→ ④证据处理→ ⑤生成→ ⑥引用验证→ ⑦增量更新
① 数据源层 已实现

下载脚本：download_pubmed_abstracts.py / download_pmc_xml.py / batch_download_pmc.py / download_openalex.py
增量同步：断点续传已有，last_sync 时间戳待补充
download_*.py (8个脚本)
② 数据存储层 已实现
论文元数据：SQLite (research.db / abstracts.db)
句子级结构索引：sentences 表 + paragraph_index
向量库：ChromaDB (chroma/ + chroma_abstracts/)，HNSW索引，768维

research.db / abstracts.db / chroma/ / documents_xml/
③ 检索层 已实现
统一检索器：unified_retriever.py（7步流水线）

重排：Cross-Encoder Reranker (bge-reranker-base)
去重：MMR多样性选择 + 三级去重(PMCID/PMID/DOI)
unified_retriever.py / hybrid_search.py / reranker.py / mmr_diversifier.py
④ 证据处理层 部分

置信度：待补充（来源类型+匹配方式+重排分数综合）

📊 三层链路总结

🦴 核心链路 = 骨架
7个模块，少一块科研级就不成立。你已实现大部分，缺：EvidenceCard去重/置信度、证据不足fallback、句子关系判定、版本管理
🔧 支撑链路 = 神经系统
5个模块，决定长期能否越用越准。你已实现评审迭代，缺：检索可观测性、用户反馈闭环、结构化日志监控
🎨 体验链路 = 皮肤
4个模块，决定用户爱不爱用。你已有基础前端，可后置，不影响核心可信度
🎯 当前优先级
P0：EvidenceCard去重+置信度、证据不足fallback
P1：检索可观测性、句子关系判定
P2：用户反馈闭环、版本管理
一句话：核心链路决定你能不能叫科研级；支撑链路决定你能不能长期科研级；体验链路决定用户爱不爱用。
