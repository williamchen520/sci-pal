## 零、背景事实（已现查核实，**直接采信**）

### 0.1 `papers.filename` 不唯一 —— 同一文件两条代码路径给出矛盾答案

```text
paper_PMC12707946_2d3bcc67        | PMC12707946.pdf | 224 段 | parse_engine=NULL   | created 2026-09-27 15:52
paper_PMC12707946_2d3bcc67_mineru | PMC12707946.pdf |   0 段 | parse_engine=mineru | created 2026-09-27 18:42
```

`papers` 表**没有** `filename` 唯一约束（索引只有 `idx_papers_doi` / `idx_papers_title`）。
凡是 `WHERE filename = ?` 后直接 `.fetchone()` 的地方，取到哪条取决于物理行序。当前实测：

| 位置 | 取值方式 | 实际拿到 |
|---|---|---|
| 异步快路径 `api_server.py:1808-1811` | `fetchone()` 无 ORDER BY | 224 段（碰巧是 rowid 在前的行） |
| **同步路由 `api_server.py:1685-1688`** | 同一句 SQL | 同上 |
| `/api/papers/local`（`api_server.py:1221-1230`） | `parsed_map[filename] = ...` **后写覆盖** | **0 段**（`_mineru` 行在后） |

→ 模型通过 `list_local_papers` 看到的是 `paragraph_count: 0`，而快路径回 224。
**同一份数据、三条路径、两个答案**，这不是"运气"，是没定义"哪条才算数"。

⚠️ 只修异步那处等于只修一半，**同步路由与 `/api/papers/local` 必须一起修**。

### 0.2 `_parse_lock` 只锁了异步路径

```text
api_server.py:1754   _parse_lock = threading.Lock()        ← 注释明确写着「两个解析并发 = 双份内存 + 抢 CPU」
api_server.py:1825   if not _parse_lock.acquire(blocking=False): ...   ← 只有 async 用
api_server.py:1717   orchestrator = ParserOrchestrator()   ← 同步路由直接跑，不取锁
```

→ 前端点「解析」+ MCP 提交解析 = 两个 docling 同时跑，锁的目的完全落空。

### 0.3 取消对已进入 docling 的任务无效，而且取消后**仍然写库**

```text
api_server.py:1830   if task_manager.is_cancelled(task_id): ...   ← 拿锁后、解析前，唯一一次检查
                     orchestrator.parse_paper(...)                ← 几分钟，全程无感知
                     insert_paper(...)                            ← 没有任何二次检查
                     task_manager.complete_task(...)              ← WHERE status='running' 静默失效
```

实测语义：用户看到 `cancelled`，**库里多了一篇论文**，任务表里没有任何痕迹。
另外三个异步端点（`qa_ask` / `agentic_search` / `generate_review`）的 docstring 都写了取消限制，
`parse_paper` 一个字没写（`api_server.py:1775-1779`）。

### 0.4 `/api/papers/local` 目录缺失时 `200 + error`

```text
api_server.py:1198  if not DOCUMENTS_DIR.exists(): return jsonify({"papers": [], "error": "documents directory not found"}), 200
```

`_forward._call` 按 2xx 包成 `{"ok": true, "status": 200, "data": {...}}` →
`list_local_papers` 判 `ok=True` → 返回 `total: 0`。
→ **"documents 目录不存在" 在 MCP 侧彻底不可见**，模型会答"本地没有 PDF"。

### 0.5 `list_local_papers` 的 limit 只有下限没有上限

```text
mcp_server/search_server.py:212   cap = max(1, int(limit))
```

工具描述写的是"避免 70+ 篇全量灌进上下文"，传 `limit=10000` 就绕过 ——
上下文预算正是这条工具存在的理由，必须在服务端硬钳。

## 一、任务

### T2-1（必须）统一"取哪条 paper"的口径

在 `api_server.py` 里加一个模块级 helper（解析同步/异步两个路由都改用它）：

```python
def _find_parsed_paper(filename: str):
    """按 filename 取「最有效」的一条已解析记录；没有返回 None。

    为什么不是裸 fetchone()：papers.filename 无唯一约束，同一文件可能存在
    `<id>` 与 `<id>_mineru` 两行（后者 total_paragraphs=0）。
    口径：段落数多者优先；并列时取创建更早的（原始入库那条）。
    """
    # SELECT paper_id, title, total_paragraphs FROM papers WHERE filename = ?
    # ORDER BY total_paragraphs DESC, created_at ASC LIMIT 1
```

要求：

1. 同步路由 `:1685-1688` 与异步快路径 `:1808-1811` 都换成它；
2. `/api/papers/local` 的 `parsed_map` 也按同一口径（同一 filename 取 `total_paragraphs` 最大那条，
   并列取 `created_at` 最早），**不许**再用"后写覆盖"；
3. **不动数据**：不删 `_mineru` 空壳行（那是数据操作，另议）。只在注释里写明"空壳行存在，故需口径"。

### T2-2（必须）锁下沉 —— 两个解析入口共用同一把锁

把"解析 + 写库"抽成一个内部函数（例如 `_parse_and_store(pdf_path) -> dict`，返回
`{paper_id, title, paragraph_count, stats}`），内部：

```python
with _parse_lock:          # 两路由共用；同步路由排队是预期行为，不要改成非阻塞
    ...orchestrator.parse_paper...; ...insert_paper...
```

同步路由与异步 `run_task` 都调用它，**不许**在别处再 `acquire()` 同一把锁（会自锁）。
异步路径的"排队中"提示要保留（非阻塞试抢一次 → 打 progress → 再阻塞抢）。

### T2-3（必须）取消语义补全 + 如实写进 docstring

1. 在 `insert_paper` **之前**再查一次 `is_cancelled`：已取消 → **不写库**、`cancel_task(task_id)`、直接返回；
   这样"用户取消后库里多一篇论文"这一条直接消失；
2. docstring 如实写清：**docling 期间无法中断**；取消只在「解析前」「写库前」两个点生效；
   若已过写库点，数据会保留，任务状态可能仍是 `completed`；
3. 若写库已发生而 `complete_task` 因状态条件失效：至少打一行 `[WARN]`（能拿到 rowcount 更好，
   但 `complete_task` 目前无返回值 —— 若无返回值就不许为此改 `services/**`，用 `is_cancelled`
   预判即可）。

### T2-4（必须）`list_local_papers` 的 limit 硬钳

```python
cap = max(1, min(int(limit), 50))
```

工具描述里同步写「上限 50」。返回值里 `truncated` / `note` 保持现状口径。

### T2-5（必须）目录缺失不许伪装成"0 篇"

`list_local_papers` 在 `payload.get("data", {}).get("error")` 非空时，返回：

```json
{"ok": false, "error": "documents directory not found", "hint": "检查 DOCUMENTS_DIR 是否存在"}
```

而不是 `total: 0`。

> **Flask 侧不改状态码**（`:1198` 保持 200）：前端也在用这个路由，改 4xx 可能让页面报错。
> 只在 MCP 侧如实上报。请在报告里确认你**没有**改 Flask 的返回码。
