# 讨论记录：文献监控与自动入库（含代码）

> 日期：2026-11-14  
> 编号：讨论 05  
> 状态：已形成结论  
> 关联：watch、ImportSession、XML/HTML/PDF、CodeRAG、联邦

---

## 1. 问题

文献监控系统是否也可以自动入库，包括代码？

具体场景：

```text
监控发现一篇论文
  有 JATS XML        -> 解析入库
  或 OA 网页          -> 解析入库
  或 PDF              -> 解析入库
  有代码链接          -> 分流到 CodeRAG 入库

人类也可以：
  指定网页 URL
  上传 XML / PDF
  指定 GitHub / Zenodo
  上传代码 zip
  -> 同样解析入库
```

---

## 2. 结论

```text
可以。
但监控系统只负责“发现和触发”。
真正入库必须走统一 ImportSession。
自动入库 = 自动进入草稿/审查，不等于自动发布。
```

---

## 3. 两条 lane

```text
Watch
  -> 发现候选
  -> 去重
  -> 获取全文
  -> ImportSession
       paper lane
       code lane
  -> 审查
  -> 发布
  -> 联邦注册
```

### paper lane

```text
JATS XML   -> xml_library
HTML       -> html_library
PDF        -> pdf_library
```

### code lane

```text
GitHub / GitLab / Zenodo / supplementary
  -> code_library
  -> snapshot
  -> parser
  -> index
```

两边用 `paper_id` 关联，但不合并库。

---

## 4. 自动监控流程

```text
watch profile
  -> scheduled query
  -> candidate list
  -> dedupe by DOI / PMCID / hash
  -> acquire
       full text
       code link
  -> ImportSession(origin=watch)
  -> Detect
  -> Route
  -> Parse
  -> Review
  -> Build
  -> Index
  -> Publish
```

### 全文来源

```text
PMC JATS XML
publisher OA HTML
authorized PDF
```

不能绕过付费墙。

### 代码来源

```text
Code availability
Data availability
GitHub / GitLab
Zenodo DOI
supplementary zip
```

---

## 5. 自动入库边界

默认策略：

```text
auto_stage = true
auto_publish = false
```

流程：

```text
自动发现
自动下载
自动解析
自动建草稿
自动跑质量审查
  -> 人工批准发布
```

只有可信租户/可信来源才允许：

```text
auto_publish = true
```

否则监控系统会变成污染库的入口。

---

## 6. 人工导入走同一条管线

人类可以：

```text
指定网页 URL
上传 XML
上传 PDF
指定 DOI
指定 GitHub / Zenodo
上传代码 zip
```

统一调用：

```json
POST /api/imports
{
  "origin": "manual",
  "tenant_id": "...",
  "library_id": "...",
  "items": [
    {"kind": "auto", "uri": "..."},
    {"kind": "auto", "uri": "..."}
  ]
}
```

Detector 判断：

```text
JATS XML
HTML
PDF
Python
R / Rmd
git repo
zip
```

人工和自动的差别只有：

```text
origin = watch | manual | api
```

不应该有两套导入逻辑。

---

## 7. 代码的特殊处理

### 自动发现

```text
从全文 extraction：
  GitHub URL
  Zenodo DOI
  Code availability
  supplementary
```

### 入库前检查

```text
仓库可达
license
语言
文件数
是否已有 snapshot
是否与 paper 已绑定
```

### 解析

```text
只静态解析
不执行代码
不安装依赖
不跑测试
```

### 关联

```text
paper_id
  -> paper_code_links
  -> code_library
  -> snapshot
```

如果只有代码没有论文：

```text
先入 standalone code_library
以后发现论文再 bind
```

## 8. 数据模型建议

```text
watch_runs
watch_candidates

import_sessions
  import_id
  origin          watch | manual | api
  tenant_id
  status
  created_by

import_items
  import_id
  item_id
  kind            paper | code | supplementary
  source_kind     jats | html | pdf | repo | zip
  source_uri
  status

paper_code_links
  paper_id
  code_library_id
  snapshot_id
```

论文和代码分别有状态：

```text
paper: parsed / reviewed / published
code:  fetched / parsed / indexed / bound
```

允许：

```text
论文成功，代码失败
代码成功，论文失败
```

不能因为代码失败阻塞论文入库。

---

## 9. 当前差距

### 已有

```text
watch_profiles / watch_run
paper_code_links
code_rag ingest
HTML parser
JATS/PDF native
```

### 缺

```text
watch 只到摘要/元数据，没有全文获取
没有统一 ImportSession
没有 paper lane / code lane 分流
没有自动 code acquisition
没有 auto_stage / auto_publish 策略
没有租户导入队列和配额
```

结论：

```text
架构上可以
当前需要把 watch 接到 ImportSession
```

---

## 10. 分期

```text
W0  人工导入 API（paper + code）
W1  ImportSession + detector + router
W2  watch candidate -> ImportSession
W3  fulltext acquisition（XML/HTML/PDF）
W4  code acquisition + binding
W5  review gate / auto_publish policy
W6  租户配额、队列、审计
```

---

## 11. 风险

```text
付费墙 / 许可
代码 license
重复导入
错误 code link
代码执行安全
存储和模型成本
自动发布污染库
```

### 原则

```text
只自动获取授权/开放内容
代码只解析不执行
自动入库默认进草稿
代码与论文解耦状态
所有来源保留 provenance
```

---

## 12. 一句话

```text
文献监控可以自动入库，
但它只是触发器；
真正的入库由统一 ImportSession 完成：
  文献走 XML/HTML/PDF lane
  代码走 code lane
  人工和自动共用同一条管线
  自动阶段默认不自动发布
```
