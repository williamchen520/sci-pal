## 6. 关键决策

### 6.1 0.72 vs 0.75 分歧

迁移过程中，PG 早期 Recall@10 约 0.72，Chroma 约 0.75，曾据此认为 PG 不足。

后续用配对置信区间和 SciFact 300 复核：

```text
SciFact 300 Recall@10   0.8669 vs 0.8669
SciFact 300 nDCG@10     0.7458 vs 0.7470
配对 nDCG CI            [-0.0063, 0.0029]
```

结论：

```text
0.72 vs 0.75 主要是 20 题小样本波动
不构成 PG 显著劣于 Chroma 的证据
```

教训：

```text
先定非劣门槛，再跑实验
```

### 6.2 Chroma 不做回滚

```text
主架构保持 PG-only
Chroma 归档到 I:\_archive\chroma-20261107
辅助 figure/table/chunk/abstract 向量检索暂时下线
```

原则：

```text
SciPal 主架构不变
外部能力即插即用，用完可去
```

### 6.3 research.db 归档

```text
原库 -> I:\_archive\research.db-20261107
SHA256 校验一致
生产不挂载、不创建
```

### 6.4 DOI 重复组软去重

```text
8 组同一 DOI 的两种解析
保留两版
标 papers.duplicate_of
检索排除重复
0 行删除
```

## 9. 三项延期工作的可解性判断

| 工作 | 能否顺利解决 | 前置条件 | 建议 |
|---|---|---|---|
| 300 题全文金标 | 可以，但成本高 | 公开全文集 + 标注规范 | 先找公开集，不自建 |
| GraphRAG / RAPTOR | 可以作为插件做 | 图质量、评测集、独立开关 | 不进入主架构 |
| 客户端入库追踪 | 可以，属产品流程 | 批次、标记、复核 UI | 与后端清洗解耦 |
