# 工作计划：SciPal 优化路线（2026-10）

> 依据：2026-10-28 讨论的六个方向。
> 原则：先有评测，再谈优化；每个任务可验收、可回滚、可进 PR。
> 假设：1 名全职开发；周期按“人日”估算，可按人力并行压缩。

## 0. 基线

| 项 | 当前值 |
|---|---|
| 论文 | 3,297（XML 3,214 / PDF 83） |
| 句子 | 862,114 |
| 章节 | 69,097（path/depth 已物化） |
| 引用位置 | 182,758（91.5% 有句级链接） |
| 图表链接 | 图 11,696 / 表 4,702 |
| 测试 | 492 项，约 20s |
| 已有能力 | 混合检索、证据包、verify、Watch、数据沙箱、DSH/MCP、多用户 owner |

主要缺口：

1. 没有检索/生成质量评测；
2. 检索以段落向量为主，缺层次摘要与图社区；
3. 无 claim–evidence 图、引用意图、撤稿标记；
4. 无系统综述工作流（PICO/筛选/证据表/PRISMA）；
5. 任务在内存、迁移手工、可观测性弱；
6. 论文正文属于不可信输入，prompt injection 防护不足。

## 1. 总路线

```
M1（1–3 周）：评测 + 可信度快赢
M2（4–6 周）：claim/evidence + 引用意图 + 层次检索
M3（7–9 周）：系统综述工作流 + 导出
M4（10–12 周）：工程硬化 + 外部基准
```

优先级：**评测 → 可信度 → 检索增强 → 工作流 → 工程**。

## 2. 工作流一：评测与回归（P0）

### 2.1 目标

建立可重复的检索/生成质量指标，任何检索或提示改动都能被量化。

### 2.2 任务

| ID | 任务 | 产出 | 人日 |
|---|---|---|---|
| E1 | 金标准集 150 题 | `eval/gold/*.jsonl` | 4 |
| E2 | 检索指标脚本 | `eval/retrieval_eval.py`：Recall@k、MRR、nDCG | 2 |
| E3 | 生成指标脚本 | `eval/answer_eval.py`：引用准确率、claim 支持率、拒答率 | 3 |
| E4 | 回归门禁 | GitHub Actions 跑 20 题子集 | 1 |
| E5 | 结果看板 | `eval/results/*.json` + 趋势表 | 1 |

### 2.3 金标准格式

```json
{
  "id": "q001",
  "question": "肝癌免疫再挑战的疗效如何？",
  "paper_ids": ["paper_PMC..."],
  "evidence": ["paper_..._sent_012", "paper_..._sent_015"],
  "answer_points": ["ORR 约 30%", "需限定肝功能"],
  "must_cite": ["P1"],
  "forbidden": ["所有患者均有效"]
}
```

### 2.4 验收

- 150 题覆盖：事实、对比、冲突、拒答、图表；
- 基线记录：Recall@10、MRR、citation precision、claim support；
- CI 中 20 题子集：指标下降 >2% 即失败；
- 文档：`docs/评测说明.md`。

### 2.5 风险

- 金标准主观 → 双人标注 20% 抽检；
- 测试数据版权 → 只存 ID 与短引用。

## 3. 工作流二：证据与可信度（P1）

### 3.1 目标

让“结论—证据—原文”可查询，能标记撤稿/更正/引用意图，并抵御论文内的 prompt injection。

### 3.2 任务

| ID | 任务 | 产出 | 人日 |
|---|---|---|---|
| T1 | claim–evidence 表 | `claims`、`claim_evidence` + 迁移 | 3 |
| T2 | claim 抽取 | `build_db/extract_claims.py`（规则 + 3B 模型） | 3 |
| T3 | 引用意图 | `sentence_links.relation` 扩展 support/contrast/mention | 2 |
| T4 | 撤稿/更正 | `paper_flags` + Crossref/Retraction Watch 查询 | 2 |
| T5 | injection 防护 | 证据分隔、指令隔离、工具白名单、测试集 | 2 |
| T6 | 检索提示 | 撤稿论文降权并在答案中提示 | 1 |

### 3.3 表结构

```sql
claims(claim_id, paper_id, sentence_id, claim_text, claim_type, created_at)
claim_evidence(claim_id, evidence_sentence_id, relation, confidence)
paper_flags(paper_id, flag_type, source, detail, checked_at)
```

### 3.4 验收

- 新导入论文自动查撤稿标记（失败不阻塞入库）；
- `verify_answer` 对撤稿证据给出 warning；
- 20 条 injection 样例全部不改变工具调用；
- claim 支持率在金标准上 ≥0.8。

## 4. 工作流三：检索与上下文（P1）

### 4.1 目标

在现有段落检索上增加“层次摘要 + 图社区”，提升综述型/多跳问题的召回。

### 4.2 任务

| ID | 任务 | 产出 | 人日 |
|---|---|---|---|
| R1 | 章节摘要 | `summaries` 表 + `build_db/build_summaries.py` | 3 |
| R2 | 摘要向量 | Chroma `summaries` collection | 1 |
| R3 | 摘要通道 | `UnifiedRetriever` 增加 summary 召回 + 下钻 | 2 |
| R4 | Contextual Retrieval | 段落前置“标题+章节路径”后重嵌入 | 2 |
| R5 | 图社区 | `communities`、`community_members` + 摘要 | 3 |
| R6 | 评测对比 | 在 E1 上对比 Recall/nDCG | 1 |

### 4.3 验收

- Recall@10 相对基线 +5%，或 nDCG +3%；
- p95 延迟增加 ≤20%；
- 摘要节点可追溯到 section_id 与原文段落。

### 4.4 风险

- 重嵌入成本高 → 先在 500 篇子集验证；
- 摘要幻觉 → 摘要只用于召回，不直接作为证据。

## 5. 工作流四：领域工作流（P2）

### 5.1 目标

从“问答/综述”走到“系统综述流水线”，形成科研场景差异化。

### 5.2 任务

| ID | 任务 | 产出 | 人日 |
|---|---|---|---|
| W1 | PICO 抽取 | `services/review/pico.py` + 表 | 3 |
| W2 | 纳入/排除筛选 | `screening_decisions` + API | 3 |
| W3 | 证据表 | `evidence_tables` + CSV/DOCX 导出 | 3 |
| W4 | PRISMA 计数 | 流程计数 API + 图 | 1 |
| W5 | 引用导出 | BibTeX/RIS、Zotero 兼容 | 2 |
| W6 | 端到端演练 | 20 篇小样本 demo | 2 |

### 5.3 验收

- 输入一个主题，产出：PICO、筛选列表、证据表、PRISMA 计数；
- 证据表字段：研究设计、样本量、干预、对照、结局、效应量、来源句；
- 导出文件可被 Zotero 导入；
- 全流程有审计与人工修正入口。

### 6.2 任务

| ID | 任务 | 产出 | 人日 |

| O3 | 可观测性 | 请求耗时、慢查询、`/api/metrics` | 2 |
| O4 | CI | GitHub Actions：492 测试 + eval 子集 + lint | 2 |
| O5 | 安全 | 速率限制、依赖审计、secret scan | 1 |
| O6 | 备份/恢复 | 脚本 + 文档 + 演练 | 1 |

### 6.3 验收

- 空库执行迁移可建全表；
- CI 在 PR 上必须绿；
- 关键路径 p95 耗时有面板。

## 8. 里程碑与退出标准

| 里程碑 | 时间 | 退出标准 |
|---|---|---|
| M1 评测 + 可信度快赢 | 第 1–3 周 | 150 题金标准、CI 回归、撤稿标记、injection 测试 |
| M2 claim/意图 + 层次检索 | 第 4–6 周 | claim 表、支持率 ≥0.8、Recall@10 +5% |

## 10. 风险登记

| 风险 | 影响 | 缓解 |
|---|---|---|
| 重嵌入成本高 | 进度/GPU | 500 篇子集先行 |
| LLM 成本上升 | 预算 | 小模型预处理 + 缓存 |
| 评测集主观 | 结论偏差 | 双人标注 + 抽检 |
| 论文版权/许可 | 合规 | 只存 ID/短引用，遵守 AGPL 与来源条款 |
| prompt injection | 安全 | 工具白名单 + 输出过滤 + 审计 |
| 范围蔓延 | 延期 | 每个里程碑只做表内任务 |

## 11. 协作与交付

- 所有改动走 `DSH-dev → GitHub PR → dev`；
- 每个 PR 必须：492 测试通过 + 相关 eval 子集 + 文档更新；
- 新增可选项写入 `docs/可选项与用户配置.md`；
- 每完成一个任务在 `docs/变更日志.md` 记一行；
- 合并后运行 `scripts/push_all.ps1` 镜像到 Gitee。

## 12. 第一批立即开工（建议）

1. E1 金标准 30 题（先小后大）；
2. E2/E3 脚本骨架；
3. T4 撤稿标记（外部数据源可先 mock）；
4. T5 injection 测试集 20 条。

这四项 1 周内可看到结果，且不阻塞后续。
