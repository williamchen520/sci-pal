每章节内部流程（V32.5 三大升级）：
📝 生成阶段（_write_section）
a
章节类型感知：判断 Intro/Methods/Results/Discussion/Conclusion → 不同写作风格指导 🆕
b
渐进式上下文注入：传入 previous_sections_summary（前文摘要，最多800字）→ 避免重复 🆕
c
证据-声明矩阵：先列3-5个核心要点，每个要点映射证据ID，再基于有证据支撑的要点写正文 🆕
d
llm_client → Ollama qwen2.5:7b 生成章节正文（200-400词）
🔄 评审修订阶段（_review_section）🆕
e
5维评分标准：相关性30% + 证据支撑30% + 连贯逻辑20% + 学术写作10% + 无无依据推测10%
f
LLM 当评审专家，打分 + 列出问题 + 修改建议
g
分数 < 60 → 把评审建议作为 feedback 注入 prompt，重新生成（最多重试1次）
h
分数 ≥ 60 → 通过，进入下一章节
4

→

5
_auto_cite_sentences()
→

→

🎯 架构核心设计原则总结

1. 数据层与检索层解耦：只更新数据库/向量库，检索层和主程序代码一行都不用改，新数据自动被覆盖。
2. 大纲先行 + 大纲引导检索：用户完全掌控大纲结构，每章节用自己的关键词搜索，确保内容跟标题相关。
3. 证据-声明矩阵：每个声明必须有证据支撑，杜绝 LLM 凭空编内容，所有引用可追溯到原文。
4. 迭代精炼 + 评分引导：生成后自动评审打分，不达标就修订，确保输出质量。
5. 全本地部署：Embedding + Reranker + LLM 全部本地运行，数据不出本机，无 API 费用。
6. 不用多智能体架构：有精确数据库不需要推理协商，用确定性流程 + 评分标准更可控、更高效。
