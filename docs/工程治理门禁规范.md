# 工程治理门禁规范

> 日期：2026-11-12  
> 状态：v1，外部预检，不进入 Flask 主程序  
> 目标：高风险改动先停、先说清、再等人批准

---

## 1. 评审结论

专家建议的核心是对的：

```text
高风险改动不能“想到就改”
必须先说明、等人批准
```

但不能照字面做成“思维链自审”：

```text
LLM 自判“我是否触发规则”不可靠
迟早会漏判或自我豁免
```

所以落地方式改成：

```text
确定性预检（路径 / 操作 / 行数）
  + 人类批准
  + 可审计记录
```

门禁不放进 `api_server.py`，不改核心请求路径。

---

## 2. 六个触发指令

配置文件：

```text
config/governance_gates.json
```

| ID | 名称 | 触发 | 为什么 |
|---|---|---|---|
| `contract_lock` | 契约锁定 | `routes/`、`deploy/sql/`、`ARCHITECTURE.json`、`contracts/`、插件迁移 | API/表/JSON 契约变更 |
| `physical_moat` | 物理护城河 | `services/db/`、`services/tenancy/`、`deploy/.env`、compose；`dsn` / `cross_db` / `isolation` | 可能串库、误连、破坏隔离 |
| `slice_execution` | 切片执行 | 变更 >300 行，或 `refactor` | 一次改太大，审查失真 |
| `anti_corruption_audit` | 防腐审计 | `merge_core` / `core_pr` | 核心逻辑合并前必须审计 |
| `orthogonal_control` | 正交控制 | `eval/` + `confirmatory_experiment` / `eval_param` | 确认性实验和评测参数不能边跑边改 |
| `dimensional_adaptation` | 降维适配 | `hard_cut_500w` / `runtime_splice` | 500 词硬切或运行时接骨，可能改变数据语义 |

## 3. 不触发门禁的操作

```text
读文件
查日志
跑只读探针
改 docs/
改 tests/（除非同时改核心逻辑）
格式化
```

原则：

```text
只读不拦
文档不拦
测试不拦
高风险写操作才拦
```

---

## 4. 执行方式

### 命令行预检

```powershell
python scripts/governance_gate.py `
  --paths services/db/pg_pool.py deploy/.env `
  --ops dsn isolation `
  --plan "切换 DSN 校验" `
  --risk "可能误连 core/rebuild"
```

命中后退出码：

```text
2 = 拦截，等待批准
0 = 放行
```

### 输出

```text
⚠️【拦截警告】当前任务触发了 [物理护城河] 规则。
📝【计划简述】切换 DSN 校验
⚠️【风险提示】可能误连 core/rebuild
⏳ 请人类审查并回复“批准执行”以继续。
```

### 人类批准

只用一句话：

```text
批准执行
```

批准后：

```text
记录批准人、时间、改动范围
再执行
```

没有“批准执行”，不得改代码。

---

## 5. 为什么不是“思维链拦截”

```text
Think 里的自审是软约束
模型可以漏掉、误判、或自我说服
```

门禁必须依赖：

```text
确定的路径
确定的操作标签
确定的 diff 行数
退 2 的退出码
```

LLM 可以提出“我要改什么”，但不能自己决定“不需要批准”。

---

## 6. 为什么不是 300 行硬红线

300 行只作为**辅助信号**，不是唯一标准。

真正决定风险的是：

```text
是否改契约
是否改 DSN / 隔离
是否改核心合并路径
是否改确认性实验参数
```

一个 20 行的 DSN 改动，比 500 行文档更危险。

---

## 7. 与主程序的关系

```text
不 import api_server
不改 Flask 请求路径
不拦截生产流量
只做开发/CI 预检
```

可以接入：

```text
PR 模板
pre-commit（可选）
CI 脚本
agent 的任务前置检查
```

但不要把它写成运行时中间件。

## 9. 局限

```text
门禁不是安全沙箱
agent 仍可能绕过脚本直接改文件
真正的强制力来自人类审查和 CI
```

所以：

```text
关键 PR 必须附 gate 输出
CI 必须跑 gate
人类批准必须留痕
```

## 11. CI 接入

工作流：

```text
.github/workflows/governance-gate.yml
```

流程：

```text
checkout PR base commit
fetch PR head
用 base 分支的 scripts/governance_ci.py 跑门禁
按 PR diff 取 changed paths
```

关键设计：

```text
不用 PR 里修改过的 gate 脚本判断 PR
避免“改门禁绕过门禁”
```

命中后：

```text
exit 2
CI 失败
PR 加 governance-approved 标签后重跑
```

标签不是技术豁免，是“人类已经批准”的可见记录。

### 本地预检

```powershell
python scripts/governance_gate.py `
  --paths services/db/pg_pool.py `
  --ops dsn `
  --plan "切换 DSN" `
  --risk "可能串库"
```

### CI 限制

```text
CI 只能自动判断路径触发
--ops（如 confirmatory_experiment）仍需 PR 作者显式运行本地 gate
PR 标签由有权限的人添加
```

所以 CI 不是万能；它防的是“路径级明显高危改动被静默合并”。

```text
门禁不 import api_server
不进入 Flask 请求链
不改变生产行为
只在开发/CI 前置检查
```

主程序稳健性来自：

```text

```
