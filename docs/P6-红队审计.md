# P6 红队安全审计与防御计划（v2）

> 日期：2026-11-11  
> 对象：Flask API / MCP / PostgreSQL core+corpus / 备份 / Docker  
> 结论：**P6 不通过。存在 2 个 P0、4 个 P1。**

---

## 1. 执行摘要

当前数据层已经完成物理隔离：

```text
core    -> scipal_core
corpus  -> scipal_rebuild
auth    -> scipal_core.auth
```

但安全边界没有跟上：

```text
API 不是统一鉴权
内部 ingest/embed 端点可达
应用持有过高数据库权限
备份明文
无 TLS / 无速率限制
```

这类问题不是“以后优化”，是上线阻断项。

---

## 2. 发现清单

### P0-1 未认证的 `/api/ingest`

证据：

```http
POST /api/ingest {}
-> 400 （不是 401）
```

代码：

```text
routes/ingest.py
  没有 session 校验
  没有 token 校验
  直接 get_service().start(...)
```

影响：

```text
任意人可提交下载/入库任务
可指定大量 PMC ID
可触发下载、解析、embedding、磁盘写入
```

这是资源耗尽 + 数据污染入口。

### P0-2 未认证的 `/api/embed`

证据：

```http
POST /api/embed {}
-> 503 （当前 embed_rows 未注入）
```

代码：

```text
routes/ingest.py
  embed_rows 一旦注入，直接执行
  无认证
```

影响：

```text
攻击者可提交 256 行/次的 embedding
占满 GPU/CPU
把任意文本写入向量索引
```

当前 503 是“未启用”，不是“已防护”。

### P1-1 应用使用高权限数据库账号

```text
SCIPAL_CORE_DSN
SCIPAL_PG_DSN
SCIPAL_AUTH_DSN
  -> scipal_admin
```

影响：

```text
应用被攻破 = 可改 auth / 删表 / 改业务
违反最小权限
```

必须拆：

```text
core_app      只读写业务表
auth_app      只读写 auth 表
corpus_reader 只读语料
corpus_writer 只写 ingest 表
```

### P1-2 无登录速率限制

```text
/api/auth/login
```

没有：

```text
IP 限速
用户锁定
失败计数
验证码/延迟
```

scrypt 只提高单次成本，不阻止分布式撞库。

### P1-3 备份明文

```text
backups/pg/core-*.dump     4 MB
backups/pg/corpus-*.dump   1.1 GB
```

core dump 含：

```text
password_hash
email
membership
```

没有：

```text
加密
600 权限
独立备份账号
```

### P1-4 MCP / API 没有统一 token

```text
SCIPAL_API_TOKEN 未配置
mcp_server/_forward.py 只在有 token 时附加 Authorization
```

影响：

```text
MCP 和匿名 HTTP 客户端同权
本机任意进程可调用 API
```

### P2-1 HTTP 无 TLS

Caddyfile：

```text
:80 {
  reverse_proxy app:5000
}
```

### P2-2 `/api/abstracts` 未登录 200

```text
GET /api/abstracts/list?page_size=1 -> 200
```

如果摘要库包含非公开数据，这是数据泄露。

### P2-3 无请求体/任务上限

```text
/api/ingest pmc_ids 长度未限制
/top_k 虽然钳制，但任务参数未限
```

### P2-4 无 SQL statement_timeout

连接池只设 `pool timeout`，没有：

```text
statement_timeout
idle_in_transaction_session_timeout
```

慢查询会拖垮连接池。

### P2-5 备份磁盘增长

corpus 1.1 GB/份，保留 28 天：

```text
最坏 ~31 GB
```

没有磁盘水位告警。

### P2-6 备份恢复未完成

core 恢复通过；corpus 全量恢复因吞吐中止。

## 3. 防御计划

### Phase 0（阻断上线）

```text
1. /api/ingest、/api/embed 强制内部 token
2. 全局 API 鉴权中间件：
   public allowlist: health / login / evidence? / abstracts?
   其他要求 session 或 bearer
3. MCP 配 SCIPAL_API_TOKEN
4. 失败关闭：token 未配置时拒绝内部端点
```

### Phase 1（一周内）

```text
1. 数据库最小权限角色
2. 轮换所有 DSN 密码
3. 登录限速 + 失败锁定
4. 备份加密 + chmod 600
5. 备份独立账号/主机
```

### Phase 2（架构加固）

```text
1. TLS + HSTS
2. CSRF token（session POST）
3. 请求体大小限制
4. statement_timeout / idle timeout
5. 磁盘水位告警
6. corpus 恢复演练定期化
```

## 4. 验收用例

```text
POST /api/ingest 无 token -> 401/403
POST /api/embed 无 token -> 401/403
GET /api/papers 无 session -> 401
GET /api/abstracts 无 session -> 401（或明确 public）
登录连续失败 10 次 -> 429
备份文件权限 -> 600
core dump -> 无法直接读取 password_hash
```

---

## 5. 结论

```text
数据隔离通过
安全审计不通过
```

P6 不能签收；先做 Phase 0。
