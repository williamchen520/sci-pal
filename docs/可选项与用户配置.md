## 1. DSH 会话模板（✅ 已落地）

### 现状

- `packages/dsh-scipal/cordis.patch.yml` 已加入 `scipal-data` MCP server；
- 三套 workspace 模板：
  - `D:\sciPal\dsh_workspaces\raw\AGENTS.md`
  - `D:\sciPal\dsh_workspaces\public\AGENTS.md`
  - `D:\sciPal\dsh_workspaces\mixed\AGENTS.md`
- 重启后应有 **35 个 `mcp__` 工具**（1 + 10 + 9 + 3 + 12）。

### 使用者需要做的

1. **完全退出 DSH** 再启动（不是只关窗口），让 bundle 重新加载；
2. 新建 workspace，路径分别指向上面三个目录；
3. 模型选择：
   - raw → 本地 `qwen2.5:3b`
   - public / mixed → 云端大模型；
4. 打开会话后先调 `open_session` / `data_classify` 验证。

### 可调整项

| 项 | 位置 | 说明 |
|---|---|---|
| 模板内容 | `dsh_workspaces/*/AGENTS.md` | 直接编辑，下一次会话生效 |
| 工具集合 | `packages/dsh-scipal/cordis.patch.yml` | 增删 MCP server；改后需重启 DSH |
| 本地模型名 | DSH 模型选择器 / `SCIPAL_ORCHESTRATOR_MODEL` | 默认 `qwen2.5:3b` |
| 是否启用 raw 模板 | workspace 是否打开 | 不打开即不使用 |

> 注意：DSH 没有“会话模板”独立配置项，workspace + `AGENTS.md` 是它的原生机制；
> 真正的隔离仍由 SciPal 的 `cloud_gate` 与工具集合保证。

## 2. 云端 provider 白名单（⚙️ 可配置）

### 现状

- 默认：`deepseek,openai`
- 位置：SciPal 环境变量 `SCIPAL_CLOUD_PROVIDERS`
- 生效点：`cloud-gate`，不在名单内直接拒绝并写审计。

### 调整方式

```powershell
$env:SCIPAL_CLOUD_PROVIDERS = "deepseek,openai,anthropic"
```

- 逗号分隔，大小写不敏感；
- 改完需重启 Flask；
- 审计里会记录 `provider` 与拒绝原因。

### 适用场景

- 新增云厂商；
- 临时禁用某个 provider；
- 只允许私有部署的 OpenAI 兼容网关（把网关名加进去）。

## 3. Watch 定时任务观察（⏳ 待观察）

### 当前配置

- DSH 定时任务：每 3 天调用 `watch_run(profile_id=1)`；
- 首次触发：2026-10-31 07:02（北京时间）；
- 空跑 30 天才会发“本月无新增”心跳。

### 需要观察的指标

| 指标 | 关注点 |
|---|---|
| `found` | 期刊/关键词是否召回过多或过少 |
| `selected` | 是否稳定在 1–5 篇 |
| `imported_full` | JATS/Unpaywall 全文比例 |
| 同刊分布 | 是否被单一期刊占满 |
| 简报质量 | 摘要是否够用、理由是否准确 |
| 重复率 | 下一轮是否重复推送 |

### 可调整项

| 项 | 位置 | 建议 |
|---|---|---|
| 间隔 | `watch_profiles.interval_days` | 默认 3 天 |
| 每次篇数 | `max_items` | 1–5，默认 3 |
| 同刊上限 | `same_journal_limit` | 默认 2 |
| 期刊范围 | `watch_profile_journals` / 自动发现 | 用 ISSN 精确锁定 |
| 指标 | `metric_type` / `metric_min` | SJR 或 OpenAlex |
| 心跳 | `last_push_at` / 心跳逻辑 | 30 天 |
| 定时任务 | DSH schedule prompt | 改 `profile_id` 或间隔 |

### 观察后的动作

- 召回太少：加关键词/放宽期刊；
- 噪声太多：收紧 `metric_min` 或加排除 ISSN；
- 全文比例低：检查 Unpaywall 邮箱与 Europe PMC 覆盖；
- 简报太长：减少 `max_items` 或缩短摘要。

## 5. 以后新增可选项的写法

新增条目请按下面模板追加到本文件：

```markdown
## N. <名称>（✅/⚙️/⏳）

- 现状：
- 为什么是可选项：
- 默认值：
- 调整方式（命令/文件/界面）：
- 影响范围：
- 回滚方式：
```

原则：

1. **能默认就不打扰用户**；必须调整的才放这里；
2. 涉及安全/数据出境的选项，必须写清默认值与影响；
3. 每项都要有“回滚方式”；
4. 代码里对应的环境变量或字段名要写出来，方便检索。
