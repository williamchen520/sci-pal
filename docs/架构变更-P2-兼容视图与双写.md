# 架构变更授权：P2 兼容视图与双写

> 日期：2026-11-08  
> 状态：**待人类批准修改**  
> 规则：`.dsh_rules` 规则 0A  
> 前置：P1 已合并（10,094 works / 10,081 documents / 10,088 mappings）

---

## 1. 问题

P1 只回填了历史数据；新入库仍只写 `public` 表。

证据：

```text
public.papers            10,102（历史）
catalog.works            10,094（历史）
library_main.documents   10,081（历史）
```

新入库一次后：

```text
public.papers             +1
catalog.works             不变
library_main.documents    不变
```

后果：

```text
新论文没有 work/document
P3 联邦检索看不到新论文
P5 租户库无法挂接新入库
```

---

## 2. 变更

改哪一层：

```text
接口契约 + 写入路径
```

新增：

```text
services/papers/library_identity.py
  ensure_work(paper_row)
  ensure_document(paper_row, source_path)
  link_paper(paper_id, document_id)
```

调用点：

```text
build_db/db_writer.py::insert_paper
build_db/import_jats.py 的 XML 入库路径
```

新增兼容视图：

```text
library_main.v_documents
library_main.v_works
```

说明：

```text
P2 只双写 work/document/paper_documents
不双写 source_nodes
不迁移现有树
```

`source_nodes` 仍在 P3 处理。

---

## 3. 理由

```text
先保证“新论文有身份”
再做“新论文有树”
最后做“联邦检索”
```

如果 P2 直接双写整棵树：

```text
解析器差异会在写入时放大
失败会影响主入库
回滚困难
```

P2 只写轻量身份层，风险最低。

---

## 4. 影响

影响模块：

```text
build_db/db_writer.py
build_db/import_jats.py
services/papers/
```

数据：

```text
新入库 +1 paper
-> +1 catalog.works（如新）
-> +1 library_main.documents
-> +1 library_main.paper_documents
```

兼容性：

```text
public 表仍是主读路径
API 不改
检索不改
双写失败不得回滚 public 写入
```

风险：

```text
双写失败会产生“有 paper 无 document”
需要补偿任务/日志
```

---

## 5. 迁移

步骤：

```text
1. 新增 library_identity 辅助模块
2. 在 public 写成功后调用
3. 幂等 upsert
4. 失败只记录，不回滚 public
5. 每日补偿扫描缺失 document 的 paper
```

回滚：

```text
删除双写调用
不回滚 public
新表数据可保留或按 paper_id 删除
```
