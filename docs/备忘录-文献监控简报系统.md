## 3. 监控 vs QA

| 维度 | 监控简报 | QA |
|---|---|---|
| 目标 | 不漏 + 新颖 | 准确 + 引用 |
| 策略 | recall / novelty 优先 | precision / 拒答优先 |
| 输出 | 定期摘要列表 | 单问题回答 |
| 评价 | 覆盖率、相关性、反馈 | coverage、citation、refusal |

两者共享领域画像、证据、引用，但**不能直接复用 QA 的拒答策略**。

## 4. 建议架构

```
新论文入库
→ 自动领域标签
→ 与 monitor profile 匹配
→ 去重 / 新颖性判断
→ 评分排序
→ 生成简报
→ 推送 / 展示
→ 反馈更新 profile
```

### 数据模型（草稿）

```sql
monitor_profiles(
  profile_id, user_id, name,
  keywords, domain_weights,
  frequency, language, created_at
)

monitor_items(
  item_id, profile_id, paper_id,
  score, reason, status, created_at
)

monitor_feedback(
  item_id, action, note, created_at
)
```

### 简报内容
- 标题 / 期刊 / 日期；
- 1–3 句摘要；
- 为什么相关；
- 领域/主题；
- DOI/原文链接；
- 可选“建议精读”。

## 5. MVP 范围

1. 只监控本地库新增；
2. 每日/每周一次；
3. 按 profile 关键词 + 领域匹配；
4. 规则 + embedding 排序；
5. 云端生成摘要；
6. Web 展示，先不做邮件；
7. 记录打开/忽略反馈。

## 6. 待定问题

1. 监控频率：每日 / 每周？
2. 来源：本地库新增 / PubMed / arXiv？
3. 推送：Web / 邮件 / 文件？
4. 用户兴趣：关键词 / 领域 / 种子论文？
5. 简报语言：中文 / 英文 / 双语？
6. 是否需要“负反馈”抑制相似论文？
7. 去重口径：DOI / 标题 / 摘要相似度？

## 7. 风险

- 新论文领域标签不准；
- 关键词匹配噪声大；
- 简报摘要幻觉；
- 反馈稀疏；
- 推送过多导致忽略；
- 跨领域兴趣难以建模。
