# 数据树形结构迁移审计

> 日期：2026-11-01  
> 范围：SQLite `data/research.db` vs PostgreSQL `scipal_bench`  
> 问题：多引擎解析的 paper → section → paragraph → sentence → figure/table 树形关系与 Page/BBox 坐标是否在迁移后完整保留。

---

## 1. 结论

```text
文章 → 章节 → 段落 → 句子：保留
Page/BBox 字段：保留，但源数据本身大量为空
Figure/Table → 章节/段落：从未建立，无法追溯
主检索 FTS：仍是段落级，不是句子级
```

因此不能回答“100% 完美保留”。

更准确的说法：

```text
PostgreSQL 迁移没有丢列、没有丢行；
但源 SQLite 本身就有两处结构性缺陷：
1. figures / tables 只绑到 paper_id，没有 section_id / para_id
2. 大量 JATS/XML 论文没有 Page/BBox
```

---

## 2. 文章 → 章节 → 段落 → 句子

### 字段

```text
sections.parent_id      → 上级章节
paragraphs.section_id   → 所属章节
sentences.para_id       → 所属段落
sentences.paper_id      → 所属论文
```

### PostgreSQL 数据

| 表 | 行数 | 关键空值 |
|---|---:|---|
| sections | 69,128 | parent_id 29,198；page/bbox 68,094 |
| paragraphs | 167,388 | section_id 2,758；page/bbox 158,681 |
| sentences | 862,677 | section_id 9,755；page 802,155；bbox 804,029 |

`parent_id` 为空的是顶层章节，不是断链。  
`paragraphs.section_id` / `sentences.section_id` 为空的主要是摘要、参考文献前段落等无章节节点内容。

### 10 篇溯源测试

选取 10 篇同时有 sentence page/bbox 的论文，逐篇验证：

```sql
sentence → paragraph → section → paper
```

结果：

```text
10 / 10 篇有完整链
```

抽查示例：

```text
paper_PMC13612941_ba1df9d6
sentence page 18
bbox 53.60,465.47,297.40,736.97
paragraph → section → parent section → paper
```

### 结论

```text
链路字段和链路数据都在，迁移没有把它拍平。
```

## 3. Figure / Table 绑定

### 现状

`figures` 表：

```text
fig_id, paper_id, fig_number, caption, file_path, page, bbox, number_conflict
```

`tables` 表：

```text
table_id, paper_id, table_number, caption, markdown, page, bbox
```

**没有 section_id，也没有 para_id。**

也就是说：

```text
能知道图属于哪篇论文
不能知道图属于哪一章、哪一段
```

### 数据量

```text
figures 13,471；page/bbox 为空 13,204
tables  4,922；page/bbox 全部为空
```

### 判断

```text
不是 PostgreSQL 迁移丢失；
SQLite 源库就没有这个关系。
```

现有 `xml_figure_links` 只有 `pmc_id + fig_id + context`，没有 section/paragraph 外键，不能直接补成精确树。

### 需要重构

```text
figures 增加 section_id, para_id
tables  增加 section_id, para_id
```

但“100% 精确回填”需要解析器重新输出 figure/table 的 placement，或人工/规则回填；当前源数据不足以保证 100%。

---

## 4. Page / BBox 坐标

### 字段保留

PostgreSQL 与 SQLite 都有：

```text
page
bbox
```

### 覆盖率

```text
sentences：有 page/bbox 的论文只占一部分
figures：13,204 / 13,471 为空
tables：4,922 / 4,922 全部为空
```

原因：

```text
JATS / XML 解析没有 PDF 页码和 BBox
PDF 引擎解析的论文有 page/bbox
```

### 判断

```text
迁移没有把有坐标的行改成空；
空值来自源解析链路。
```

没有坐标的 XML 论文，无法在迁移后凭空生成 PDF 坐标。

## 5. FTS 倒排索引颗粒度

### SQLite

```text
paragraphs_fts  166,465
sentences_fts   862,677
```

`sentences_fts` 是存在的，而且是句子级。

### PostgreSQL

```text
sentences.search_vector 862,677 行已生成
paragraphs.search_vector 167,388 行
```

### 实际检索

`services/search/hybrid_search.py` 的 `fts_search()` 查的是：

```text
paragraphs_fts MATCH ...
```

不是 `sentences_fts`。

### 结论

```text
倒排索引没有丢；
但主检索仍是段落级，不是句子级。
```

用户要求“基于句子重写 FTS”，需要改：

```text
hybrid FTS → sentences.search_vector
```

并处理：

```text
sentence → paragraph 聚合
排序从 bm25 切到 ts_rank
```

---

## 6. 迁移是否丢数据

对比 SQLite / PostgreSQL：

```text
表行数一致
字段一致
空值率一致
P2 核心表逐行校验 0 diff
```

所以：

```text
迁移层面：没有丢行/丢列
结构层面：figures/tables 的 section/paragraph 绑定在源库就不存在
坐标层面：空值来自解析源，不是迁移
FTS 层面：句子索引存在，但主检索未使用
```

## 7. 建议的重构顺序

### 第一步：图表绑定

```text
1. SQLite figures/tables 增加 section_id, para_id
2. PostgreSQL schema 同步
3. 用 JATS placement / PDF page / context 回填
4. 无法回填的行标记 unresolved，不伪造
```

### 第二步：句子级 FTS

```text
1. 新增 sentence-level PG FTS 查询
2. 保留 paragraph 聚合层
3. 用 20 query 对比 sentence vs paragraph
4. 通过后再切
```

### 第三步：10 篇溯源报告

```text
sentence → paragraph → section → paper
+ page/bbox
+ 图表只能到 paper 的，明确标注
```
