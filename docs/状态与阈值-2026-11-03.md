## 4. Audit 阈值设计

### 4.1 现状

`eval/gate.py` 当前只做：

```text
recall@10 / mrr / ndcg@10
允许相对基线下降 tolerance=0.02
```

现有审计：

```text
retrieval_bias_audit.py
hybrid_bias_audit.py
soft_cap_mmr_audit.py
domain_coverage_audit.py
```

主要是**报告**，没有 pass/fail。

### 4.2 三层阈值

#### 第一层：发布硬门槛

```text
Recall@10       >= baseline - 0.02
MRR             >= baseline - 0.02
nDCG@10         >= baseline - 0.02
gold sentence   >= 12/20
p95 latency     <= 3s
refusal         >= 0.95
```

当前 paragraph FTS 基线：

```text
Recall@10   1.0000
MRR         0.8806
nDCG@10     0.9097
gold para   12/20
p95         0.6222s
```

#### 第二层：数据完整性硬门槛

```text
paragraph vector coverage >= 95%
section coverage          >= 95%
paper coverage            >= 90%
contextual coverage       >= 95%
sentence ID text match    = 100%
paragraph/section ID match= 100%
outbox pending            = 0
SQLite/PG drift           = 0
```

这一层应 **fail closed**。

图表覆盖率当前极低，建议先作为**专项告警**，不立即阻断发布：

```text
figures coverage >= 90%   (回填后再启用)
tables  coverage >= 90%   (回填后再启用)
```

#### 第三层：Bias / 多样性告警

```text
unique papers@10   >= 6
max hits per paper <= 3
Gini / entropy     报告，不阻断
```

在人工领域标签完成前，不建议把 bias 指标设成硬阻断。

### 4.3 阈值原则

```text
检索质量：非劣性阈值
数据完整性：零容忍
多样性：先告警，后阻断
小样本：用 holdout，不用单次 20-query 调阈值
```

### 4.4 实施映射

```text
eval/gate.py
  扩展 gold_sentence / p95 / coverage

scripts/retrieval_bias_audit.py
scripts/hybrid_bias_audit.py
scripts/soft_cap_mmr_audit.py
  加 --gate 参数；默认仍只报告

CI
  发布前跑 eval/gate.py + data integrity gate
```
