# 召回架构：10 题 vs 20 题逐题对账

> 日期：2026-11-10  
> 数据：`eval/results/`  
> 结论先行：0.9 不是上下文灌水造成的；20 题下降主要发生在 reranker 之前。

---

## 0. 口径

```text
旧算法
  pg_only_deployed_20.json

新算法（大灌水）
  sentence_window_10_gpu.json / sentence_window_20_gpu.json
  上下文自动选择：段落 <=600 字符给整段，否则 ±2 句

新算法（限字数）
  sentence_window_10_limited.json
  强制所有证据都只给 ±2 句窗口
```

注意：

```text
Hit@10 只看 top10 的 sentence_id
上下文是在 top10 之后才构建的
```

所以上下文长度**不可能**改变 Hit@10。

## 2. 为什么前 10 题是 0.9？

### 2.1 不是 7000 字符上下文造成的

证据一：

```text
大灌水 vs 限字数
  命中集合完全相同
  上下文长度不同
```

证据二：

```text
q008 3,645 字符 命中
q015 21,998 字符 不命中
```

上下文字符数与命中没有单调关系。

证据三（结构上）：

```text
top10 sentence_id 先确定
context 后构建
context_chars 不进入任何打分
```

所以：

```text
0.9 与 7000 字符无关
```

### 2.2 也不是 reranker “恰好排对”

| q002 | ✅ rank14 | 7 | ✅ | ✅ rank2 | 2 |
| q003 | ✅ rank6 | 1 | ✅ | ✅ rank1 | 1 |
| q004 | ✅ rank1 | 2 | ✅ | ✅ rank1 | 1 |

### 2.3 q007 是波动题

第一次 10 题运行：

```text

```


这说明：

```text

```

## 4. 系统到底错在哪？

### 错误 A：池前截断（4 题）

```text
q013, q016, q018, q020
```

共同点：

```text
正确段落已经召回
正确句子也在候选集合
但正确句子没有词法命中
只有段落 prior
```

结果：

```text
0.7 * 0 + 0.3 * prior
分数太低
在 top20 之前被截掉
```

这些题**根本没送到 reranker**。

### 错误 B：向量漏召回（1 题）

```text
q015
```

```text
正确段落不在 top30
正确句子词法排名 95
没有段落 prior
分数不够，未进 top20
```

这是候选生成问题，不是排序问题。

### 错误 C：全部漏掉（1 题）

```text
q009
```

```text
段落未召回
句子词法也没有命中
候选集合里没有正确句子
```

### 不是 reranker 排丢

```text
q011-q019 中进入 rerank 池的 5 题：
  gold final rank = 3, 1, 1, 1, 2
```

```text
reranker 5/5 全中
```

所以：

```text
第 11-20 题的主要错误
不是 reranker 把正确句子排丢
而是正确句子没进 reranker
```

## 5. 0.9 -> 0.65 的分解

前 10 题：

```text
9 hit
1 miss（q009）
```

第 11-20 题：

```text
5 hit
5 miss（q013, q015, q016, q018, q020）
```

合并应为：

```text
14 / 20 = 0.70
```

但 20 题运行实际：

```text
13 / 20 = 0.65
```

差的 1 题是：

```text
q007
```

原因：

```text
q007 的正确段落在 HNSW top30 边界
10 题运行时进了，20 题运行时没进
```

所以：

```text
0.65 不是“题变难了”
0.65 = 前 10 题 9 中
      + 后 10 题 5 中
      - q007 边界波动
      => 13/20
```

## 6. 结论

```text
1. 7000 字符上下文不是 Hit 提升的原因
   上下文在排序之后，且大/小两版命中集合相同

2. 前 10 题 0.9 主要因为：
   q002/q006 比旧算法多命中
   + q007 边界命中
   + reranker 在池内排得准

3. 后 10 题主要错误：
   4 题池前截断
   1 题向量漏召回
   1 题完全漏召回

4. reranker 不是主要错误来源：
   进池的 gold，5/5 都排进 top3
```

## 7. 直接修复方向

优先级最高：

```text
扩大/改写 rerank 候选池
```

具体：

```text
1. 给每个 top 段落保留至少 1-2 个 rerank 名额
   即使该句没有词法命中

2. rerank 池 20 -> 50
   但 GPU 成本要评估

3. 对“无词法命中”的段落，用整段 rerank
   或段落内按位置/标题选句

4. q007 这类边界题：
   paragraph_top_k 30 -> 50
   或 HNSW ef_search 提高
```

不要先调上下文长度。

上下文长度影响的是：

```text
生成成本
答案可读性
```

不是 Hit@10。
