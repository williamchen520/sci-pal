# Retrieval Bias Audit

> Date: 2026-11-01  
> Query set: 20 cases, 5 per source.  
> Data: `data/research.db`.  
> Purpose: separate paper-level success from sentence-level success and per-document duplication.

## Result

```text
cases                              20
gold papers per query               1 (all 20)
queries with multiple gold papers   0
mean unique papers@10              10.0
mean max hits per paper           118.4
gold paper in top10               20 / 20
gold sentence in top10             9 / 20
paragraph FTS paper metrics       1.0000 / 0.8806 / 0.9097
```

Raw:

```text
eval/results/retrieval_bias_audit.json
```

## Interpretation

### 1. Paper-level recall is saturated

Every query has exactly one gold paper. A single matching paragraph in the
paper is enough for paper-level Recall@10.

This is not a duplicate-count bug: the evaluation deduplicates paper IDs. The
problem is **granularity**:

```text
paper correct
≠
the sentence that answers the question was retrieved
```

Only 9/20 queries retrieve the gold sentence in the sentence top10.

### 2. Candidate pools are document-skewed

Mean maximum hits per paper in the 1,000-paragraph candidate pool:

```text
118.4 paragraphs from one paper
```

At the paper level, top10 still contains 10 unique papers because we dedupe.
But the candidate list is dominated by a few papers before deduplication.
That is document-level bias in the retrieval stage.

### 3. Why the 1.0 is misleading

```text
5 seed queries were all the same paper → 1.0/1.0/1.0
20 queries have one gold paper each → Recall@10 is coarse
gold sentence top10 only 9/20 → paper hit overstates answer hit
```

## Required evaluation changes

Report both:

```text
paper_recall@10
gold_sentence_recall@10
unique_papers@10
max_hits_per_paper@k
```

and add a sentence-level gold gate:

```text
gold paper hit AND gold sentence hit
```

## Debiasing options

```text
1. max_per_paper = 1 or 2 before paper aggregation
2. MMR / diversity across papers
3. RRF normalization by document hit count
4. sentence-level gold as the primary metric
5. multi-gold queries; stop using single-paper-only sets as the main benchmark
```

## Decision

```text
Do not use paper-level 1.0000 as evidence that retrieval is solved.
Keep paragraph FTS as production baseline, but report sentence-level recall
and per-document duplication in every future comparison.
```
