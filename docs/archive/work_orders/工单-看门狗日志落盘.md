## 二、任务

### L-1 `log()` 双写：stdout + 文件

- 文件：`LOGS_DIR / "sciPal_watchdog.log"`（绝对路径，由 `PROJECT_ROOT` 派生）。
- 编码 `utf-8`、**追加模式**、行格式与现在完全一致（`[YYYY-MM-DD HH:MM:SS] msg`）。
- **每次写入时 open/close**，不复用长期句柄 —— 理由：日志量极小（见背景 6），
  而长期句柄在进程被强杀时可能丢缓冲；每次 open 追加能保证「写进去的就是盘上的」。
- **写失败绝不能抛、也不能刷屏**：`except Exception` 后向 stderr 提示**一次**（模块级
  `_log_file_broken = True`，之后静默走 stdout），主循环照跑。
  → 磁盘满 / 权限不足 / 目录被删，都不许让管家死掉。
- 允许环境变量覆盖路径 `SCIPAL_WATCHDOG_LOG`（便于验收时指向临时文件，**不参与生产逻辑**）。

### L-2 启动横幅（RUN MARKER）——用来回答「跑的是不是修好的那版」

每次 `run_daemon()` / `run_once()` 启动时，在文件里写一条**分隔线**，至少含：

| 字段 | 为什么 |
|---|---|
| `=== watchdog start ===` 分隔线 | 切分多次运行，一眼看出重启过几次 |
| `pid` | 对上 `--status` 的 lock holder |
| `BASE_URL` / `PROBE_URL` | 端口被改过时立刻可见 |
| Python 版本 + 可执行文件路径 | 排「是不是用了系统 python 而不是 venv」 |
| **脚本自身 `mtime` + `size`（或 sha256 前 12 位）** | 本机踩过：改了 watchog 代码但没重启守护进程，日志里无法分辨跑的是哪版 |
| 上次退出状态 | 从锁文件判断：有锁且持有者已死 → `unclean（疑似异常退出/被强杀）`；无锁 → `clean` |

> 这一条不是装饰：**「改了代码没重启」在本机至少踩过两次**（五-B 的 patch、看门狗的修复），
> 每次都靠比进程 `CreationDate` 才发现。写进日志后自查成本降到零。

### L-3 状态切换日志要带**判据数字**（这是本次最有价值的一条）

现在有几处日志只说明「发生了什么」，不说明「凭什么这么判」，导致事后无法复盘：

| 位置 | 现在 | 改成 |
|---|---|---|
| `:459-461` 端口有人在监听但探针失败 | `端口已有人在监听但探针未通过（可能在冷启动），本轮**不拉起**，继续等` | 追加 **`listening pids=[...]` / `count=N`** |
| `:455` 服务不通 | `服务不通（url）` | 追加 **`listening pids=[...]`**（空列表本身就是证据：真死了 vs 冷启动中） |
| `:392-395` 已拉起 | 有 pid / 日志路径 | 追加 **`listening pids` 拉起后快照**与 `STARTUP_WAIT_TIMEOUT` |
| `:199` 服务已就绪 | 有等待秒数 | 保留，追加 `listening count`（**>1 就说明已经堆积了**，这是关键告警信号） |
| `:202` 等满超时仍未就绪 | 有端口监听状态 | 追加 **`listening pids` + count**；若 count ≥2，单独一行 `⚠️ 检测到多实例监听` |

**判据说明**（写进 docstring）：实例堆积的特征是「多条 `已拉起` 没有对应 `已就绪`」+
「`listening count` > 1」。修复前那晚若早有这些字段，一眼就能看出来，不必数端口。

### L-4 轮转（按大小，标准库实现）

- 阈值 **5 MB**，保留 `sciPal_watchdog.log.1` / `.2` 两个历史文件，超出丢弃最老的。
- 时机：每次写入前检查当前文件大小；超阈值就 `rotate`。
- **轮转失败不许影响运行**：`os.replace` 失败 → 记一条到 stderr，继续写原文件。
- 阈值与保留数写成模块级常量（`LOG_MAX_BYTES` / `LOG_BACKUPS`），便于验收时临时调小验证。

| 7 | `--once` 交互输出 | 终端里仍能看到完整输出（不能因为双写就把 stdout 去掉） |
| 8 | 峰值监听数 | 整个过程 `listening count` **始终 ≤ 1**，且日志里 `⚠️ 检测到多实例监听` **一次都没出现** |
