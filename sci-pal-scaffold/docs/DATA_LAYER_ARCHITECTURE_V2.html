📏 解析粒度设计决策（重要！）

💡 粗粒度索引 + 细粒度存储

Docling 一步切到句子级，存储分两层，索引只建段落级

📊 索引层：段落级（粗）
索引只建段落级！

• 索引小，条数可控
• 查询快，性能好
• 图文关联：段落级就够
• 引用关联：段落级就能定位

查关系走这层！
📦 存储层：段落+句子（细）
存储存到句子级！

• 细节全，随时能查
• 上下文完整
• 精准抽取数值（剂量10mg/kg）
• 精准溯源（点某句跳原句）

抽细节走这层！
落地方式：
段落表（主）：paragraph_id, text, section, subsection
句子表（子）：sentence_id, paragraph_id, text, sequence
索引表：source_id = paragraph_id，target_id = fig_id / ref_id

一句话：查关系走段落，抽细节走句子。

🔍 正反向查询示例

⬆️ 正向查询：正文 → 图表
用户在第040段 → "如图3所示" → 点一下看图3！

SELECT target_id FROM index_table
WHERE source_id = 'paper_001_para_040'
  AND relation_type = 'mentions';

结果：paper_001_fig_3 → 打开图片！
⬇️ 反向查询：图表 → 正文
用户在看图3 → 想看上下文 → 点一下回原文！

SELECT source_id FROM index_table
WHERE target_id = 'paper_001_fig_3'
  AND relation_type = 'mentions';

结果：paper_001_para_040, paper_001_para_041 → 跳回原文！
🔗 跨篇查询：引用 → 被引论文
论文A引用了Smith 2020 → 我们库里有没有这篇？

SELECT cited_paper_id FROM citations
WHERE doi = '10.1038/xxx';

结果：paper_042 → 直接跳转到我们库里的这篇论文！

和词源项目的对比

词源项目：
• 词库小的时候，关系也少
• 词库大了，关系网才密
科研助手：
• 文献少的时候，网络也稀疏
• 文献多了，网络才丰富

同一套逻辑：数据量决定网络密度，网络密度决定系统能力

🎯 我们的策略

先把系统跑通，然后慢慢喂数据。喂得越多，它越聪明！
不要指望两三篇就"网络智能"。那是数据库，不是知识图谱。

🧭 网络方向性设计（重要！）

💡 我们的网络是"关联网络"，不是"方向网络"

方向靠 source/target 表达，靠查询指定，靠时间戳兜底

⭕ 篇内关系：无向
段落 ↔ 图表

正向查：这段提到了哪些图？
→ SELECT target_id ...

反向查：图被哪些段落提到？
→ SELECT source_id ...

方向是查询时自己定的！
✅ 跨篇引用：有向
论文A → 论文B

正向查：A引用了哪些论文？
→ WHERE paper_id = 'paper_A'

反向查：哪些论文引用了B？
→ WHERE cited_paper_id = 'paper_B'

方向在 source/target 里！
⏰ 时间维度：天然方向
时间不可逆！

论文A：2020年发表
论文B：2023年发表

A → B 方向是固定的
不管你怎么查，A都在B之前

时间是唯一不可逆的方向！

和词源项目的对应

词源项目：
• 同义词 → 对称的（无向）
• 上下位词 → 有方向的（有向）
科研助手：
• 提到、引用 → 对称的（无向）
• 时间先后 → 有方向的（有向）
