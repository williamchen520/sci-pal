# 工作计划：从“综述生成”到“论证工作台”

> 版本：v0.1  
> 日期：2026-10-30  
> 适用：SciPal V33.96+  
> 目标：把现有“章-节-句-图-表”文档树，升级为可审计的 claim-evidence 论证基础设施。

---

## 1. 背景与判断

### 1.1 现状

SciPal 已经具备：

- 多用户、workspace、项目、实验、run；
- 混合检索（向量 + FTS + RRF）；
- bge embedding / reranker；
- 证据卡片、引用校验；
- 综述大纲与综述生成；
- DeepSeek 云端 LLM 接入。

但“一键综述”仍然属于：

```text
主题 → 检索 → 大纲 → 扩写 → 引用
```

这条链路产出的是“像论文的文本”，不是“被证据约束过的论证”。

### 1.2 核心判断

> 出版级论文不是“多智能体联合生成的长文本”，而是“一个可辩护的 claim + 支撑它的证据链 + 对反例和边界的处理”。

因此，下一步不应继续优化“一次生成 5000 词”，而应建设：

```text
文档树（证据地址）
    +
claim 图（论证关系）
    +
矛盾检测（反例与异质性）
    +
受约束生成（无证据不写）
```

### 1.3 为什么现在做

现有数据已经具备树形基础：

| 对象 | 数量 |
|---|---:|
| papers | 3,308 |
| sections | 69,128 |
| paragraphs | 167,337 |
| sentences | 862,405 |
| figures | 13,471 |
| tables | 4,922 |
| citations | 182,817 |

覆盖率：

- 3,075 / 3,308 篇论文有 sections；
- 164,630 / 167,337 段落有 `section_id`；
- 715,298 / 862,405 句子有 `char_start/char_end`（约 83%）。

这说明：

1. 树已经可用，但还不完整；
2. 不需要从零重建解析；
3. 应该把树接到 claim 层，而不是再做一套扁平 RAG。

## 2. 目标与非目标

### 2.1 目标

1. 建立“文档节点 → 证据单元 → 原子 claim → 论证关系”的四层结构。
2. 每条 claim 必须能回溯到：
   - paper；
   - section；
   - paragraph；
   - sentence / figure / table；
   - 字符偏移或 bbox。
3. 对每个 claim 支持：
   - 支持证据；
   - 反对证据；
   - 边界条件；
   - 证据质量；
   - 当前状态。
4. 输出矛盾报告，但区分：
   - 真矛盾；
   - 表面矛盾；
   - 异质性；
   - 证据不足。
5. 写作阶段强制：
   - 每个段落绑定 claim；
   - 每个句子绑定证据节点；
   - 无证据句子不允许进入正文。
6. 提供可评估的 benchmark 与人工验收流程。

### 2.2 非目标

本阶段不做：

- 全自动“一键投稿”；
- 自动发明研究贡献；
- 自动替代同行评审；
- 全量论文的完美 claim 图；
- 一开始就上 GraphRAG / 多智能体辩论；
- 对私有数据默认上云。

## 3. 设计原则

### P1：树是地址，不是论证

树回答：

```text
这句话在哪？
```

claim 图回答：

```text
这句话支持什么？反驳什么？
```

两者不能互相替代。

### P2：claim 必须带限定条件

一个 claim 至少包含：

```text
population / intervention / comparator / outcome / unit / scope / time
```

没有限定条件的 claim，不允许进入矛盾判定。

### P3：精确 provenance 是一等公民

每条证据必须满足：

```text
document_text[char_start:char_end] == evidence_text
```

图/表证据必须绑定：

```text
paper_id + fig_id/table_id + caption + page/bbox
```

### P4：矛盾不是“文本相似度低”

矛盾检测要区分：

- 直接否定；
- 数值不一致；
- 人群不同；
- 剂量/干预不同；
- 终点不同；
- 因果 vs 相关；
- 时间范围不同；
- 定义不同。

很多“矛盾”其实是异质性。

### P5：人类在关键节点决策

必须由人确认：

- claim 是否值得提出；
- 矛盾是否真实；
- 证据是否足以支持结论；
- 是否投稿。

### P6：先窄后宽

先做单篇论文内的 claim 锚定与证据关系；  
再做跨论文 claim 对齐；  
最后做全库论证图。

---

## 4. 目标架构

```text
L0 文档树
  paper
   └─ section
       └─ paragraph
           ├─ sentence
           ├─ figure
           └─ table

L1 证据单元
  sentence / figure / table
  + paper_id + section_path + offsets + bbox
  + parse_quality

L2 原子 claim
  canonical_text
  claim_type
  qualifiers
  status
  confidence

L3 论证图
  claim --supports/refutes/assumes/extends--> claim
  claim --supported_by/refuted_by--> evidence_node

L4 写作与审计
  section_plan
  paragraph_plan
  sentence_claim_map
  citation_map
  review_findings
```

## 5. 数据模型

### 5.1 现有表复用

保留：

- `papers`
- `sections`
- `paragraphs`
- `sentences`
- `figures`
- `tables`
- `citations`

不复制 86 万句子到新表。  
新增逻辑映射，按需物化。

### 5.2 新增表

```sql
CREATE TABLE claims (
    claim_id        TEXT PRIMARY KEY,
    workspace_id    TEXT NOT NULL DEFAULT 'ws_default',
    canonical_text  TEXT NOT NULL,
    claim_type      TEXT NOT NULL DEFAULT 'empirical',
    status          TEXT NOT NULL DEFAULT 'proposed',
    confidence      REAL NOT NULL DEFAULT 0.0,
    qualifiers_json TEXT NOT NULL DEFAULT '{}',
    created_by      TEXT,
    created_at      TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at      TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_claims_workspace ON claims(workspace_id, status);
CREATE INDEX idx_claims_type ON claims(claim_type);
```

```sql
CREATE TABLE claim_evidence (
    evidence_id     TEXT PRIMARY KEY,
    claim_id        TEXT NOT NULL,
    paper_id        TEXT NOT NULL,
    node_type       TEXT NOT NULL,   -- sentence | figure | table | paragraph
    node_id         TEXT NOT NULL,
    relation        TEXT NOT NULL,   -- supports | refutes | mentions | underdetermines
    strength        REAL NOT NULL DEFAULT 0.0,
    rationale       TEXT,
    quote           TEXT,
    char_start      INTEGER,
    char_end        INTEGER,
    extractor       TEXT,
    verified_by     TEXT,
    created_at      TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(claim_id, node_type, node_id, relation)
);

CREATE INDEX idx_claim_evidence_claim ON claim_evidence(claim_id, relation);
CREATE INDEX idx_claim_evidence_paper ON claim_evidence(paper_id);
```

```sql
CREATE TABLE claim_relations (
    relation_id     TEXT PRIMARY KEY,
    src_claim_id    TEXT NOT NULL,
    dst_claim_id    TEXT NOT NULL,
    relation        TEXT NOT NULL,   -- supports | refutes | assumes | extends | same_as | contradicts
    confidence      REAL NOT NULL DEFAULT 0.0,
    rationale       TEXT,
    provenance_json TEXT NOT NULL DEFAULT '{}',
    created_at      TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(src_claim_id, dst_claim_id, relation)
);
```

```sql
CREATE TABLE contradictions (
    contradiction_id TEXT PRIMARY KEY,
    claim_a_id       TEXT NOT NULL,
    claim_b_id       TEXT NOT NULL,
    contradiction_type TEXT NOT NULL,
    severity         TEXT NOT NULL DEFAULT 'medium',
    status           TEXT NOT NULL DEFAULT 'apparent',
    rationale        TEXT,
    evidence_json    TEXT NOT NULL DEFAULT '[]',
    resolved_by      TEXT,
    resolution       TEXT,
    created_at       TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at       TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

```sql
CREATE TABLE claim_reviews (
    review_id       TEXT PRIMARY KEY,
    claim_id        TEXT NOT NULL,
    reviewer        TEXT,
    decision        TEXT NOT NULL,   -- accept | revise | reject | needs_evidence
    notes           TEXT,
    created_at      TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

### 5.3 节点解析

新增只读解析器，不复制全文：

```python
def resolve_node(node_type: str, node_id: str) -> dict:
    ...
```

返回：

```text
node_type, node_id, paper_id, text, section_path,
char_start, char_end, page, bbox, parent_id
```

### 5.4 可选物化视图

只有当查询性能不足时，再建：

```sql
CREATE TABLE node_registry (...)
```

不要第一步就物化 86 万句子。

## 6. 文档树改造

### 6.1 必须补齐

1. 统一 `node_id`：
   - `sentence:<sentence_id>`
   - `figure:<fig_id>`
   - `table:<table_id>`
2. section 路径：
   - `path` / `depth` 已有，但需审计完整性；
   - 缺失时从 `section_level1/2/3` 回退。
3. char offsets：
   - 目前 83%；
   - 对缺失句子，用原文重新对齐；无法对齐的标记 `offset_missing`。
4. 图表引用关系：
   - 建立 `figure_ref` / `table_ref`：
     ```text
     sentence_id → fig_id/table_id
     ```
   - 解析 “Fig. 3”, “Table 2”, “图 3”, “表 2”。
5. 跨父节点：
   - 图/表可以被多个章节引用；
   - 不要强行只挂一个 parent，允许 `references` 多对多。
6. 解析质量：
   - 每个节点加 `parse_quality`：`ok | partial | broken`；
   - 出错节点不能进入 claim 图。

### 6.2 树不完整时的降级

如果某篇论文 section 缺失：

```text
paper → paragraph → sentence
```

仍然可用，但：

- 不允许做“章节级”论证结论；
- claim 标记 `structure_incomplete=true`。

## 7. Claim 抽取

### 7.1 目标

从句子/段落/图表中抽取：

```text
atomic claim
```

不是摘要，不是主题句，不是“本文研究了 X”。

### 7.2 claim 类型

至少：

```text
empirical      实证结果
causal         因果
mechanistic    机制
method         方法/工具
comparative    对比
policy         政策/应用
definitional   定义
```

### 7.3 抽取输入

优先：

```text
sentence + 父段落 + 所属章节标题 + 图表 caption
```

不要只给孤立句子。

### 7.4 抽取输出

严格 JSON：

```json
{
  "claim_text": "...",
  "claim_type": "empirical",
  "qualifiers": {
    "population": "...",
    "intervention": "...",
    "comparator": "...",
    "outcome": "...",
    "unit": "...",
    "scope": "...",
    "time": "..."
  },
  "evidence_node": {
    "node_type": "sentence",
    "node_id": "...",
    "quote": "..."
  },
  "confidence": 0.0
}
```

### 7.5 约束

- `quote` 必须与原文完全一致；
- 找不到精确 quote 的 claim 丢弃；
- 不确定的 claim 标 `needs_review`；
- 不做跨句合并，除非显式允许。

## 8. 正反证据检索

### 8.1 每个 claim 生成四类查询

```text
support_query   支持该 claim 的证据
refute_query    反对/削弱该 claim 的证据
boundary_query  边界条件/例外
mechanism_query 机制解释
```

### 8.2 检索范围

按 claim 类型选择：

| claim 类型 | 优先章节 | 证据类型 |
|---|---|---|
| empirical | Results / Tables | 数值、统计 |
| causal | Results / Discussion | 实验、自然实验 |
| mechanistic | Results / Discussion | 通路、分子 |
| comparative | Results | 对照 |
| policy | Discussion / Review | 政策分析 |

### 8.3 排序

沿用现有：

```text
BM25 + dense + RRF + bge reranker
```

但增加：

- 结构过滤（section type）；
- 图表证据单独一路；
- 反例查询不得被支持性结果淹没。

### 8.4 关系判定

候选证据进入分类器：

```text
supports / refutes / mentions / underdetermines
```

要求：

- 给出 rationale；
- 给出 quote；
- 低置信度进入人工队列。

---

## 9. 矛盾检测

### 9.1 输入

两个 claim，必须都有 qualifiers。

### 9.2 类型

```text
direct_negation
numeric_disagreement
scope_mismatch
population_mismatch
method_difference
causal_vs_correlation
temporal_mismatch
definitional_mismatch
```

### 9.3 流程

```text
1. 数值/单位规则检查
2. NLI / 科学矛盾分类器
3. LLM 结构化裁决
4. 人工复核（高严重度）
5. 写入 contradictions
```

### 9.4 输出

不是“谁对谁错”，而是：

```json
{
  "status": "apparent",
  "type": "population_mismatch",
  "reason": "两项研究的纳入人群不同",
  "severity": "medium",
  "needs_human": true
}
```

### 9.5 关键规则

- 不允许只凭向量相似度判矛盾；
- 数值比较必须做单位归一；
- 人群/剂量/终点不同，默认判“异质性”，不是“矛盾”；
- 只有直接否定或同一条件下数值冲突，才升为 `confirmed`。

## 10. 论证图

### 10.1 节点

```text
claim
```

### 10.2 边

```text
supports
refutes
assumes
extends
same_as
contradicts
```

### 10.3 图的用途

- 找论证缺口；
- 找未被反驳的 claim；
- 找只靠单篇论文支撑的 claim；
- 找“看起来支持、其实是异质性”的边；
- 为写作提供段落结构。

### 10.4 可视化

第一版只需：

```text
claim 列表 + 证据分组 + 矛盾标记
```

不要一开始做复杂力导向图。

## 11. 写作约束

### 11.1 从 claim 到段落

```text
section_plan:
  section_id
  claim_ids[]
  purpose
```

```text
paragraph_plan:
  paragraph_id
  claim_id
  evidence_ids[]
  rhetorical_role
```

### 11.2 句子级约束

生成每个句子时：

```text
必须绑定至少一个 evidence_id
```

没有证据：

- 不允许生成断言句；
- 只能生成过渡句/问题句，并显式标记。

### 11.3 写作流程

```text
大纲 → 段落 claim 分配 → 证据选择 → 句子生成 → 引用校验 → 红队审稿
```

不是：

```text
大纲 → 一次性扩写
```

## 13. 分阶段实施

### P0：数据审计（1 周）

- section 完整性；
- sentence offset 完整性；
- figure/table 引用；
- 解析质量抽样；
- 输出 `docs/审计-文档树.md`。

验收：

```text
可量化说明哪些论文可进入 claim 抽取
```

### P1：Claim Anchor（2 周）

- 新增 claims / claim_evidence；
- 单篇论文 claim 抽取；
- 精确 quote 校验；
- `/claims.html` 最小列表。

验收：

```text
100 篇论文，每篇 ≥3 条可回溯 claim
quote 一致率 100%
```

### P2：正反证据（2–3 周）

- 四类查询；
- 关系分类；
- 人工裁决队列。

验收：

```text
50 个 claim，支持/反对证据均有覆盖
```

### P3：矛盾检测（3 周）

- qualifier 抽取；
- 数值/单位规则；
- NLI + LLM 裁决；
- contradictions 表。

验收：

```text
人工标注 100 对，precision ≥ 0.7
```

### P4：论证图与写作（3 周）

- claim graph；
- section/paragraph plan；
- 句子级证据约束；
- 红队审稿。

验收：

```text
生成 1 篇可读综述草稿，所有断言句有证据
```

### P5：评估（持续）

- 内部 benchmark；
- 外部 benchmark；
- 人工评审。

### 14.2 外在指标


### 14.3 数据集

- SciFact；
- SciNLI；
- BioDivergence；
- ALCE；
- CiteBench；
- FActScore；

- claim 是否成立；

- 反例是否被处理；
- 结论是否越界。

## 15. 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 树不完整 | claim 无法定位 | P0 审计，标记 incomplete |
| claim 抽取幻觉 | 证据链污染 | 精确 quote + 人工复核 |
| qualifier 缺失 | 假矛盾 | 强制字段 + 低置信度拦截 |
| 矛盾误判 | 结论错误 | 规则 + NLI + 人工 |
| 成本过高 | 不可持续 | 先小样本，缓存，批量 |
| 私有数据上云 | 合规风险 | 本地模型路由 / 数据分类 |
| 过度工程 | 半年不出结果 | P1 先交付可用闭环 |

## 17. 算法选型（调研版）

> 原则：先用可解释、可验证、低成本的组件；不要为了“先进”上 GraphRAG 或多智能体辩论。

### 17.1 文档树与层级检索

| 方向 | 候选 | 用途 | 建议 |
|---|---|---|---|
| 结构解析 | GROBID / Docling / MinerU | section、引用、图表 | 保留 Docling，补 GROBID 对照 |
| 树摘要 | RAPTOR | 递归摘要树 | 试验 |
| 层级存储 | TreeRAG | 长文档层级检索 | 观察 |
| 上下文 chunk | Late Chunking | 长上下文 embedding | 试验 |
| 图检索 | GraphRAG / HippoRAG | 多跳、全局问题 | 暂缓 |

参考：

- RAPTOR：<https://ar5iv.labs.arxiv.org/html/2401.18059>
- TreeRAG：<https://aclanthology.org/2025.findings-acl.20.pdf>
- Late Chunking：<https://export.arxiv.org/abs/2409.04701v2>
- GraphRAG survey：<https://dl.acm.org/doi/10.1145/3777378>
- HippoRAG：<https://papers.nips.cc/paper_files/paper/2024/hash/6ddc001d07ca4f319af96a3024f6dbd1-Abstract-Conference.html>

### 17.2 Claim 抽取与证据推理

| 方向 | 候选 | 用途 | 建议 |
|---|---|---|---|
| Claim→Evidence 基准 | “Can AI Validate Science?” | 评估 claim 推理 | 参考 |
| 证据中心知识图 | Semantics for Science | claim/evidence 建模 | 参考 |

## 18. 推荐技术栈

### 必须采用

```text
文档树：现有 sections/paragraphs/sentences/figures/tables
检索：现有 hybrid + bge reranker
claim 抽取：LLM + JSON schema + 精确 quote
证据关系：NLI/LLM + 人工复核
矛盾：规则 + NLI + LLM
评估：SciFact/SciNLI/ALCE/FActScore
```

### 先试验

```text
RAPTOR 树摘要
Late Chunking
MiniCheck
ColBERT
```

### 暂缓

```text
GraphRAG
HippoRAG
全自动多智能体辩论
全库 claim 图
```

理由：

- 数据规模大；
- 成本高；
- 可解释性差；
- 当前瓶颈是 claim 锚定，不是图算法。

## 19. 验收标准

### P1

- 100 篇论文；
- 每篇 ≥3 条 claim；
- quote 一致率 100%；
- 每条 claim 可定位到 sentence/figure/table。

### P2

- 50 个 claim；
- 支持/反对证据均有覆盖；
- 人工裁决可追踪。

### P3

- 100 对人工标注；
- contradiction precision ≥ 0.7；
- 假矛盾可解释。

### P4

- 1 篇综述草稿；
- 所有断言句有证据；
- 红队审稿报告。

---

## 20. 决策点

在开始 P1 前，需要确认：

1. 先做英文论文，还是中英文都做？
2. 先做综述，还是原始研究？
3. claim 抽取用云端 DeepSeek，还是本地模型？
4. 是否允许把私有论文发给云端？
5. 人工裁决由谁负责？

---

## 21. 一句话

> 不是把“写论文”自动化，而是把“claim 的辩护过程”变成可审计的工作流。
