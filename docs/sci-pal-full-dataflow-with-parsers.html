1 PDF 解析层 — 6大解析引擎协同工作
📥 输入： 本地 PDF 文件 / PMC 下载的 XML（XML 直接走 import_xml_v2.py，不经过解析器）
🎼 解析器调度器 (parser_orchestrator.py)
V3 架构：Docling 主力 + GROBID 增强（可选）
• Docling 负责：段落 / 图表 / 表格 / 章节层级（正文结构主力）
• GROBID 负责：元数据（标题/作者/期刊/DOI/年份）+ 结构化参考文献（补充增强）
• GROBID 可选：服务没运行时静默回退到只用 Docling，不崩溃
• 标题合理性校验算法：全大写检测(>85%) / 联盟后缀检测 / 截断检测 / 过短过长检测 → 可疑时用替代标题
⬇️ 并行调度 ⬇️
🏆 Docling 主力
docling_parser.py
管线配置：OCR OFF / 表格结构 ON / 布局检测 ON / 标题层级 ON(优先PDF书签)
提取：TextItem / SectionHeaderItem / TableItem / FigureItem
算法：HierarchicalChunker 分层分块（按章节层级，保留section_l1/l2上下文）
📋 GROBID 可选增强
grobid_parser.py
服务：http://localhost:8070 (TEI XML)
提取：元数据(标题/作者/DOI/期刊/年份/卷期) + 结构化参考文献(作者/标题/期刊/年份/DOI)
算法：DOI正则提取(10.\d{4,9}/...) + 空格OCR修复 + 尾部清理
🔄 MinerU 备选
mineru_parser.py
学术PDF最佳整体解析器
懒加载：启动不加载，首次调用才 import magic_pdf
提取：paragraphs / figures / metadata（标准化输出）
技术：版面分析 + 公式识别(LaTeX) + 表格识别 + 阅读顺序推断 + 中英文混合优化
📊 pdfplumber 专用
pdfplumber_parser.py
复杂表格专用提取器
逐页 page.extract_tables()，只处理表格，不处理正文
算法：空表过滤(<2行跳过) + 自动编号(paper_id_tab001) + 页码记录
⚡ Journal Optimizer
journal_optimizer.py
顶刊专项优化（后处理）
DOI前缀识别期刊家族，覆盖50+子刊
优化：期刊特定标题识别 + 卷期页码提取 + 章节类型归一化 + 双栏布局提示
📐 BaseParser
base_parser.py
抽象基类(ABC)
定义统一接口：parse(pdf_path, paper_id) → Dict / get_parser_name() → str
作用：确保所有解析器输出格式一致，调度器可直接合并

📦 标准化输出（统一Dict格式）
📄 metadata
paper_id / title / authors / journal / year / doi / pmid / pmcid / volume / issue / pages / abstract
📝 paragraphs
para_id / paper_id / text / section_l1 / section_l2 / section_level / paragraph_index / page_number
🖼️ figures
figure_id / paper_id / caption / image_path / page_number / section_l1 / section_l2
📊 tables
table_id / paper_id / caption / table_data(二维数组) / page_number / section_l1 / section_l2
📚 citations
citation_id / paper_id / ref_index / authors / title / journal / year / volume / pages / doi / raw_text

2 数据导入与建库层 — 写入 SQLite + 构建各种索引
import_xml_v2.py
【主力】JATS XML 解析导入器。解析 PMC 下载的 XML，提取段落/章节/图表/参考文献，写入 research.db。支持增量导入(INSERT OR REPLACE)。
JATS解析增量导入
build_abstracts_db.py
摘要库构建器。读取 abstracts_xml/*.json，写入独立的 abstracts.db（FTS5 + 向量索引）。embedding 模型 bge-base-en-v1.5。
摘要库FTS5
build_db/build_database.py
数据库初始化。创建所有表：papers/paragraphs/figures/tables/citations/sentences/chunks/paper_graph/communities 等。
建表Schema
build_db/build_fts.py
FTS5 全文索引构建。为 paragraphs 表建 FTS5 虚拟表，支持布尔搜索/短语搜索/前缀搜索/NEAR操作。BM25 排序。
FTS5BM25
build_db/build_paper_graph.py
论文引用图谱构建。解析参考文献，建立 CITES(引用) 和 SIMILAR(相似) 关系边。用于图谱扩展检索。
引用图谱CITES
build_db/build_communities.py
论文社区发现。基于引用图谱用 Louvain 算法做社区检测，将论文聚类成主题社区。
Louvain社区检测
build_db/build_chunks.py
文本分块器。将长段落切分成固定大小 chunk（含重叠），用于更精细的向量检索。
分块重叠
build_db/build_sentences.py
句子级切分。将段落切分成句子，写入 sentences 表。用于句子级证据定位和引用校验。
句子切分
build_db/build_citation_index.py
引用索引构建。解析文内引用标记([1]/(Smith,2020))，建立句子-参考文献对应关系。用于引用溯源。
引用索引
build_db/dedup_papers.py
论文去重工具。基于 DOI/PMID/标题相似度去重，避免重复论文入库。
去重

3 向量索引层 — Embedding + ChromaDB + Rerank 模型
build_paragraph_vector_index.py
【主力】段落级向量索引构建。读取 paragraphs 表，用 bge-base-en-v1.5 做 embedding(768维)，写入 ChromaDB(collection: sci_pal_paragraphs)。支持增量追加(collection.add)。
段落向量bge-base增量
build_abstracts_db.py
摘要向量索引构建。为 abstracts.db 建独立的 ChromaDB 向量库(data/chroma_abstracts/)。
摘要向量独立库
services/search/reranker.py
Cross-Encoder 重排序器。用 bge-reranker-base 对候选(query, paragraph)对打分，0-1相关性分数。粗排前50-100条精排到前10-20条。
RerankCross-Encoder
Embedding: BAAI/bge-base-en-v1.5 (768维) Rerank: BAAI/bge-reranker-base (Cross-Encoder) 向量库: ChromaDB (HNSW索引, 余弦相似度) 批量编码 batch_size=256 增量追加 collection.add (不重建)
🔢 全文向量库 chroma/
data/chroma/ (ChromaDB)
collection: sci_pal_paragraphs，HNSW索引，768维向量
🔢 摘要向量库 chroma_abstracts/
data/chroma_abstracts/ (ChromaDB)
独立摘要向量库

4 检索引擎层 — 混合检索 + Rerank + 扩展 + 在线搜索
🔍 统一检索流水线 (unified_retriever.py)
1.查询路由→ 2.混合搜索→ 3.Rerank精排→ 4.MMR去重→ 5.上下文扩展→ 6.图谱扩展→ 7.摘要库补充
输出：结构化 evidence envelope（段落+图表+表格+论文+图谱关联）
unified_retriever.py
【核心】统一检索器。串联完整检索流水线，输出结构化 evidence envelope。
统一检索流水线
hybrid_search.py
混合搜索核心。向量检索(ChromaDB) + FTS5全文检索，RRF融合(k=60)。支持Multi-Query扩展、动态权重、MMR多样性。
向量+FTSRRF融合
query_router.py
查询路由器。scispacy NER提取关键实体(基因/蛋白/疾病)，做实体增强检索。按查询类型选择策略。
NER实体增强
context_expander.py
上下文扩展器。Small-to-Big策略：命中段落(chunk)→扩展到父章节(section)，用►◄标记命中位置。
Small-to-Big
graph_traverser.py
图谱遍历器。沿CITES/SIMILAR边扩展查找相关论文，补充向量检索遗漏的关联文献。最多2跳。
图谱扩展
mmr_diversifier.py
MMR多样性选择器。Maximal Marginal Relevance，在相关性和多样性间平衡，避免内容重复。
MMR
abstract_search.py
摘要库检索器。独立检索 abstracts.db(FTS5+向量)，作为全文检索的补充。
摘要检索
online_search.py (V33.1)
NCBI在线搜索。ESearch搜ID→ESummary批量取元数据。同时搜PubMed+PMC。限速(有Key10次/秒)+缓存(24h)+3次重试。
在线搜索NCBI
hybrid_retriever.py (V33.1)
本地+在线并行搜索。ThreadPoolExecutor并行。三级去重(PMCID→PMID→DOI)，本地优先。统一排序。
本地+在线三级去重
online_downloader.py (V33.2)
在线下载器。异步下载PMC XML→增量导入DB→增量建索引。三阶段进度(下载40%+导入30%+索引30%)。任务队列(同时只跑1个)。
异步下载增量队列
boilerplate_filter.py + reference_filter.py
结果清洗。去除页眉页脚/作者信息/版权声明等样板文本；过滤参考文献条目。
过滤清洗
向量检索: 余弦相似度 (HNSW) 全文检索: FTS5 (BM25) 结果融合: RRF (k=60) 重排序: Cross-Encoder (bge-reranker) 多样性: MMR 上下文: Small-to-Big 图谱: CITES/SIMILAR 2跳扩展 去重: 三级 (PMCID/PMID/DOI)
⬇️
证据卡片 → 综述生成 / QA问答
5 生成与应用层 — 综述生成 + QA问答 + 引用校验
review_generator.py
【核心】综述生成主流程。V32.5五大升级：①分章节生成+渐进式上下文注入 ②章节类型感知(intro/methods/results/discussion/conclusion) ③证据-声明矩阵 ④迭代精炼+5维评分(相关性30%+证据30%+逻辑20%+写作10%+无臆测10%，低于60分重试) ⑤引用铁律(每句必须有[evidence_id])。
综述生成分章节迭代精炼
evidence_extractor.py
证据抽取器。LLM从段落抽取结构化证据卡片(EvidenceCard)，含类型/章节/关键发现/方法/样本量/结论。简化模式直接用段落做证据卡片。
证据抽取EvidenceCard
outline_generator.py
大纲生成器。3种模板(系统综述/叙事型/方法学型)，每章节有关键词用于按大纲搜索文献。V32.4自动注入主题核心关键词。
大纲模板关键词注入
citation_verifier.py
引用校验器。两层校验：①确定性校验(引用标记存在性/有效性) ②可选LLM深度校验(引用恰当性/断章取义检测)。
确定性校验LLM深度校验
llm_client.py
LLM客户端。支持Ollama(qwen2.5:3b轻量/7b重量)和云端OpenAI兼容API。自动重试、流式输出。
OllamaQwen2.5
qa_service.py
RAG问答服务。基于统一检索器获取证据，LLM生成带引用回答。支持多轮对话、证据溯源、关系抽取、冲突检测。
RAG问答多轮对话
relation_extractor.py + conflict_detector.py
关系抽取+冲突检测（问答/分析功能用）。V31.82综述生成已完全跳过这两步。
问答用
models.py + review_store.py + task_manager.py
数据模型(EvidenceCard/ReviewDraft/ReviewOutput等) + 综述结果暂存(TTL 3600s) + 任务管理器。
数据模型暂存
分章节生成 + 渐进式上下文注入(前章200字) 章节类型感知 (6种写作风格) 证据-声明矩阵 (先列要点再写) 5维评分迭代精炼 (低于60分重试) 引用铁律 (每句必须有[evidence_id])
