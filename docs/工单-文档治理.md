## 一、原则（先讲清楚，免得改错方向）

1. **删除文件 = 用户点头。** 本工单只要求你**产出清单与判定依据**，不要求你执行删除。
2. **判定「哪份是活的」的判据**：查**谁引用它**，不是看谁更像。
   - 根目录的 `README.md` / `ARCHITECTURE.md` 是给人和 AI 入口看的（`CODEBUDDY.md` 的阅读清单指向哪些？先查）。
   - 被引用多的那份是活的。
3. **同字节的对（A 组）**：删哪份都无损，但建议**保留根目录那份**（与 `AGENTS.md`/`CODEBUDDY.md` 同层，
   符合 AI 入口习惯），删 `docs/` 那份。
4. **B 组必须逐对比对内容差异再下结论**，不许「看着像」就删。
5. **不做内容重写**，只做「去重 + 改名 + 标注」。合并内容属于另一件事。

## 二、任务

### D-1 · A 组去重（低风险，可先做）

对 4 组同字节文件：先 `cmp` 再确认一次（我查过了，但二次确认成本极低），
然后在**交付报告里列出建议删除清单**，**不执行删除**，等用户点头。

### D-2 · B 组判定（本工单重点）

对 3 组内容不同的文件，逐组回答三个问题并给出依据：
1. 哪份被引用更多？（列出引用它的文件与行号）
2. 差异是什么？（给出 diff 摘要，不要贴全文）
3. 结论：保留哪份、另那份是「删」还是「标注为历史快照」？

特别提示：
- `README.md` 根 16KB vs docs 2KB —— 差的 14KB 大概率是真实内容，**别因为 docs 那份短就判它冗余**。
- `docs/架构.md` 14KB vs `docs/架构总览.md` 5KB —— 名字相近但内容量差 3 倍，
  可能是「详版 vs 摘要」而非重复，**也可能是不同时期的快照**，用修改时间和引用关系判断。

### D-3 · 怪名文件改名

`docs/P2 优先级分类+6幅架构图索引+明天工作计划）.md` → 建议改成一个正常文件名
（例如 `docs/P2-优先级分类与架构图索引.md`）。
**用 `git mv` 保留历史**；改名后如果有别处引用它，同步更新引用。
同样：**先给建议名，等用户点头再执行**。
