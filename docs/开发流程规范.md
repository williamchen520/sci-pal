# 开发流程规范：架构即代码

> 日期：2026-11-03  
> 真理源：`ARCHITECTURE.json`  
> 工具：`scripts/validate_arch.py`、`scripts/scaffold_from_arch.py`

## 1. 铁律

```text
1. 新增 / 修改 / 删除路由，第一步改 ARCHITECTURE.json
2. 没改 JSON 之前，禁止动 Python 路由和 handler
3. 改完 JSON 立刻运行 validate_arch.py
4. 校验通过后，才写路由和业务逻辑
5. 写完后再次运行 validate_arch.py
```

违反这条规则，视为架构漂移，不进入评审。

## 2. 为什么需要 planned 状态

新路由在 JSON 里存在、但 Python 还没写时，校验器不能把它当成“缺失路由”。

因此新节点必须：

```json
{
  "rule": "/api/foo/<int:item_id>",
  "endpoint": "foo.get_item",
  "methods": ["GET"],
  "status": "planned",
  "codegen": {
    "id": "foo_get_item",
    "blueprint": "foo",
    "function": "get_item",
    "mcp_server": "search_server",
    "mcp_tool": "get_foo_item",
    "description": "Return one foo item.",
    "parameters": [
      {"name": "item_id", "in": "path", "type": "int"},
      {"name": "verbose", "in": "query", "type": "bool", "default": false}
    ]
  }
}
```

状态流转：

```text
planned
  -> scaffold
  -> 实现并注册
  -> implemented（删除 status 或写 implemented）
  -> validate 通过
```

`validate_arch.py` 对 `planned` 只给 warning，不报错；对 implemented 路由做严格检查。

## 3. 标准操作

### 3.1 新增路由

```text
1. 编辑 ARCHITECTURE.json
   - rule / endpoint / methods
   - status=planned
   - codegen 块

2. 运行
   python scripts/validate_arch.py

3. 生成骨架
   python scripts/scaffold_from_arch.py --node foo_get_item

4. 把 generated/foo_get_item/route.py 合入 routes/
   把 mcp_tool.py 合入 mcp_server/
   实现 handler 与 tool

5. 在 api_server.py 注册 blueprint

6. 把 JSON 的 status 改为 implemented
   （或删除 status 字段）

7. 再次运行
   python scripts/validate_arch.py

8. 跑对应测试
```

### 3.2 修改路由

```text
1. 改 JSON 的 rule / methods / endpoint
2. validate（此时旧代码会报 wild route 或 missing route）
3. 改 Python
4. validate 通过
```

### 3.3 删除路由

```text
1. 从 JSON 删除节点
2. validate 会报 wild route
3. 删除 Python 路由与 blueprint 注册
4. validate 通过
```

## 4. 校验器规则

`scripts/validate_arch.py` 检查：

```text
JSON route + method 集合 == Flask url_map 集合
JSON endpoint 函数存在
路径变量 <id> 必须在 handler 签名中
JSON parameters 声明的参数必须在 handler 签名中
重复 route+method 报错
status=planned 允许暂不实现
```

当前基线：

```text
json_routes   202
app_routes    202
OK
```

这里的 202 是 **route + method** 对，不是 URL 数量。

## 5. 生成器规则

`scripts/scaffold_from_arch.py`：

```text
只接受 status=planned
只接受带 codegen.id 的节点
输出到 generated/<id>/
不修改 api_server.py
不修改已有 routes/*.py
不修改 mcp_server/*.py
```

输出：

```text
generated/<id>/route.py
generated/<id>/mcp_tool.py
generated/<id>/README.md
```

生成器不会自动注册 blueprint，也不会自动插入 MCP 工具；这是故意的，避免脚本改坏生产入口。

## 6. MCP 约束

```text
MCP 是薄转发层
不 import services/*
不 import api_server
只通过 _forward._call 调 Flask 路由
```

生成器按这个约束生成：

```python
@mcp.tool(description="...")
def get_foo_item(item_id: int, verbose: bool = False) -> str:
    return _call("GET", f"/api/foo/{item_id}", {"verbose": verbose})
```

## 7. 例外

允许先写 Python 的情况只有：

```text
纯内部函数，不新增路由
没有 HTTP 入口
不改变 JSON 的 API 面
```

即使如此，也不能新增“野路由”。

## 9. 失败处理

```text
validate 失败：
  先修 JSON 或 Python
  不允许用 --skip 绕过
  不允许临时注释校验

scaffold 失败：
  检查 codegen.id 是否唯一
  检查 status 是否为 planned
  检查 rule / methods

合并前：
  python scripts/validate_arch.py
  python -m unittest discover -s tests -p "test_*.py"
```
