# SciPal 协作规范

> 本文是 [`.dsh_rules`](../.dsh_rules) 的详细说明版。
> **最高优先级以根目录 `.dsh_rules` 为准。**
> 任何 AI / Agent 在唤醒、读取项目、修改代码、写数据库、创建 PR 之前，必须先加载 `.dsh_rules`。

---

## 0. 为什么需要这 5 条规则

SciPal 已经进入“研究 + 工程混合”的阶段：

- 工程侧：检索、解析、部署、测试；
- 研究侧：claim、证据关系、语料取舍、写作口径。

两者混在一起时，最容易出现：

1. PR 范围漂移；
2. AI 替人类做研究裁决；
3. 负结果被包装成进展；
4. 合并绕过人类确认；
5. 只报“完成”，不报证据。

这 5 条规则就是针对这 5 个问题。

---

## 规则 1：一个 PR 一个主题

### 要求

- 一个 PR 只解决一个单一主题；
- 不把架构文档、功能、数据修正、格式化混进同一个 PR；
- PR 创建后不再扩大范围；
- 新主题 → 新分支 / 新 PR；
- PR 标题必须能一句话说明单一主题。

### 反例

```text
feat: claim 写作口径 + 架构文档 + 在线入库
```

### 正例

```text
feat: claim 写作口径
docs: 架构与 README 升级
fix: 在线 ingest 解析
```

### 检查问题

> 这个 PR 解决了什么单一主题？

---

## 规则 2：合并必须由人类明确说

### 要求

- AI 可以创建 PR、跑测试、给建议、准备合并；
- **只有人类明确说“合并”后，AI 才能合并 PR**；
- 不自动合并；
- 不因为 CI 通过就合并；
- PR 必须明确标注“是否已准备好让人类合并”。

### 允许

```text
AI：PR 已创建，测试通过，等待你确认合并。
```

### 禁止

```text
AI：CI 通过了，我直接合并了。
```

### 检查问题

> 是否已准备好让人类合并？

---

## 规则 3：研究裁决与工程实现分开

### 工程侧（AI 可推进）

- 代码；
- 测试；
- 文档；
- 部署；
- 检索/解析/性能修复。

### 研究侧（必须人类确认）

- claim 状态；
- 证据关系（supports / refutes / underdetermines / mentions）；
- 是否接受 / 拒绝 / 保留争议；
- writing brief；
- 语料取舍与反例标注。

### 写库前必须说明

```text
将写入：claim_hcc_triple_os
关系：refutes
证据：paper_..._sent_001
理由：...
影响：accepted → contested
```

### 禁止

```text
检索到一条反例，所以我把 claim 改成 rejected。
```

### 检查问题

> 本次修改的 Claim 状态和证据链是什么？

---

## 规则 4：负结果止损

### 要求

- 同一方向连续两次负结果，必须停下来讨论；
- 不得继续调参掩盖问题；
- 必须明确写“未发现 / 未提升 / 失败”；
- 负结果也要记录，不删除。

### 示例

```text
语义检索连续两次未产生 refutes
→ 停止调参
→ 先问：语料里到底有没有反例？
```

### 检查问题

> 本轮是否出现负结果？下一次是否应该止损？

---

## 规则 5：每轮结束必须回答三件事

```text
1. 做了什么？
2. 证据是什么？
3. 需要人类决定什么？
```

不能只写“完成了”。

### 证据示例

- 测试：`671 tests OK`
- API：`status=contested`
- 文件：`docs/claim-pilot-在线入库-01.md`
- 引用：`paper_PMC..._sent_001`

### 检查问题

> 本轮做完了什么？下一轮干什么？

---

## 违规处理

发现违反任一规则：

1. 立即停止；
2. 输出：

   ```text
   RULE_VIOLATION: 规则 N — <具体违反内容>
   ```

3. 说明影响；
4. 给出回滚/修复方案；
5. 等待人类指示。

不允许“下次注意”代替报错。

---

## 启动自检

```text
[ ] 已读 .dsh_rules
[ ] 本轮只做一个主题
[ ] 是否涉及 claim/证据/研究裁决？如是，先问人类
[ ] 是否要合并？只有人类明确说“合并”才做
[ ] 结束时回答：做了什么 / 证据 / 需要决定什么
```
