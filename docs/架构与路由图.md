# SciPal 架构与路由图

> 版本：2026-11-08 · PG-only  
> 技术栈：Python 3.12 · Flask 3 · PostgreSQL 16 + pgvector · 原生 HTML/JS  
> 部署：Docker Compose（app + watch-cron + Caddy + PostgreSQL）

> 配套文档：[开发-模块手册](开发-模块手册.md) · [PG-only 总报告](PG-only迁移总报告-2026-11-08.md) · [机器架构](../ARCHITECTURE.json)

---

## 1. 设计原则

```text
确定性检索
  -> 结构化证据
    -> claim 审讯
      -> 受约束写作
```

四条底线：

1. **检索可追溯**：段落、句子、图、表都能回到 `paper_id / section / page / bbox`。
2. **claim 有证据**：claim 必须绑定精确 quote。
3. **裁决可审计**：状态变化写入事件表，不覆盖历史。
4. **单轨存储**：生产只读写 PostgreSQL；SQLite / Chroma 仅作归档，不在运行路径。

## 5. 检索流程

```mermaid
sequenceDiagram
  participant U as DSH/浏览器
  participant API as Flask
  participant HS as HybridSearch
  participant PG as PostgreSQL
  participant RR as Reranker
  participant CE as ContextExpander

  U->>API: query
  API->>HS: search()
  HS->>PG: pgvector paragraph recall
  HS->>PG: FTS/BM25 recall
  HS->>HS: RRF fusion
  HS->>RR: cross-encoder rerank
  RR->>CE: top paragraphs
  CE->>PG: sections / neighboring paragraphs
  PG-->>API: evidence envelope
  API-->>U: paper + section + sentence + page/bbox
```

关键行为：

```text
SCIPAL_VECTOR_BACKEND=pgvector
SCIPAL_FTS_BACKEND=postgres
SCIPAL_SEARCH_META_BACKEND=postgres
```

重复论文过滤：

```text
papers.duplicate_of IS NULL
```

覆盖检索、summary、evidence 三层。

## 9. 启动与故障

```text
启动
  -> 加载 env
  -> 注册 26 个蓝图
  -> SCIPAL_SQLITE_QUERY_ONLY=1 时跳过 SQLite schema/migration
  -> 首次请求加载 embedding/reranker
  -> /api/health
```

原则：

```text
PG 不可用 -> 主检索失败，不回退 SQLite
research.db 不存在 -> 正常启动
Chroma 不存在 -> 正常启动
```
