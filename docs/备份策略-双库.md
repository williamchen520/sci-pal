# 双库备份策略

> 日期：2026-11-11  
> 目标：core 高频、corpus 低频；备份逻辑与数据层隔离一致

---

## 1. 策略

```text
scipal_core
  内容：users / auth / projects / experiments / notes / tasks
  频率：每 6 小时
  保留：7 天
  方式：pg_dump custom format + pg_restore --list 校验

scipal_rebuild
  内容：papers / paragraphs / sentences / embeddings
  频率：每 7 天
  保留：28 天
  方式：同上
  理由：可由原始 XML 重建，低频足够
```

## 2. 运行

```text
pg-backup 容器
  image: postgres:16
  deploy/pg_backup.sh
  /app/backups/pg
```

使用 PG16 客户端，避免 `pg_dump 17` 对 PG16 恢复时的
`transaction_timeout` 警告。

每轮只检查到期项：

```text
core   距离上次 >= 6h
corpus 距离上次 >= 7d
```

## 3. 校验

每个 dump：

```text
pg_dump --format=custom
pg_restore --list
```

失败写入：

```text
/app/backups/pg/pg_backup_status.json
```

不会因为备份失败覆盖好文件。

## 4. 恢复演练

```text
createdb scipal_core_restore
pg_restore -d scipal_core_restore core-....dump
count(*) 对账
dropdb scipal_core_restore
```

corpus 同理，但恢复后必须重建 HNSW。

## 5. 恢复演练结果（2026-11-11）

```text
core-20261111-030432.dump
pg_restore --exit-on-error -> 0
auth.users 2
lib_ws_default.projects 1
lib_ws_default.tasks 477
```

无 `transaction_timeout` 警告。

## 6. 旧备份容器

```text
backup-cron   已移除
pg-backup    唯一备份路径
```

旧 SQLite 快照不再产生。

## 7. 边界

```text
core 备份含密码哈希，必须限权
backups/pg 不进 git
保留策略不等于归档
跨库一致性不要求同一时间点；auth 与 corpus 无强事务
```
