# 架构耦合检测规则

> 日期：2026-11-10  
> 来源：`docs/架构.md` “绝对不能跨模块调用”  
> 机器契约：`ARCH_CONTRACT.json`

---

## 1. 五条规则

| ID | 禁止 | 范围 | 机器检查 |
|---|---|---|---|
| `review-no-storage` | 综述层直接 import SQLite / Chroma | `services/review/**` | `forbid_import` 新增文件 |
| `qa-no-evidence-extractor` | 问答层直接 import `EvidenceExtractor` | `services/qa/**` | `forbid_import` 全量 |
| `downloader-no-llm` | 下载层直接 import `LLMClient` | `services/search/online_downloader.py` | `forbid_import` 全量 |
| `search-no-review-generator` | 检索层直接 import `ReviewGenerator` | `services/search/**` | `forbid_import` 全量 |
| `no-direct-data-db` | 任何模块直接写 `data/*.db` | `services/**` | `forbid_pattern` 新增文件 |

## 2. 为什么要分“新增/全量”

```text
review/ 仍有多处历史 sqlite3 import
data/*.db 仍有历史路径
```

一上来全量强制会：

```text
所有 PR 全红
规则被绕过
```

所以：

```text
历史债：文档登记，逐步清
新代码：从第一天拦截
```

已有违规未清完时，不能把规则标成“全量通过”。

## 5. 与前三条迁移规则的关系

```text
前三条：运行时单栈 / allowlist 只减 / 测试 provider
这五条：模块依赖方向
```

两者互补：

```text
迁移规则防“又回到 SQLite”
耦合规则防“层与层互相穿透”
```
